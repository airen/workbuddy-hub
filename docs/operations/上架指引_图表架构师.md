## 2. 上传

后台路径：**发布管理 → 专家 → 右上角「创建」**

1. 把 `diagram-architect.zip` 拖进上传区 → 平台自动解压、识别、生成专家 ID
2. 点「继续」进入确认信息页。部分字段从包里读出来，**页面上改不了**；要改就回 `plugin.json` 改了重新打包
3. 补齐页面上要填的三项：
   - **市场展示分类**：⚠️ **务必勾选含「AI创作」的分类**（可多选，建议 **AI创作 + 内容创作**，或 AI创作 + 技术工程）
   - **服务类目**：至少 1 个、最多 5 个，建议「工具-办公」
   - **头像**：可沿用包内 `avatars/diagram-architect.jpg`，也可重传
4. 核对右侧预览（名称 / 简介 / 头像）→ 继续 → 确认汇总 → **提交**

## 3. 已知风险点

| 风险 | 说明 | 处置 |
|---|---|---|
| **类目驳回**（「至少应包含高度生成或AI创作类目」） | 本包输出的是**图形产物**，属高度生成 | 上传页的**市场展示分类**必须勾含 AI 创作的分类（可多选）。若仍被驳回 → 把 `plugin.json` 的 `categoryId` 从 `02-Engineering` 改为 `04-DataAI`，版本升 `1.0.1`，重新打包再提交 |
| **名称「已被占用」** | `name` 是**全平台全局唯一**，不是账号内唯一 | 换更具体的前缀名，并把 `plugin.json` 的 `name`、`plugin`、`agentName`、agent 文件名、目录名**一起改**，重新打包 |
| **传错入口** | 技能包走「技能」、专家包走「专家」 | 专家包第一层是 `agents/`/`skills/`/`.codebuddy-plugin/`，**没有 SKILL.md**；传到技能页会报「未找到 SKILL.md」 |

## 6. 后续版本维护

改本地文件 → 重新 `validate` → `register` → `package` → 上传。命令：

```bash

EXP="$WORKBUDDY_CONFIG_DIR/plugins/marketplaces/my-experts/plugins/diagram-architect"

python3 "$EM/scripts/register_expert.py" "$EXP"
python3 "$EM/scripts/package_expert.py" "$EXP" /Users/damo/workshop/WorkBuddy/dist

# 上架前自审（对解包后的 zip 跑）

```
