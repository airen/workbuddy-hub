# 老刀（lao-dao-editor）去 AI 味能力评估与升级方案

- 评估对象：`experts/lao-dao-editor`（资深编辑 · 去AI味改写，v1.0.1，内置 skill `de-ai-rewrite`）
- 判据来源：`agent-skills-hub` 的 anti-slop 实测（23 个去 AI 味 skill）
  - 评分脚本 `ops/slop-runs/score_slop.py`（三层判据 + 6 条结构特征）
  - 结果表 `ops/slop-runs/RESULTS.md`
  - 结论页 `agentskillshub.top/best/anti-slop/`
- 判据模型：StoryScope 叙事特征（COLM 2026），被上述实测用作「结构层」的裁判标准

---

## 一、裁决

**是。老刀 v1.0.1 正是「只做表层、不动结构」的典型。**

它把「去 AI 味」几乎全部实现为**词表清理 + 标点清理**。10 条删除规则里 9 条是表层（词/标点/语法），唯一沾到结构的「模糊归因」也被降格成措辞问题；而真正的结构层六条特征，**它一条都没有作为目标写出来，也就一条都不会被系统性地改掉**。

按实测脚本的三层口径，老刀 v1.0.1 的**可达最深层次是 `phrasing`（措辞层）**，`structure`（结构层）只能靠模型偶然触及。它的预期得分与实测榜上的 `blader/humanizer`（5.4 万星）、`op7418/Humanizer-zh`（1.9 万星）同类：**约 3.0 / 5**——破折号能删光、措辞能改，但「讲明道理」「整齐收尾」原封不动。

这不是老刀独有的缺陷，是这一类 skill 的系统性缺陷。实测数据：40 份改写里 **「讲明的道理」26/26 保留、「整齐的结尾」28/28 保留**；21 个改写类工具里 **19 个只改用词、不动结构**。

## 二、判据：AI 味的三层

实测脚本把 AI 味拆成三层，逐层判定改写实际够到了哪一层（`layer: none|surface|phrasing|structure`）：

| 层 | 内容 | 判定方式 |
|---|---|---|
| **surface 表层** | 用词与标点：英文 AI 词（delve / tapestry / leverage…）、中文模板词（值得注意的是 / 总而言之 / 赋能 / 助力…）、破折号 `—` | 机械计数（正则） |
| **phrasing 措辞层** | 陈词滥调、紫色散文、对冲、冗余、节奏单调 | 裁判模型 |
| **structure 结构层** | 下面 6 条叙事特征 | 裁判模型，逐条 true/false |

结构层六条（原文，`score_slop.py` 的 `STRUCTURE` 提示词）：

1. **`stated_theme` 讲明道理** —— 文本把自己的寓意、主题或结论直接说出来，而不是留给读者。
2. **`tidy_ending` 整齐收尾** —— 结尾被整齐解决（和解、接受、一句总结），而不是保持开放。
3. **`vague_references` 泛指** —— 泛泛指向「某些东西」，而不点出具体的作品、地点、人物或例子。
4. **`body_emotion` 身体化情绪**（虚构类）—— 情绪主要靠身体感受与氛围来传达。
5. **`no_reader_address` 不对话读者** —— 全程从不直接对读者说话。
6. **`single_track` 单线推进** —— 一条整齐的论证线或情节线，没有岔路、没有没收的线头。

## 四、为什么它必然停在表层（机制分析）

不只是「没写」，而是现有结构在**机制上**把模型推向表层：

1. **顺序错了。** 工作流是「先删词 → 再注入人声」。模型做完第一步（10 条词表规则，工作量显性、易验证）后，已经产生「改完了」的错觉；第二步「注入真实人声」只有 5 条抽象口号（改变节奏、表达观点、保留不整齐），没有任何可判定的完成标准，实际执行中极易被跳过或降格为「换几个词」。

2. **目标没命名。** 模型不会主动去改一个没被点名的东西。「结尾不要收得太整齐」这句话在 v1.0.1 里根本不存在，所以模型没有理由去动结尾。

3. **没有强制产出物。** 「必做流程（3 遍）」的第 2 遍要求「诚实复读并指出仍然机械痕迹的残留处」，但**这一步的产出没有出口**——`输出规范` 规定「只交付最终版本，不加引言、评论或修改摘要」。要求模型自查却禁止它写出自查结果，等于把自查变成一次静默的内心活动，可靠性极低。

4. **输出规范反向隐藏了结构改动。** 因为只交正文，用户无法判断「讲道理的那句到底删没删」。这也让**回归测试不可能**——你拿不到可对比的证据。实测里工具越改越像 AI（`DadaNanjesha` 在句首加连接词、`sepia` 把散文改成编号清单加硬总结）这类失败，在这种「只看成品」的交付方式下很难被发现。

5. **「保留原文的语义与信息量」被过度保守地解读。** 模型容易把它读成「不要删句子」，于是连「总结升华句」这种**没有信息量的评论句**也不敢删——而这正是 `stated_theme` 的手术对象。需要显式区分：**删的是评论/升华/总结句，不是事实句**。

6. **过度承诺。** 人设写「让任何读者或检测工具都无法判断出它是 AI 写的」。这个承诺没有对应的执行手段，属于无支撑的宣称；同时会诱导模型把注意力放在「骗过检测器」的表层特征上，而不是真正改变文本结构。

## 五、升级方案（v1.1.0）

针对上述机制，逐条对症：

| 病根 | 处方 |
|---|---|
| 顺序错 | **结构优先**：结构扫描 → 结构手术 → 措辞 → 表层 → 结构自查。先动骨架，后动皮肉 |
| 目标没命名 | 把六条结构特征**逐条写进 skill**，每条配可执行的「手术动作」 |
| 无强制产出 | 交付时附 **结构改动回执**（≤6 行），把内部自查变成可见产出 |
| 输出规范隐藏改动 | 回执默认开启（用户可说「只要正文」关闭），使改动可核对 |
| 保真规则误伤结构手术 | 显式区分「事实/数字/专名/主张」与「评论/升华/总结句」 |
| 过度承诺 | 改为可验证的表述：给出三层判据 + 自检脚本，而不是「检测工具测不出」 |
| 无回归手段 | 新增零依赖脚本 `scripts/ai_tell_check.py`，机械统计表层 + 结构启发式，支持 before/after 对比 |

### 结构层六条的手术动作

| 特征 | 手术动作 |
|---|---|
| `stated_theme` 讲明道理 | 找到结尾/段末那句「这告诉我们…」「由此可见…」「真正重要的是…」，**整句删掉**，让细节自己说话 |
| `tidy_ending` 整齐收尾 | 删掉收束句（「一切都有了回报」「终于圆满」），**停在最后一个具体动作或一个未解决的细节上** |
| `vague_references` 泛指 | 优先从原文里找可点名的具体对象（人名/机构/时间/数字）；**原文没有的绝不编造**，改为整句删除 |
| `body_emotion` 身体化情绪 | 把「胸口一紧 / 胃里发沉 / 空气凝固」这类身体形容词，换成**具体动作、对话、可触摸的物件** |
| `no_reader_address` 不对话读者 | 在合适的文体里，允许**直接对读者说一次话**（「你要是也遇到过…」）；说明文体可保持 |
| `single_track` 单线推进 | **补一条岔路或一个没收的线头**——从原文已有素材里选一个次要细节展开，或让某条线悬着不解决 |

### 反退化规则（防止越改越像 AI）

实测里的反面案例（`DadaNanjesha`、`sepia`）说明：改写本身会**新增**结构味。因此必须禁止：

- ✗ 在句首加连接词（然而 / 于是 / 与此同时 / Nonetheless）
- ✗ 把连续散文改成编号清单或分点
- ✗ 新增任何总结句、升华句、「希望对你有所帮助」
- ✗ 把段落改得长短整齐、结构对称

## 六、验证方式

用实测同款口径自证：给定原文与改后文本，比较

- **表层**：中/英 AI 高频词计数、破折号计数（`ai_tell_check.py` 机械统计）
- **结构**：六条特征 before/after 逐条判定（回执 + 人工/裁判复核）

合格线：**结构层至少改掉 `stated_theme` 与 `tidy_ending` 两条**，且事实一条不丢。只删词、只删破折号的交付，视为不合格。

## 七、审查记录

升级后的 v1.1.0 由三位独立审查员并行把关（性能审查不适用——非 Web 项目，按 SOP 跳过）。以下为原始结论与修复闭环。

### 安全（安守正）—— 两轮，可放行

| 编号 | 定级 | 问题 | 处置 |
|---|---|---|---|
| High#1 | High → **关闭** | 新旧版都没有「数据 vs 指令」边界，粘贴文本可注入 | 已在 SKILL.md 顶部与 agent.md H1 之后各加「输入边界」 |
| High#2 | High → **降 Medium（未关闭）** | 「补一条岔路」授予新增内容权，回执反成背书工具 | 已加保真三约束 + 回执附原文出处 + 无出处标 `[无出处·已删除]`；残余：出处判定仍由模型自证 |
| Medium | Medium → 已修 | `--facts` 子串误判（`100` 命中 `1000`）；定位夸大为「事实核验」 | 数字改边界匹配；标签改为「事实**抽检**」并注明非自动核验 |
| Low | Low → 已修 | 注释称「不跟随符号链接」但代码实际跟随（控制名不副实） | 改为真检查，符号链接直接报错拒绝 |
| Low | Low → 关闭 | 缺合规边界 | `不适用` 段已补学术/出版披露免责 |

安守正对总体判断的修正：**「新版在完整性上更危险」不再成立**。加入输入边界 + 保真三约束 + 回执附出处 + `--facts` 后，v1.1.0 的完整性姿态已不劣于、且略优于 v1.0.1。唯一例外是多租户/自动化部署场景。

**必须原文保留的残余风险表述（不得软化）：**

> 本工件的全部安全防线（输入边界、保真三约束、结构改动回执）均为**提示词级、由模型自证**，无外部强制校验；`--facts` 是人工枚举的抽检而非自动事实核验。它能显著降低注入与事实篡改风险，但无法消除：面对足够强的对抗性注入，防线可被绕过，回执与事实声明本身也可能是幻觉产物。因此不得将该工件部署为处理第三方文本、或输出被下游自动消费的流水线，除非在其外部增加代码级输入隔离与输出校验。

### 代码审查（沈查）—— 两轮，APPROVE

**首轮 REQUEST CHANGES**，指出两个会重新把模型推回表层的自相矛盾：

| 编号 | 定级 | 问题 | 处置 |

| 同步一致性 | 插件市场副本与工作区包 `diff -rq` 完全一致 |

### **未验证（本环境无法闭环）**

> **LLM 实际改写行为未验证。** 本环境无法真实执行「模型按 skill 改写文本」这一步，因此「v1.1.0 提示词能否在真实模型上稳定产出结构层改动」**尚未被证明**——目前证明的只是「指令层已把结构前置并强制、门禁层能识别真假改动」。闭环需要主理人按第七节 A/B 对照协议实跑模型（v1.0.1 提示词 vs v1.1.0 提示词，同一语料，各重复 ≥2 次）。

### 遗留项

| 项 | 级别 | 说明 |
|---|---|---|
| 结构层判定仍是启发式 | 中 | 脚本靠词表与位置启发式判断，「单线推进」这类语义特征机械上抓不到（示例 §6 的改写被判 ⚪）。**门禁是辅助，不是裁判**——脚本自己也会说「读得懂语义的只有改写者本人」 |
| 回执仍是模型自证 | 中 | 安全审查判定 High#2 降级而非关闭：出处判定由模型自己完成，强注入仍可自圆其说 |
| `--facts` 是抽检 | 低 | 只检查人工枚举的项，抓不到未列出的编造 |
| 提示词级防线 | 低 | 输入边界是提示词约束，非强制机制；多租户/自动化管线场景需外挂代码级隔离 |
| recents 版本号 | 低 | `storage/.../expert.json` 的 recents 条目 version 仍为 1.0.1（同步脚本对已存在条目只增不改）。插件本体已是 1.1.0，不影响功能 |

## 九、怎么用

```
# 对比检查（改前/改后）
python3 skills/de-ai-rewrite/scripts/ai_tell_check.py --before 原文.txt --after 改后.txt

# 带事实抽检
python3 .../ai_tell_check.py --before 原文.txt --after 改后.txt --facts "186000,11,8 小时"

# 单篇体检
python3 .../ai_tell_check.py 稿子.txt
```

在「我的专家」里选中老刀后，直接粘贴文本说「去 AI 味」即可。改完它会附一份**结构改动回执**；说「只要正文」则不附。

> **部署后需重启一次 WorkBuddy 应用**，UI 才会扫到更新后的插件目录（白名单与 recents 是热加载，插件目录不是）。

## 十、一句话结论

**老刀 v1.0.1 确实属于「只做表层」那一类**——它的 10 条规则里 9 条是词表，结构层六条特征明确指令 0/6，按实测口径预期得分约 3.0/5，与 5.4 万星的 humanizer 同级。

**v1.1.0 把它从「换词工具」改造成了「结构优先的改写流程」**：三层模型把结构层目标逐条命名、结构手术前置、反退化规则堵住「越改越像 AI」、no-op 出口避免硬凑、五档自检门禁能识别真假改动。诊断中发现的病根（顺序错、目标未命名、无强制产出、输出隐藏改动、保真规则误伤结构手术、过度承诺）六条全部对症处理。

**但它仍然不是「检测工具测不出」**——那个承诺已被删除，因为它无法被兑现，任何工具都做不到。真正的去 AI 味只有一条路：**删道理、开结尾、点实名、留线头**，这四件事做不到，词换得再干净也是白改。
