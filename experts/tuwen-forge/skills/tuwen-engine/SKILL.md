# 图文总入口

一个图文请求进来，**先在这里做四个决定，再去加载任何版式参考**：

| # | 决定 | 去哪一节 |
|---|---|---|
| 1 | 该不该做？做几张？ | §0 |
| 2 | 做哪种出口？ | §1 |
| 3 | 走什么风格与主题？ | §2 |
| 4 | 用哪个版式骨架？ | §3 |
| 5 | 怎么组装与渲染？ | §4 |
| 6 | 怎么证明排对了？ | §5 |

不要跳过。跳过 §0 会产出没人看的图；跳过 §1 会把该发小红书的图做成 21:9 头图；跳过 §5 会交付一张标题溢出的图。

---

## §0 该不该做，做几张

**先判断内容量够不够撑起一套图。** 判据：

| 内容状态 | 结论 |
|---|---|
| 有一个可争辩的核心判断 + 2–3 条支撑 | ✅ 值得做整套 |
| 只有一个判断，没有支撑 | ⚠️ 做**单图**，或先补内容 |
| 只是信息罗列，没有观点 | ⚠️ 做**单张信息图**（数据卡 / 清单），不做轮播 |
| 内容量 > 12 页预算 | ⚠️ 拆上下篇，或改做长图 |
| 内容 < 3 页 | ⚠️ 合并成 1–2 页，或建议改做单图 |

**页数预算**：整套默认 **5–9 页**（含封面与尾页）。硬上限 12 页。小红书一次最多发 18 张，但超过 9 张完读率会掉。

**轮播的黄金结构**（详见 `tuwen-storytelling`）：
```
封面（钩子） → 1 页一个判断（3–6 页） → 收束页（划重点 / 收藏 / 互动）
```

## §1 出口决策

**出口决定画板尺寸、页数预算、命名。这是第一决策。**

| 出口 | 画板 | 尺寸（CSS px = 输出 px @1x） | 何时用 |
|---|---|---|---|
| **单图** | `.poster` | 1080 × 1440 | 一个判断 / 一张信息图 / 分享单卡 |
| **整套轮播** | `.poster` × N | 1080 × 1440 | 小红书 / X 图文组图，5–9 页 |
| **公众号封面对** | `.poster.wide` + `.poster.square` | 2100 × 900 + 1080 × 1080 | 一篇公众号文章的 21:9 头图 + 1:1 分享卡，**视觉必须一致** |
| **中文长图** | `.poster.long` | 1080 × auto（建议 2400–8000） | 高密度信息图：复盘全景 / 工作台账 / 知识卡合集 / 文章导读 |

判定顺序：**先问发布平台，再问内容密度**。同内容发公众号 + 小红书，就是两个出口各出一份，不要一份通用。

- 单图 vs 整套：内容能拆成 ≥3 个独立判断 → 整套；否则单图。
- 封面对是**一对**：`wide` 与 `square` 必须同主题、同字体、同强调色，只有版式比例不同。
- 长图**不切页**：它是单张超高画布，靠板块（`.block`）分层，不靠翻页。
- 长图**两端留白 120 px**（水平 84 px）：垂直留白比 3:4 的 84 px 更大，便于裁切、拼接与二次排版。三套模板已内置，别改小。

> 尺寸口径以 `references/platform-specs.md` 为准；平台安全区、导出倍率、命名规范都在那里。

## §2 风格与主题

**两套视觉系统，选一套。** 不允许混搭。

| 系统 | 气质 | 适合 | 不适合 |
|---|---|---|---|
| **Editorial 编辑杂志风** | 衬线、克制、叙事、留白 | 故事、经历、生活方式、阅读、人文、影视、旅行 | 密集数据、产品参数 |
| **Swiss 瑞士国际主义** | 无衬线、网格、单一锚点色、直角发丝线、极致字号对比 | 产品测评、数据、方法论、教程、AI 工具、观点 | 需要氛围感与情绪的内容 |

**主题预设各 6 套 / 4 套，只能从里面挑，不允许自定义 hex。** 用户不指定时按内容自动匹配并**说明理由**。

> 完整规则与反模式见 `references/style-system.md`；色票详解见 `references/theme-presets.md`。

**一句话选风格**：内容在**讲故事**→ Editorial；内容在**讲道理 / 摆事实**→ Swiss。

## §3 版式骨架

**从版式库里挑、粘、改文案。不要发明不存在的页面。**

- Editorial 16 个骨架（`M01`–`M16`）：封面、分栏、图文比、引言、Before/After、Pipeline、Image-Led Cover、收束页等。
- Swiss 12 个骨架（`S01`–`S12`）：强调色封面、KPI Tower、H-Bar Chart、Matrix + Hero、堆叠 ledger、编号列表等。

选版式时**必须能回答**：为什么是它、为什么不是相邻那两个。

> 每个骨架的文案上限、最小密度、适用场景见 `references/layout-recipes.md`。

## §4 组装与渲染

**只走一条路：单文件 HTML + CSS → Playwright → PNG。** 不引入构建链。

1. 在任务目录建 `index.html`，从 `assets/` 拷一份种子模板当骨架：
   - `assets/template-editorial.html` — Editorial，6 主题 × 3 尺寸
   - `assets/template-swiss.html` — Swiss，4 主题 × 3 尺寸
   - `assets/template-longform.html` — 中文长图
2. 每个画板是一个 `<section class="poster" data-theme="…" data-name="01-cover">`。
   `data-name` 决定输出 PNG 的文件名。
3. 所有样式走 CSS 变量（`var(--ink)`、`var(--paper)`、`var(--accent)`…）。切主题只改 `data-theme`。
4. 渲染：
   ```bash
   node scripts/render.cjs <任务目录>
   ```
   输出到 `<任务目录>/output/`，默认 2x Retina。
5. **字体**：CSS 里已写好 macOS 优先的 CJK 字体栈；渲染前脚本会 `await document.fonts.ready`。**缺字必须显式失败，不许出缺字图。**

> 渲染链路、字体栈、浏览器解析顺序、失败兜底见 `references/render-pipeline.md`。

## §5 质检闸门

**交付前必须跑：**

```bash
node scripts/verify.cjs <任务目录>
```

它用 Playwright 做**真实 DOM 测量**，不是静态扫描。规则：

| 规则 | 拦什么 |
|---|---|
| `R1 overflow` | 任何元素超出画板 → error，并给出超出像素对应的修正阶梯 |
| `R2 footer-collision` | 内容压到底部页脚 / 页码 |
| `R3 min-font` | 正文字号低于手机可读下限（正文 < 24px） |
| `R4 band-density` | 1440 高画布切 4 横带，某带既无内容也无 `.allow-void` 标记 |
| `R5 line-cap` | `.h-display` / `.h-xl` 行数超出该画板预算 |
| `R6 title-gap` | 标题与下一块内容间距过小（贴在一起） |
| `R7 bottom-void` | 内容底部留白超过画板高度的 22%，且这片空洞**没有被 `.allow-void` 覆盖**（区域级判据：标记须与空洞纵向重叠 ≥ 50% 才算覆盖） |
| `R8 orphan-line` | 末行只剩一个字（孤字）——中文排版最扎眼的瑕疵，肉眼才看得出，这条把它自动化 |

- 有 `error` → **不得交付**，先修再跑。
- 只有 `warn` → 可以交付，但必须在交付说明里逐条说明。
- 脚本跑不起来（浏览器起不来 / 文件缺失）→ **如实说「这次只做了人工核对」**，并逐条走 `references/qa-checklist.md` 的人工清单。

> 人工清单、每条规则的判据与修正阶梯见 `references/qa-checklist.md`。

## §6 交付

交付**两样东西**：

1. **PNG**（`output/` 下的图，直接给用户看）
2. **交付说明**（一段话）：
   - 出口 / 视觉系统 / 主题预设 / 页数
   - 每页用了哪个版式骨架
   - 质检结论（跑了没有 / 有没有 warn / 逐条说明）
   - **被砍掉的内容**（以及为什么砍）

**先给图，再给说明。** 不要把说明写进图里。

## §7 渲染边界（诚实清单）

| 能力 | 状态 | 说明 |
|---|---|---|
| HTML/CSS → Playwright → PNG | ✅ 可用 | 本机系统 Chrome + `--no-sandbox`，已实测 2x Retina 出图 |
| CJK 字体渲染 | ✅ 可用 | macOS 系统字体栈，`document.fonts.ready` 后截图 |
| CSS Grid / Flex / 变量 / 伪元素 | ✅ 可用 | 版式全部靠这些 |
| SVG 内联图形（图表、图标、线条） | ✅ 可用 | 数据卡 / 迷你图表走手写 SVG |
| WebGL / canvas 背景 | ⚠️ 可用但需实测 | 截图前必须等一帧稳定；低性能或截图异常时**禁用**，退回纯 CSS 纹理 |
| 网络图源（Unsplash / Pexels 等） | ⚠️ 需联网且需署名 | 取图后必须落本地 + 写 `SOURCES.md`；离线环境改用纯排版图形 |
| 生图模型 | ❌ 不用 | 本专家的定义性约束 |

**跑不动就如实说，不许假装出了图。**
