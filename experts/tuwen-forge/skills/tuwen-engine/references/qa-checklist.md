# 质检闸门 · 规则与人工清单

> 交付前跑 `node scripts/verify.cjs <任务目录>`。它是**真实 DOM 测量**，不是静态扫描。
> 有 `error` → 不得交付。只有 `warn` → 可交付，但必须在交付说明里逐条说明。

## 一、八条自动规则

### R1 `overflow` — 元素溢出画板（error）

**判据**：任一元素的 `getBoundingClientRect()` 超出 `.poster` 的边界（右/下超出 > 2 px 容差）。

**修正阶梯**（按顺序试，不要跳）：
1. 砍文案（首选，且最有效）
2. 提高该页的留白预算（减 padding 之外的装饰）
3. 缩小字号**一档**（但正文不得低于 24 px）
4. 换版式骨架
5. 拆成两页

⚠️ **禁止**用 `overflow: hidden` 掩盖溢出——那只是把问题藏起来。

### R2 `footer-collision` — 内容压到页脚（error）

**判据**：主体内容区（`.poster-body`）的底边 > 页脚（`.poster-footer`）的顶边。

**修正**：给主体区加 `padding-bottom`，或砍内容。页脚与主体之间至少留 32 px。

### R3 `min-font` — 字号过小（error）

**判据**：遍历画板内**所有含文本的叶子元素**（含直接文本子节点的元素），其 `font-size < 24 px`。

**例外**：`.caption`（来源 / 注脚）与 `.poster-footer`（页码 / 署名）豁免——它们不承担正文阅读。

⚠️ 判据是「叶子元素」而不是「选择器列表」：`.ledger-row`、`.matrix-cell` 这类**容器**会继承 16 px 的 `font-size`，按选择器抓会把容器误判成正文。

**修正**：提字号 → 砍文案 → 换版式。**不允许**为了塞内容把正文压到 24 px 以下。

### R4 `band-density` — 横带密度不足（warn）

**判据**：画板高度 ≥ 900 px 时，纵向均分 **4 条横带**（带高 = 画板高 ÷ 4）；某条带内**既没有任何文本元素，也没有 `.allow-void` 标记**。

- 1440 高的 3:4 画板 → 带高 360 px
- 1080 高的 1:1 画板 → 带高 270 px
- 长图（1080×auto）→ **带高随实际高度变化**（4000 px 长图即 1000 px 一带），不是固定 360 px

**修正**：
- 内容太少 → 补内容，或换更简单的版式（单图而非整套）
- 有意留白 → 给该区域加 `<div class="allow-void" data-void="呼吸区，突出标题"></div>`

### R5 `line-cap` — 标题行数超预算（error）

**判据**：

| 类 | 字号 | 行数上限 |
|---|---|---|
| `.h-display` | ≥ 88 px | 3 行 |
| `.h-statement` | ≥ 72 px | 4 行 |
| `.h-xl` | 56–87 px | 4 行 |
| `.h-lg` | 40–55 px | 5 行 |
| `.h-md` | < 40 px | 6 行 |
| `.block-title` | — | 4 行 |

**修正**：砍标题字数 → 提高字号换更短的措辞 → 换 `M15`/`S04` 这类「大字号专用」版式。

### R6 `title-gap` — 标题与下一块贴太近（warn）

**判据**：标题块底边到下一个内容块顶边的距离 < 24 px。

**修正**：给标题加 `margin-bottom`，或给下一块加 `margin-top`。

### R7 `bottom-void` — 底部留白过大（warn）

**判据**：最后一个**正文**元素的底边距画板底部 > 画板高度的 22%（1440 画板即 > 317 px），**且这片空洞没有被 `.allow-void` 覆盖**。

⚠️ 页脚（页码 / 署名）不计入「正文元素」——否则 `lastBottom` 永远落在画板底部，**底部空洞永远测不出来**。

**「覆盖」怎么算（区域级判据）**：某个 `.allow-void` 与空洞区（`lastBottom` → 画板底部）的**纵向重叠 ≥ 空洞高度的 50%** 才算覆盖。

⚠️ 这里**必须按区域判，不能按整页判**。若用「页面上任意位置有一个 `.allow-void` 就整页沉默」这种粗粒度写法，**顶部**有个小呼吸区标记、**底部**却有意外的空洞时，底部空洞会被一并放过。脚本的提示语会区分两种成因：

- `且未标记 .allow-void` —— 页面上根本没有留白标记
- `页面上虽有 .allow-void，但没有覆盖到这片空洞` —— 有标记，但标记在别处（这才是区域级判据要抓的）

**修正**：补内容 / 换更满的版式 / **把 `.allow-void` 挪到空洞所在的位置**（拉伸型标记放在最后一个内容块之后，它会自动吃掉剩余空间）。

### R8 `orphan-line` — 末行孤字（warn）

**判据**：某段文本折行 ≥ 2 行，且**最后一行只剩 1 个字**。

实现方式：用 `Range.getClientRects()` 取到每个行盒，再二分查找「最后一行从第几个字符开始」，差值即末行字数。

**修正阶梯**：
1. 给该元素加 `text-wrap: pretty`（Chrome 支持，最省事，优先试）
2. 仍不解决 → 改文案，把末行那个字挪上去（加一个字或减两个字）
3. 容器宽度微调（`padding` 减 4–8 px）

⚠️ `text-wrap: pretty` 能解决大多数情况，但**不是万能的**——短行 + CJK 时可能仍留孤字，此时只能改文案。这条规则本身就是「肉眼才看得出」的典型，别因为脚本没报就跳过目视。

## 二、脚本跑不起来时的人工清单

浏览器起不来、文件缺失、或环境不支持时，**逐条人工核对**，并在交付说明里写「本次未跑自动质检，已人工核对以下 N 条」。

### 排版
- [ ] 没有元素超出画板（目视四边）
- [ ] 标题没有被裁断，行数在预算内
- [ ] 正文 ≥ 24 px（可读性）
- [ ] 标题与正文之间有明确间距，不贴
- [ ] 页脚没被内容压住
- [ ] 每页内容覆盖高度 ≥ 70%，或留白有理由

### 中文
- [ ] 没有缺字（方块 / 问号 / 空白）
- [ ] 标点是全角，不是半角
- [ ] 中英混排处有 1/4 空隙
- [ ] 没有孤字成行（一行只剩一个字）
- [ ] 没有标点出现在行首（避头尾）

### 视觉
- [ ] 整套图同一主题、同一字体
- [ ] 强调色全页只用一处或一个区域
- [ ] 正文与底色对比度 ≥ 4.5:1
- [ ] `lemon` / `lime` 主题下没有黄色/绿色的字压在浅底上
- [ ] 没有硬编码颜色（换主题时会露馅）
- [ ] 页码与署名位置一致

### 平台安全区（自动规则查不到，必须目视）

> 自动规则只测画板内部的一致性，**测不出「平台会盖住哪一块」**。口径见 `platform-specs.md`。

- [ ] **3:4（小红书 / X）**：最底部 **160 px** 内没有关键信息（详情页文案与操作栏会遮挡）；顶部 **80 px** 留白
- [ ] **21:9（公众号头图）**：把**中心 1080×900** 单独截出来看——标题主体仍在、左右两端没有关键信息（会被按中心 1:1 裁切）
- [ ] **1:1（分享卡）**：关键元素避开**正中偏下**（分享卡中心有圆形头像遮挡）
- [ ] **长图**：顶部与底部各 **120 px** 是空白，没有被文字压到

### 内容
- [ ] 一页一个核心判断
- [ ] 封面能独立成立（脱离正文看得懂）
- [ ] 没有编造原文没有的信息（数字 / 人名 / 结论）
- [ ] 图上没有制作术语（「本页采用 M03」这类）
