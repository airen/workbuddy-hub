# 文案压缩

> 塞不下的时候，**砍文案，不要缩字号**。这是本专家最硬的一条纪律。

## 一、先算预算，再写文案

1080 宽画板、边距 76 px → 内容宽 **928 px**。

| 字号 | 每行字数（中文） | 一页可用行数 | 一页字数上限 |
|---|---|---|---|
| 34 px 正文 | ≈ 27 字 | 6 行 | ≈ 160 字 |
| 30 px 正文 | ≈ 30 字 | 7 行 | ≈ 210 字 |
| 52 px 标题 | ≈ 17 字 | 2 行 | ≈ 34 字 |
| 96 px 大标题 | ≈ 9 字 | 2 行 | ≈ 18 字 |

**写之前先按这张表估。** 排完才发现溢出，返工成本高得多。

## 二、六种压缩手法

### 1. 删限定词

```
❌ 其实在很多时候，我们往往会不自觉地…
✅ 我们常常…
```

删：其实 / 往往 / 在某种意义上 / 某种程度上 / 一般来说 / 不得不说

### 2. 把从句拆成短句

```
❌ 因为生图模型并不理解字形的构造，所以它画出来的字本质上是像字的花纹。
✅ 生图画出的字，是「像字的花纹」。它不懂字形构造。
```

### 3. 抽象名词换成动词

```
❌ 进行优化 → ✅ 优化
❌ 做出判断 → ✅ 判断
❌ 实现提升 → ✅ 提升
```

### 4. 数字替代描述

```
❌ 速度有了非常显著的提升 → ✅ 快了 3 倍
❌ 大量用户反馈 → ✅ 128 条反馈
```

### 5. 删掉重复语义

```
❌ 唯一仅有的一个 → ✅ 唯一
❌ 提前预判 → ✅ 预判
❌ 免费赠送 → ✅ 送
```

### 6. 把"补充说明"移到下一句或删掉

```
❌ 这个方案很好用（当然前提是你得先装好环境，配置好路径，还要注意版本兼容性）。
✅ 这个方案很好用。
```

## 三、哪些内容可以砍

| 可以砍 | 不能砍 |
|---|---|
| 铺垫、背景介绍 | 核心判断 |
| 重复的论据 | 关键数字 |
| 常识性解释 | 结论 |
| 冗余的修饰 | 人名、时间、出处 |
| 与主线无关的支线 | 唯一的证据 |

## 四、一页的文案结构

```
标题（判断）      ≤ 20 字
   ↓
支撑（1–3 段）    每段 ≤ 60 字
   ↓
强调（可选）      ≤ 24 字
```

**支撑超过 3 段，就该拆页。**

## 五、标题的压缩

标题是压缩率要求最高的地方。

```
原始：关于 AI 生图在中文排版场景下的一些局限性分析
压缩：AI 出图，为什么中文总翻车
```

手法：**留冲突，删限定，换主动语态。**

## 六、压缩后自检

- [ ] 按预算表估过字数，不是排完才发现
- [ ] 没有删掉关键数字
- [ ] 没有删掉结论
- [ ] 标题 ≤ 20 字
- [ ] 每段 ≤ 60 字，一页 ≤ 3 段
- [ ] 压缩后语义没变

## 七、反面案例

```
❌ 一页塞 400 字（字号被迫降到 22 px）
   → 手机上读不了，且违反 R3

✅ 拆成两页，每页 180 字（字号 32 px）
   → 读得舒服，完读率更高
```

**永远不要为了"一页讲完"而牺牲可读性。**
