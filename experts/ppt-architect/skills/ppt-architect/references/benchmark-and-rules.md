# PPT 实测基准与质量规则（benchmark-and-rules）

本文件汇总自「27 套 PPT Skill 同需求实测」与「萝卜 PPT / luobo-ppt」开源实践，是 ppt-architect 的质量底线。每次出片前对照执行。

## 一、27 套实测结论（同一份 8–10 页需求，Opus 5.5 生成、gpt-6-astra 逐页打分）

- ① 数字一个没错，但 8 套**加了需求里没有的说法** → 编造是头号问题，必须零容忍。
- ② 要大改的 2 套，**全是图片，字改不了** → 纯图片 PPT 不可编辑，正式交付禁用。
- ③ 设计满分的 ppt-agent-skills 只有 904★ → 设计≠好用，过重反而难落地。
- ④ 5.8 万★ 的 ppt-master 微调就能交 → 稳定、可控、可交付优先于花活。
- ⑤ 转换器能把全图片 PPT 转回可编辑：**0 → 2224 个字** → 「图片 + 转换器」是"要 pptx 又要好看"的兜底路径。

## 二、怎么选格式（怎么选）

| 用途 | 选什么 | 说明 |
|---|---|---|
| 同事要改 / 正式交付 / 二次编辑 | **原生 PPTX** | 字在文本框、表格是真表、图表双击可改 |
| 自己讲 / 在线演示 / 追求高颜值 | **网页 HTML** | 单文件、浏览器直接开、动效自由 |
| 发社媒 / 朋友圈 / 缩略图 | **图片** | 出整页或长图，注意字不可改 |
| 要 pptx 又要好看 | **网页/图片 + 转换器** | 先用高颜值出图，再用转换器还原可编辑 PPTX |

> 用户没说时按关键词路由：汇报/提案/客户/正式/交同事 → PPTX；分享/演示/技术/网页 → HTML；社媒/朋友圈/封面 → 图片。

## 三、质量铁律（不可协商）

1. **不编造**：只基于用户给的素材（文章/大纲/数据）产出。**绝不添加需求里没有的说法、案例、数据**。来源里没有的数字、结论、引用，一律不写；要补就明确标"待你确认"。
2. **数字精确**：所有数字逐字照搬，不四舍五入、不"约"、不重算。图表数据与来源一一对应。
3. **原生优先**：正式交付默认原生 PPTX——文字在文本框、表格是真表格、柱状/饼图双击可改数据；背景/插画/图标才用图片。禁用"整页导出成图"当正式稿。
4. **美化不改字**：美化已有 PPT 时，**文字一字不改**，只换配色/版式/图标/插画；用脚本逐字核对（不是靠大模型自觉），改完报"哪些字变了：无"。
5. **中式语境**：审美与表达顺着中文习惯走，标题说人话、不拧巴；参考图/预设风格驱动，不强行西式排版。
6. **公式转纯文本**：理科/数据稿里的公式写成纯文本公式（如 `V′(x) = (a−2x)(a−6x)`），别用公式编辑器对象，换软件也能看、能改。

## 四、容量与一致性规则（防溢出、防缩字）

| 版式 | 容量上限 |
|---|---|
| 标题 | ≤ 12 字（结论式优先，如"数据分析""项目介绍"这类话题标题要标出来让用户改） |
| 正文 | 每页 ≤ 6 行，每行 ≤ 20 字 |
| 要点 | 3–5 条 |
| 漏斗 | 最多 5 层，每层说明 ≤ 26 字 |
| 2x2 矩阵 | 每象限 ≤ 3 条，每条 ≤ 14 字 |
| 时间线 | 节点 ≤ 8 个，每节点 ≤ 14 字 |

- **强调色**：一页最多用 3 处；全篇字号只从一组固定阶梯里挑（如 40/28/20/16/13），禁止为塞字临时缩小。
- 字数超了就**换装得下的版式**或拆页，**不要硬塞、不要缩字**。

## 五、五维自检（每次出片后自评）

| 维度 | 看什么 |
|---|---|
| 统一 | 风格/配色/字号阶梯全局一致；章节页编号与目录同款 |
| 层级 | 标题 > 正文 > 备注 清晰；重点有且只有一两处 |
| 细节 | 对齐、留白、图标语义正确；无错别字、无溢出 |
| 传达 | 每页一句话能说清在讲什么；结论式标题 |
| 节奏 | 封面→目录→章节→内容→结尾 首尾呼应；篇幅分配均衡 |

## 六、结构与流程增强

- **幽灵稿先行**：先出"只有标题"的骨架（每页一句结论标题 + 目录由章节页自动生成），让用户先定结构，再填充。
- **口播备注**：每页配 50–100 字演讲者备注，打开备注栏就能照讲。
- **参考图迁移**：用户给参考图时，按视觉元素复现（如封面画上参考图里的风车/山景），不依赖 AI 生图模型也能出完整画面。
- **快速模式**：赶时间说"快速模式"，跳过中间确认环节，10 分钟上下出片；默认完整流程 15–25 分钟。
