# 角色 IP 视觉总入口

一个「用固定角色建立个人品牌」的请求进来，**先在这里做三个决定，再去加载任何具体技能**：

| # | 决定 | 去哪一节 |
|---|------|---------|
| 1 | 这个角色**现在**要替你做什么？ | §1 三问定界 → §2 路由表 |
| 2 | 它的**身份锚点**是什么，存在哪？ | §4 一致性契约 → §5 档案互认 |
| 3 | 这一张图，**凭什么还是同一个人**？ | §6 一致性闸门 |

**核心命题**：难点不在画得好看，在于**换一篇文章、换一个场景，读者还能认出同一个「你」**。所以本专家的默认动作永远是：先固定角色，再生成内容；先生成一张，确认后再批量。

---

## §1 三问定界（每次开工前必答）

只问当前真正缺的那一问，能从上下文推断的就推断，并把推断写成假设让用户纠正。

| 问 | 要问出什么 | 答不上来时的默认 |
|---|---|---|
| **谁** | 这个角色是谁？有现成照片/玩偶/头像/既有角色吗？还是只有一句人设？ | 先按「从零设计」走，别急着要照片 |
| **干什么** | 这次要产出的是：角色档案 / 头像 Logo / 文章配图 / 知识图解 / 整套长文视觉？ | 按用户给的材料形态反推（见 §2） |
| **出到哪** | 发在哪：公众号 / 小红书 / 知乎 / 官网 / PPT / 只是自己存档？ | 问一次，因为它决定比例与安全区 |

> 三问答完仍不确定选哪条路线时，把 §2 路由表**原样贴给用户**让他选。不要替用户在两条差别很大的路线之间硬猜。

## §2 路由表（7 条路线）

| 路线 | 加载技能 | 什么时候走它 | 典型输入 | 主产出 |
|---|---|---|---|---|
| ① 建档 | [comic-ip-onboarder](../comic-ip-onboarder/SKILL.md) | **已经有**照片 / 玩偶 / 手办 / 头像 / 吉祥物，要变成可复用角色 | 源图 + 角色名 | `IP_DNA.md` + 正面全身确认图 + 三视图 + 8 张表情动作图 |
| ② 从零设计 | [ip-character-designer](../ip-character-designer/SKILL.md) | **只有一句人设或品牌定位**，没有任何形象素材 | 品牌名 + 调性关键词 | 角色设定表 + 视觉规范 + 表情系统 + 品牌物料提示词 |
| ③ 头像 / Logo | [ip-as-logo](../ip-as-logo/SKILL.md) | 只要**一个方形标识**：头像、Logo、吉祥物，强调缩小后仍可辨识 | 产品做什么 / 给谁用 / 什么气质 | 3 个方向 + 6 张 1:1 候选（32×32 可辨识） |
| ④ 文章配图 | [punk-ip-article-illustrations](../punk-ip-article-illustrations/SKILL.md) | 有**真人照片**，想直接做到文章配图；或想直接用内置角色 Punk | 照片 + 文章 | 角色包（draft→confirmed）+ 正文插图 + 建议插入位置 |
| ⑤ 长期复用 | [lz-ip-illustration](../lz-ip-illustration/SKILL.md) | 要**跨文章、跨平台长期复用**：封面、正文图、小红书卡片、动图都要进同一套流程 | IP 档案 + 文章 | `ip-profile.md` + `visual-spec.md` + `prompt-pack.md` + `action-library.md` + 各 run 目录 |
| ⑥ 角色图解 | [ip-diagram-creator](../ip-diagram-creator/SKILL.md) | 想让**角色替你讲流程、讲知识**：知识卡、方法步骤、海报、PPT 演讲页 | 照片/主页截图/简介 + 长文或大纲 | 三张角色固定资产 + 长文配图 / 知识卡 / 方法拆解图 / PPT 页面 |
| ⑦ 长文统一视觉 | [editorial-ip-visuals](../editorial-ip-visuals/SKILL.md) | 要**一整篇文章视觉统一**：封面 + 方形缩略图 + 正文论证图，且要精确插入位置 | 文章全文 + 发布平台 | 横版封面 + 1:1 缩略图 + 3–4 张 16:9 正文图 + 插入定位表 |

### 决策树：按「你手上现在有什么」选

```text
手上有什么？
├─ 一张照片 / 一个玩偶 / 一个现成角色
│   ├─ 目标是「先有个角色档案」          → ① 建档
│   ├─ 目标是「给这篇文章配图」          → ④ 文章配图（内含建档，一步到位）
│   └─ 目标是「以后每篇都能用」          → ⑤ 长期复用（先建档再进 run）
├─ 只有一句人设 / 品牌定位
│   ├─ 要一个完整角色                    → ② 从零设计
│   └─ 只要一个方形标识                  → ③ 头像 / Logo
├─ 已经有确认过的角色档案
│   ├─ 配正文插图                        → ④ 或 ⑤（⑤ 更适合要跨平台复用的）
│   ├─ 讲流程 / 讲方法 / 做知识卡 / PPT   → ⑥ 角色图解
│   └─ 整篇长文一套视觉 + 插入位置        → ⑦ 长文统一视觉
└─ 什么都没有，只有一篇写好的文章
    └─ 先回到 §1 第一问：没有角色就先建档（① 或 ②），不要直接生成配图
```

### 三条硬路由规则

1. **没有已确认角色，不生成内容图。** 用户直接说「给这篇文章配图」但手上没有确认过的角色时，先停下来建档（① 或 ②），或问他是否要用内置角色 Punk（④）。
2. **不要同时混用两条路线的画风。** 同一个角色的画风绑定在档案里；换路线时读档案里的 `style` / 视觉规范，不要凭记忆重画。
3. **⑦ 和 ④/⑤ 不要叠着用在同一篇文章上。** ⑦ 是「整篇统筹 + 插入定位」，④/⑤ 是「逐张插图」。选一个当主路线，另一条最多用来补单张。

## §3 不要用本专家做什么

- 通用插画 / 无身份角色的配图需求 —— 这不是个人 IP 系统，直接走通用生图。
- 纯排版图文卡片（不出图、用代码排）—— 那是图文排版技能的事，不是本专家的路线。
- 拿别人肖像做 IP —— 只处理用户**自己**授权提供的照片、主页截图、简介、账号资料。
- 把 AI 重绘的社交平台界面当成真实用户证据 —— 需要截图证据时按 ⑦ 的脱敏规则走。

## §4 一致性契约（跨路线通用）

无论走哪条路线，**这四件东西必须在生成任何内容图之前就固定下来**：

1. **角色参考图**（identity anchor）：一张被用户明确确认过的全身/主锚图。之后每次生成都把它作为图像参考输入，**不是只靠文字描述重画**。
2. **视觉规范**（visual spec）：配色锚点、线条风格、材质、头身比、背景规则。**即使带了参考图，也要在提示词里用文字显式重申** —— 参考图管身份，文字管规则，两者都要。
3. **识别锚点**（recognition anchors）：3–5 个「以后绝对不能漂移」的特征（发型、眼镜、标志性配饰、服装逻辑、体型）。
4. **禁区**（never-do）：明确写出不能变的项与不能借用的东西（其他 IP 的外貌、照片原始背景、水印、文字）。

> 这份契约在四条路线里名字不同、载体不同（见 §5），但内容必须是同一套。**换路线时先把它翻译过去，再开工。**

## §5 档案互认与交接

四个技能各自产出的角色档案格式不同。走跨路线流程时，按这张对照表做翻译，**不要重造角色**：

| 概念 | ① comic-ip-onboarder | ④ punk-ip-article-illustrations | ⑤ lz-ip-illustration | ⑥ ip-diagram-creator | ⑦ editorial-ip-visuals |
|---|---|---|---|---|---|
| 档案主文件 | `IP_DNA.md` | `character-spec.md` + manifest | `ip-profile.md` + `visual-spec.md` + `prompt-pack.md` | 角色信息提取卡 | Visual Brief（每篇一份） |
| 主参考图 | `front-full-body.png` / `three-view.png` | `*-reference-clean.png` | `reference-images/*-visual-master-v1.png` | `01_角色主锚图` | `assets/default-ip-reference.png` 或用户新图 |
| 动作库 | `expressions/01..08` | 按 `character-package.md` 结构 | `action-library.md` | `03_动作_表情_小比例场景扩展图` | 无（按 shot list 现场设计动作） |
| 画风绑定 | 档案内风格 DNA | manifest 的 `style` 字段（`retro-flat-3d` / `loose-watercolor`） | `visual-spec.md` 的 rendering 段 | 视觉语言段 | 固定层（3D 玩偶 + 灰白编辑空间） |

**交接模板**（把角色从 A 路线交给 B 路线时，按这个格式说清楚）：

```text
当前角色档案：<绝对路径>
角色名 / slug：
主参考图（identity anchor）：<绝对路径>
视觉规范：<配色锚点 / 线条 / 材质 / 头身比 / 背景规则，一段话说清>
识别锚点（不可漂移）：1) … 2) … 3) …
禁区：1) … 2) …
画风绑定：<风格名 + 来源>
硬性质检：<5–8 条不可妥协的检查项>
```

> 交接时**只传这份契约**，不要把上一个技能的整套参考文档塞给下一个技能。下一个技能需要细节时，让它自己去读档案文件。

## §6 一致性闸门（每张图都要过）

### 生成前

- [ ] 已确认的角色参考图**已作为图像参考输入**（不是只写在提示词里）
- [ ] 提示词里**用文字重申**了配色、线条、材质、头身比、背景规则
- [ ] 本张图**只解释一个**认知锚点 / 只表达一个核心判断
- [ ] 角色在画面里**参与核心动作**，不是站在旁边当装饰
- [ ] 已确认这张图的图内文字（短、少、可核对）
- [ ] 已保存提示词到独立文件（可复现记录）

### 生成后

- [ ] 还像**同一个角色**吗？识别锚点有没有漂移？
- [ ] 是不是**明显沿用了参考图**，而不是像重新设计的角色？
- [ ] 配色、线条、材质、头身比、背景与上一张是否一致？
- [ ] 图内文字是否准确、可读、不过量、不裁切？
- [ ] 有没有误借别的 IP 的特征？有没有复刻旧图的构图？
- [ ] 角色是否抢走了内容信息（尤其是长文配图）？

**任一项不过，先修再继续。** 不要用模糊的「更好看」反复漂移整套风格；返修时把用户的话翻译成一个**有明确目标**的编辑动作（「仅修正标题」「仅恢复灰色针织衫」「仅减少右侧元素」）。

### 一致性失守的三种典型症状与处置

| 症状 | 常见原因 | 处置 |
|---|---|---|
| 每张图像不同的人 | 只靠文字描述重画，或参考图只在第一张传了 | 每一张都重新附上同一张已确认参考图 |
| 同一角色但风格漂移 | 换了路线却没翻译视觉规范 | 按 §5 把视觉规范翻过去，写进新提示词 |
| 角色对了但内容不解释 | 生成前没定「这张图解释哪一句」 | 回到 shot list，一个锚点一张图 |

## §7 通用边界

- **隐私**：只处理用户明确授权提供的照片、主页截图、简介、账号资料。不根据照片猜测姓名、职业、民族、健康、政治倾向、宗教、性取向等敏感属性。不鼓励上传他人肖像。
- **不伪造**：不把 AI 重绘的社交平台界面伪装成真实截图；不编造帖子、评论、点赞数。
- **不覆盖**：已有角色资产与插图不覆盖，用 `-v2` / `-v3` 或时间戳版本。
- **文字**：需要图内中文时，**必须是整合在画面里的字**（生成时就带上），不要用后期贴字补救。
- **没有生图能力时**：输出完整可执行的中文提示词 + 参考图路径 + 保存计划，并**明确说明尚未生成图片**。不要用 HTML / CSS / SVG / canvas / 网页截图伪装成最终图片。

## §8 输出模板

每次交付时说清这五件事：

```text
走了哪条路线：<①–⑦ + 技能名>
角色契约：<主参考图路径 + 识别锚点 + 禁区>
这次产出了：<文件清单（绝对路径）>
一致性结论：<逐张是否过闸门；不过的是哪一条>
下一步建议：<推荐动作 + 一个明确的确认问题 + 2–3 个可选方向>
```

> 阶段结束时**主动推进**：不要只说「完成了」，也不要让用户自己猜下一步。把推荐选项放在第 1 个。
