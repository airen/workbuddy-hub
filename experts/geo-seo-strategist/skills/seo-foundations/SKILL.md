# SEO 地基与关键词研究

在做 GEO 之前，先把 SEO 地基做通。**GEO 不是推翻 SEO，而是 SEO 在 AI 问答场景下的延伸；如果页面没被 Google 发现、收录、理解，AI 也没有内容可以引用。** 本技能把"从真实需求到能被收录、有排名的页面"落成可执行的 SOP。

> 核心顺序：先让一张页面跑通（有人搜索 → 有人进入网站 → 有人使用产品），再照同样的方法做下一张。等网站里越来越多页面能被发现、被理解、被引用，SEO 才会形成稳定流量；这之后再做 GEO，才有可被 AI 找到和推荐的内容。

## 适用场景

- 用户的网站还没被 Google 收录 / 没有自然搜索流量，却想直接做 GEO
- 用户问"怎么开始 SEO""为什么没流量""关键词怎么找"
- 作为 `geo-topic-research` 的上游：先有被收录、有排名的内容，再在其上做 GEO 选题

## 输入

- 产品 / 网站定位（解决谁的什么问题）
- 目标市场与语言（美国 / 日本 / 国内…用目标用户真实使用的语言做最终判断）
- 如有：Search Console 权限、现有页面清单

## 执行步骤

### 步骤 1 — 先想清 SEO 是什么（不是多写文章）

SEO = 把"有人搜索"到"有人进入网站"这一段路打通：找到真实需求 → 判断用户想看工具 / 商品 / 教程 / 对比 → 做出能被 Google 发现、读取、收录的页面 → 用内链 / 外链帮 Google 理解关系 → 按真实展示 / 点击 / 搜索词持续改。广告停了流量就掉；SEO 做的是持续获得正在找你的人。

### 步骤 2 — 理解 Google 的四步链路（不可混为一谈）

一张网页进入搜索结果要过四步：**发现 → 抓取 → 收录 → 排名**。发现了不代表抓取；抓取了不代表收录；收录了不代表有排名。SEO 做的每件事都能放回这条链路看：需求和搜索词决定回答什么；内容和技术设置决定 Google 能不能读懂；内链 / 外链帮助发现和判断重要性；搜索数据告诉你前面判断对不对。

### 步骤 3 — 第一步是"真实需求"，不是关键词

先别急着注册域名 / 写文章 / 提交收录。用一个需求把问题拆开（以"压缩图片"为例）：要做什么（压缩 / 缩小体积）、为什么（邮件太大 / 上传失败 / 加载慢）、什么设备、什么文件（JPG/PNG/证件照/商品图）、担心什么（变糊 / 泄露 / 太慢）、会比较什么（免费 / 免注册 / 替代品）。这些只是**需求地图**，不是最终关键词；最后判断必须回到目标用户实际使用的语言。

### 步骤 4 — 已知需求，找更多搜索词（AI 扩词，再用真实数据收窄）

- **先让 AI 铺开**：把产品 / 用户 / 场景给 AI，按"想直接完成 / 遇到限制 / 学操作 / 比较工具 / 找替代 / 担心隐私画质速度"等方向列候选说法。**AI 适合**补同义说法、找没想到的场景、把大批词分组；**AI 不适合**直接告诉你"这个词一定有流量 / 竞争很小 / 做了一定排上"——这些要真实搜索结果和关键词工具核对。
- **再到真实搜索环境收窄**：Google 输入核心说法，看自动补全、"相关搜索"、"其他人还问了"（来自真实搜索）。
- **关键词工具扩更多**：Ahrefs 免费关键词生成器、OpenSEO 关键词生成器（返回相关词、估算搜索次数和竞争）；Google Trends 看上升 / 稳定 / 季节热度（相对热度，非准确人数）；Google Ads 关键词规划师看搜索量区间、地区、广告竞争（需登录 Ads 账号，可输搜索词或竞品网址）。
- **广告参考数字**（工具里显示的点击出价）只帮判断"这个搜索背后有没有生意"，不能单独决定做不做。
- **人负责删**：去掉和产品无关、没有点击机会、或自己根本解决不了的需求。

> 所有工具的可用性 / 功能 / 数据口径会变，引用前建议联网复核当前状态。

### 步骤 5 — 搜索意图别只让 AI 猜，必须亲自搜

"搜索意图"= 用户输入这句话时想干什么（`compress image how` 像找教程；`online image compressor` 想马上用工具；`best image compressor` 在比较；`X alternative` 在找替代）。AI 可做第一轮分类，但**最后一定要亲自搜索**——真正决定页面类型的是当前前排结果：前排是工具页，说明想直接操作；多是教程，说明想看步骤。判断只看三件事：前排是什么页面、它们怎么呈现、共同强调什么（免费 / 速度 / 免注册 / 安全）。分别搜两个词，前排大部分相同可先同页承接；完全不同就拆两页。

### 步骤 6 — 把需求变成"页面"，不是一堆文章

按需求类型决定页面类型：工具需求→工具页，购买需求→商品页，学习需求→教程，比较需求→对比页。不要所有词都写成博客，也不要为多收录把同一功能换词复制成十张页面。内容运营按四层排：**核心页面**（真正提供产品 / 工具 / 服务，最重要）→ **场景页面**（某文件 / 设备 / 职业 / 使用场景）→ **教程内容**（怎么做 / 为什么失败 / 怎么选）→ **比较内容**（帮挑方案）。新站先做少量核心页，再补场景和教程。AI 可整理提纲、翻译初稿、补 FAQ、查遗漏，但发布前人工核对三件事：内容是否真符合产品功能、步骤能否操作、语言是否像当地用户会说的话。批量生成几十篇意思差不多的文章只会更乱。

### 步骤 7 — 工具页要让用户和 Google 都看懂

工具页最上面先说清能做什么、马上让用户操作，说明 / 限制 / FAQ 放工具后面。检查基础位置：搜索标题（结果页主标题，直接说清解决什么）、搜索说明（标题下简介）、页面主标题（进入后最大标题）、小节标题（步骤 / 限制 / FAQ 分开）、页面地址（简短稳定能看懂）、图片说明（图挂了仍能知道内容）。**页面承诺要和真实功能对上**（写"免费压缩 JPG"却上传后付费，搜索词和承诺就错位）。AI 生成的站点，直接问它"打开网页源代码时能不能看到核心文字和链接"；如果源码几乎没有正文，让 AI 把公开页面改成 Google 更容易读取的形式。

### 步骤 8 — 页面做好后，让 Google 发现 / 读取 / 收录（技术 SEO 清单）

新手先查：页面公开可访问不需登录；能正常打开不是 404 / 5xx；robots.txt 没禁止读重要页；没加 `noindex`；sitemap 里有想收录的网址；重要页能从正常链接点进去；手机端可操作；打开后源码能看到真实文字和链接。Google 发现新页面的四个入口：**站内链接、外部链接、Sitemap、Search Console**。新页发布后：先从首页 / 相关页给它一条正常链接 → 确认在 sitemap 里 → 打开 Search Console 提交 sitemap 并用"网址检查"看状态。Sitemap 是"我希望 Google 知道的页面清单"，帮助发现但不保证收录（WordPress / Shopify / 常见框架多可自动生成）。收录状态看懂四种：`未发现`（查内链 + sitemap）→ `已发现尚未抓取`（知道网址还没读）→ `已抓取尚未编入索引`（看过暂未收）→ `网页已编入索引`（已进入数据库）。`site:域名` 可粗略看有没有页面；具体页用"网址检查"更准。页面多时不必一张张请求收录，保证内链 + sitemap 正常更重要；反复点请求不会让收录变快。

### 步骤 9 — 内链把页面接起来，外链把入口带进来

内链：首页链核心工具和主分类，教程讲到压缩时链压缩工具，相关工具互推；链接文字直接写清目的（"图片压缩工具"）比全站"点击这里"更易理解。外链：其他网站链到你，既带用户也让 Google 看到引用；查竞品只看两件事——前排页面大概多强、有多少个不同网站链到它。新站从真实入口开始：提交相关产品目录、在社区解决具体问题、做别人愿意引用的免费工具 / 模板、联系相关主题作者体验产品。链接出现的地方和产品有关，点进去的人应得到帮助。

### 步骤 10 — 白帽黑帽，问两个问题就够了

这个页面对用户有没有用？这个链接除了影响排名还有没有正常存在的理由？能解决问题的页面、真实推荐产生的链接、独立可用的小工具更接近白帽；隐藏内容、复制大量空页面、入侵别人网站放链接、专门搭空壳站给主站加链接风险很高。多个网站本身没问题，只要每个都有独立功能 / 内容 / 用户、在合适位置互推；若只复制内容统一给主站加链接，就成了操纵排名的站群。

### 步骤 11 — 上线后做三个基础检查

用 SEO 扩展（如 AITDK SEO 扩展）扫一遍：搜索标题 / 说明、主标题、正式网址、爬虫规则、sitemap、图片说明、链接；分数只是提醒漏项，不代表一定排名。页面速度用 PageSpeed Insights（新站先处理图片太大、首屏慢、按钮无响应、内容跳动）。结构化信息（Schema）是加分项不是新站第一天必做；需要时让 AI 按页面**真实存在**的产品名 / 价格 / 评分生成代码，再用富媒体测试检查，页面没有的信息不要在代码里编造。

### 步骤 12 — 用 Search Console 决定下一步

验证网站 → 提交 sitemap → 查核心页是否收录。看四个数字：**展示**（结果里出现次数）、**点击**（进网站人数）、**点击率**（每百次展示约带来多少点击）、**平均排名**。按症状处理：没被发现→补内链查 sitemap；已发现没收录→查能否打开 / 内容太少重复；已收录没展示→重查需求和意图；有展示排名靠后→补内容 / 内链 / 外链；排名不低点击少→改标题说明；有点击没人用产品→搜索词和页面承接可能不匹配。"网址检查"看单页：是否收录、上次何时来、哪个网址被当作正式版本。

## 反模式

- 网站没被收录就想做 GEO（本末倒置）。
- 把 AI 当关键词音量 / 竞争度的最终裁判（要真实搜索 + 工具核对）。
- 所有词都写成博客，或同一功能换词复制十张页。
- 页面承诺（"免费"）和真实功能（上传后付费）对不上。
- 用 `site:` 代替 Search Console 查单页；反复点"请求收录"想加速。
- 页面没有的信息写进 Schema 代码里编造。

## 与 GEO 的关系

本技能是 **`geo-topic-research` 的上游**：先有被收录、有排名、能回答真实问题的内容，再在其上判断"哪个主题值得做 GEO 选题"、写 GEO 式文章（`geo-content-writing`）、补机器可读资产（`llms-txt-builder`）。地基没通，GEO 无从谈起。
