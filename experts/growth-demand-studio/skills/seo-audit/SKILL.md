# 搜索优化审查

技术 SEO 审查、结构化数据和页面内容优化。

> 交付的是**按处理顺序排好的问题清单**，不是"建议优化 SEO"。

## 适用场景

- 网站搜不到 / 收录少
- 迁移或改版后流量下滑
- 内容投放前，先确认技术面没拖后腿
- 想找出"为什么排名上不去"

## 输入

- 站点地址与可访问范围
- 是否有搜索引擎管理后台权限（有的话数据更准）
- 目标关键词与主要页面
- 技术栈（是否 SPA、是否服务端渲染）

## 执行步骤

### 步骤 1 — 先确认能不能被抓到

按顺序检查：

1. `robots.txt` 是否误挡
2. 页面是否返回正确状态码（不是软 404、不是到处重定向）
3. 主要页面是否可索引（有没有 `noindex`）
4. 是否有 `sitemap.xml`，里面的 URL 是否可达
5. SPA 项目：搜索引擎拿到的是不是空壳 HTML（这是最常见的致命问题）

抓不到，后面全部免谈。

### 步骤 2 — 检查页面级要素

逐页检查：

| 要素 | 要求 |
|---|---|
| `title` | 每页唯一，包含目标词，长度合适 |
| `description` | 每页唯一，说清这页是什么 |
| `h1` | 每页一个，与内容主题一致 |
| 规范化链接 | 重复内容指向规范版本 |
| 图片 | 有描述性替代文本 |

### 步骤 3 — 检查结构化数据

- 需要富结果的页面类型（文章、产品、问答、面包屑）是否加了对应结构化数据
- 格式是否合法（用校验工具验证，不靠肉眼）
- 结构化数据里的内容必须与页面可见内容一致

### 步骤 4 — 检查内链与重复内容

- 重要页面是否至少有一条内链指向（孤岛页面不会被抓）
- 是否存在大量重复或近似页面（参数 URL、分页、标签页）
- 死链数量

### 步骤 5 — 检查体验信号

- 移动端适配：视口设置、点击区域、字号
- 加载性能：首屏渲染时间、阻塞资源、图片体积
- 页面稳定性：布局是否跳动

**这部分只报能实际观测到的现象**，需要真实测量工具的部分明确说明"需实测"。

### 步骤 6 — 排处理顺序

按 **影响范围 × 实施成本** 排序，分三批：

1. **先修**：抓取与索引层面的阻断问题（影响全站）
2. **再修**：页面要素与结构化数据（影响单页）
3. **持续做**：内容质量与内链建设（长期）

## 输出

- 抓取与索引结论（能不能被抓到、能不能被收录）
- 问题清单（按批次排序，每项含影响面、改法、验证方式）
- 结构化数据校验结果
- 需要实测才能确认的项目（明确列出）

## 反模式

- **只做关键词不做技术面**：抓不到，内容再好也没用
- **不区分 SPA 服务端渲染问题**：这是最常被漏掉的致命项
- **title / description 全站一样**：等于放弃了每个页面的独立入口
- **结构化数据靠肉眼检查**：必须过校验工具
- **把需实测的性能问题说成结论**：没有测量就没有数字
- **问题清单不排序**：一百条平铺，等于没人会做

## 参考

- 具体算法与排名因素经常变化，不做"保证排名"的承诺；结论以可观测现象和官方指南为准。
