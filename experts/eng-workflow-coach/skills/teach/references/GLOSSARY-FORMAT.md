# GLOSSARY.md 格式

`GLOSSARY.md` 是这个教学工作区的规范语言（canonical language）。所有讲解、练习和学习记录都应遵守它的术语。构建它本身就是学习的一部分：把一个概念压缩成一个紧凑的定义，是用户理解它的证据。

## 结构

```md
# {主题} 术语表

{一两句话，描述这份术语表覆盖的主题。}

## 术语（Terms）

**Hypertrophy**:
由反复训练带来的机械张力与代谢压力所驱动的肌肉生长。
_避免使用_：Bulking、getting big

**Progressive overload**:
随时间系统地通过负荷、训练量或强度增加对肌肉的要求。
_避免使用_：Pushing harder、levelling up

**RPE (Rate of Perceived Exertion)**:
对一组训练感觉有多吃力所做的 1–10 自评，其中 10 表示力竭，8 表示还剩两次重复的余力。
_避免使用_：Effort score、intensity rating
```

## 规则

- **只有当用户理解了一个术语，才把它加进来。** 术语表是压缩知识的记录，不是给用户用来学习的词典。如果用户刚被介绍到一个概念，等他能够正确使用它之后，再把它提升到这里。
- **要有主见。** 当同一个概念有多个词时，挑出最好的那个，把其余的列为要避免的别名。语言就是这样压缩的。
- **定义要紧凑。** 一到两句话。定义这个术语**是什么**，而不是它做什么或怎么做。
- **在定义里使用术语表自己的术语。** 一个术语一旦进入术语表，就在所有地方优先使用它，包括在别的定义里。这正是让复杂术语日后更容易理解的原因。
- **自然地归入子标题。** 当出现自然的聚类时（例如 `## Anatomy`、`## Programming`）。当术语彼此连贯时，平铺的列表也可以。
- **显式标记歧义。** 如果某个术语在更广的领域里被松散地使用，注明本工作区的解决方式：「在本工作区里，'set' 始终指正式组（working set）；热身另算。」
- **随理解加深而修订。** 用户在第一周写的定义，到第六周可能是错的。就地更新；不要留下过时的条目。
