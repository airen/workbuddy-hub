# 给 agent 写文档（writing-for-agents）

这是一份参考：写任何一份 agent 消费的文档时都用得上——一门技能、一份 `AGENTS.md`（或 `CLAUDE.md`）、一份通过指针够到的文档。包装不同，写法不变：同样的几根杠杆让它们各自变得可预测，因为 agent 每次运行走的是同一个_过程_，而不是产出同样的结果。

当你写的文档是一门技能时，读 [`SKILL-MECHANICS.md`](references/SKILL-MECHANICS.md)，了解 frontmatter、调用方式的选择和路由技能。

## 上下文指针（Context pointers）

一个**上下文指针（context pointer）**是 agent 上下文里持有的一条引用，它点出某份不在上下文里的材料，并编码了够到它的条件。技能的 description 就是一个；`AGENTS.md` 里点名一份文档的一行是同一个东西。决定 agent 何时、以及多可靠地够到那份材料的，是指针的_措辞_，而不是它的目标。一个必须够到的目标藏在一句措辞软弱的指针后面，就是一个方差 bug（variance bug）：先把措辞磨锋利，只有磨不动时才把材料内联进来。

一条指针干两件事：说明那份材料是什么，并列出应当触发够到它的**分支（branches）**（一个分支就是文档处理的一个不同情形，于是不同的运行会走出不同的路径）。一条常驻加载的指针，它的每一个字都在每一轮上产生成本，所以它比正文更值得狠狠地修剪：

- **把引导词（leading word）放在最前面**：指针正是它做触发工作的地方。
- **每个分支一个触发词。** 给同一个分支改名的近义词，是同一个分支写了两遍；把它们合并掉，只留下真正不同的分支。
- **砍掉正文已经承载的身份信息。**

## 两种负载（The two loads）

你添加的每一份文档和指针，都在花掉两种预算之一：

- **上下文负载（context load）**是常驻加载的材料在 agent 窗口上的成本：一行 `AGENTS.md`、一段技能 description、任何每一轮都坐在上下文里的东西——不管它触发与否，都在花 token 和注意力。
- **认知负载（cognitive load）**是人这一侧的成本：有哪些文档存在、什么时候该够哪一份。人就是索引。这不是一个要最小化的成本：它是人的能动性的代价；在人判断力要紧的地方花它，不要紧的地方去掉它。

只通过一条指针够到的材料，以指针自己那一行为代价，逃掉了上下文负载；完全没有指针的材料，则整个骑在认知负载上。

## 信息层级（Information hierarchy）

一份文档由两类内容搭成：**步骤（steps）**（agent 按顺序执行的动作）和**参考（reference）**（按需查阅的定义、规则、事实）。两者自由混合：全是步骤（一份菜谱）、全是参考（一次评审的规则、本技能），或者两者都有。核心决定是每一块东西坐在**信息层级（information hierarchy）**的哪一级——这是一把梯子，按 agent 对这份材料的需求有多即时来排序：

1. **文件内步骤（In-file step）**是主层：agent 按顺序做什么。
2. **文件内参考（In-file reference）**按需查阅。它往往是一个合法地扁平的同级集合（一次评审的每条规则都在同一级），这是一种好安排，不是坏味道。
3. **被披露的参考（Disclosed reference）**被推到单独一个文件里，通过一条上下文指针够到，只在指针触发时加载。范围从同目录下的一个兄弟文件，一直到完全外部的参考——它住在任何地方，任何文档都能指向它。

往下推得太少，顶上就臃肿；推得太多，你就藏起了 agent 真正需要的材料。这股张力就是整个决定的全部。

**渐进式披露（Progressive disclosure）**就是往下走一级（离开主文件、藏到一条指针后面），好让顶部保持清晰可读。它主要不是一次 token 优化：它是信息层级被保护的方式。分支是最干净的披露测试：每个分支都需要的就内联，只有部分分支够得到的就推到指针后面。当一份文档有步骤时，本该被披露出去的文件内参考会把它们埋掉，把「留意它们」变成抛硬币：这是一根方差杠杆，不只是可读性的问题。

**就近放置（Co-location）**是文件内部的搭档：梯子决定一块东西坐得_多靠下_，就近放置则决定它到了那里之后_旁边坐着什么_。把一个概念的定义、规则和注意事项收在同一个标题下，而不是散落各处，这样读其中一部分就会把它的邻居一起带出来。测试：这份文档读起来应当像为 agent 写的文档。成组放置的材料读起来就是那样；散落的材料不是。（这不同于重复：重复是把一个意思在两处讲；散落是把一个意思碎成很多处。）

**蔓延（Sprawl）**是这里的失效模式：一份文档就是太长了，哪怕每一行都是活的、独一无二的。注意力在冗余里被稀释，而每一行多余的都是又一个要保持相关的负担。解药就是那把梯子：把参考披露到指针后面，并按分支或序列拆分，让每条路径只背负它需要的东西。

## 步骤与完成判据（Steps and completion criteria）

每一步都以一条**完成判据（completion criterion）**收尾，它告诉 agent 活儿干完了。两个性质让它成为一根杠杆：

- **清晰度（Clarity）**：agent 能不能分辨「干完了」和「没干完」？一个模糊的边界（「达成理解」）会招来**提前完成（premature completion）**：在真正干完之前就结束这一步，注意力滑向_「已经干完了」_。前面还看得见的步骤（**完成后步骤（post-completion steps）**）提供拉力；判据的清晰度是阻力。按顺序防御：**先把边界磨锋利**（局部且便宜）；只有当它不可再简化地模糊_且_你观察到了那种赶工，才通过拆分序列把后面的步骤藏起来。藏起来只在跨过一个真实上下文边界时才有效（一次交接或一次子代理派发；一次内联调用会把后面的步骤留在上下文里，什么也没清掉）。
- **要求（Demand）**：它要求多少。「每一个被修改的 model 都有着落」逼出扎实的工作，而「产出一份变更清单」不会。要求驱动**暗中用力（legwork）**（agent 在工作之内做的挖掘，它潜伏在措辞里，而不是被写成单独的一步），而且它不绑定于步骤：「每条规则都应用」约束的是一整块扁平参考，就像「每一步都完成」约束的是一个序列——这就是一份全参考的文档如何仍然带着一条穷尽性的标准。

最强的判据既可核对、又穷尽。

## 什么时候拆分（When to split）

把一份文档拆成两份，会花掉两种负载之一，所以只有当这道切口值回票价时才拆：

- **按序列**：当完成后步骤会诱使 agent 赶工它面前那一步时，把这一段步骤拆开。让它们不在视野里，会在当前任务上逼出更多暗中用力。当心反过来：把序列合并起来，会把每一步的后续步骤暴露给后面，招来提前完成。
- **按调用方式**，技能专属：见 [`SKILL-MECHANICS.md`](references/SKILL-MECHANICS.md)。

## 引导词（Leading words）

一个**引导词（leading word）**是一个已经活在模型预训练里的紧凑概念，agent 在跑这份文档时用它来思考（_lesson_、_fog of war_、_tracer bullets_）。它以一个 token 的形式重复，从不以句子的形式，于是累积出一份分布式的定义，用最少的 token 锚住一整片行为，靠的是招募模型本来就持有的先验。自造一个词也行，只要你把它定义清楚，但自造的词招募不到先验：一个预训练词免费给你的东西，你得用定义它的 token 去付账；先够向一个已有的词。

它锚两次。在正文里锚_执行_：每当这个词出现，agent 都会伸手去够同一套行为；在扁平参考里，它把注意力聚焦到一类要找的东西上。在指针里锚_调用_：当同一个词活在你的 prompt、你的文档和你的代码库里，agent 会把这份共享语言和那份材料挂上钩，更可靠地够到它。

去找用引导词重构的机会。一个在三处被完整拼出来的三元组，一条花一整句话去指一个想法的指针。每一处都是一段求着要塌缩成一个 token 的文字：

- 「快、确定性、低开销」→ _tight_（一个 _tight_ 循环）。
- 「一个你信得过的循环」→ _red_，把一个模糊的闸门变成一个二元的可观察状态（循环在 bug 上变_红_，或者不变）。

你赢两次：更少的 token，以及一个更锋利的钩子让 agent 把思考挂上去。假设每份文档都背着一些能被引导词退役掉的复述。去找出来。

**否定（Negation）**是这根杠杆旁边的失效模式：靠禁止来操舵，会把被禁止的行为拖进上下文，让它变得_更_容易浮现，而不是更少。_别去想一头大象_，于是满脑子只有那头大象；否定是一个软弱的修饰语，被强激活的概念一冲就垮，于是这条禁令有一半读起来像是在指示你去做那件事。要用**正面**来提示：说出目标行为（「写单行注释」），好让被禁的那个从不被说出口。一条禁令只有在它是你无法用正面措辞表达的硬护栏时才配得上它的位置；即便如此，也要把它和正面目标配成一对，好让注意力落在该做什么上。

## 修剪（Pruning）

- 把每个意思收进一个**单一真相来源（single source of truth）**：一个权威的地方，于是改行为就是改一个地方。**重复（Duplication）**（同一个意思出现在不止一处）花掉维护成本和 token，并把一个意思在梯子上的显著度吹高到超出它真实的等级。（它是引导词的意外反面——引导词是故意重复一个 token，从不重复那个意思。）
- **环境（environment）**也是一个真相来源（`package.json` 的 scripts、配置文件、目录布局、`--help` 输出），而一份复述它的文档是一个**缓存（cache）**：一次查询的副本，只有当这次查询昂贵时才值回它的负载。缓存那些 agent 靠看找不到的东西：没写下来的约定、一个选择背后的理由、没有哪个配置会坦白承认的坑。把「一个文件、一条命令」就能查到的留给环境，在那里它们不会过期。
- 对每一行检查**相关性（relevance）**：它还跟这份文档所做的事有关吗？一行丢掉相关性，要么是因为它从不跟任务相关（纯属说明，或者一个本该被披露出去的分支），要么是因为它描述的行为或世界变了、它过期了。更短的文档更容易保持相关。没有一套修剪纪律，默认的宿命就是**沉积（sediment）**：过期的层层沉淀下来，因为「加」感觉安全、「删」感觉冒险，直到你不得不一路往下钻，才找得到还活着的东西。
- 逐句猎杀**空操作（no-ops）**：一条模型默认就已经遵守的指令，是在花负载说一句什么也没说的话。这个测试（它相对于默认会不会改变行为？）是相对于模型而言的，不是相对于读者而言的：两个人为一个空操作争执，其实是在为默认争执，解决它的方式是跑一遍这份文档，而不是辩论。当一句话没通过，就删掉整句，而不是从里面抠字。这个测试也给引导词打分：一个弱到打不过默认的词（agent 本来就挺周到了，还说 _be thorough_）就是空操作，解药是换一个更强的词（_relentless_），而不是换一种技巧。
