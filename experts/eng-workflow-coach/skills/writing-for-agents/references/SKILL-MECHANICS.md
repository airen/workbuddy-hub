# 技能机制（Skill mechanics）

这是 [`writing-for-agents`](../SKILL.md) 的技能专属分支：当要写的文档是一门技能时，有哪些变化（frontmatter、调用方式的选择，以及路由技能）。关于怎么写它的其余一切，都在 `SKILL.md` 里那份通用参考中。

## 调用方式（Invocation）

两个选择，用两种负载来交换：

- 一门**模型调用（model-invoked）**的技能保留 `description`，于是 agent 能自主触发它，其他技能也能够到它。你仍然可以敲它的名字：模型调用始终_包含_用户的触达；description 只会在 agent 的发现能力上做加法，从不会拿走人的那份。description 是技能最顶层的上下文指针，被迫时刻保持加载：以永久的上下文负载，换取可发现性。一门内容全是参考的模型调用技能，也是共享参考的一个归宿：另一个技能可以调用它，于是多个技能都需要的参考只住在一个地方。**机制**：模型能不能自己够到一门技能，全看 `description`（它是唯一常驻加载、始终对模型可见的字段）。所以要做的就是把它写好：面向模型，带上触发分支（`SKILL.md` 里的指针写法规则完全适用）。
- 一门**用户调用（user-invoked）**的技能，把 description 从 agent 的触达范围里剥掉：只有人敲它的名字才能调用它，其他技能都不能。零自主触达，但它花掉认知负载：你就是那个必须记得它存在的索引。**机制**：在 frontmatter 里写 `disable-model-invocation: true` 即可 —— 官方上架文档明确列出该字段，置 true 则 AI 不会自动触发、只能由用户手动调用（WorkBuddy 的多个内置技能都在用）。`description` 仍然常驻加载，所以上下文负载照付，但触达权收归人。

只有当 agent 必须自己够到这门技能、或另一门技能必须够到它时，才选模型调用。如果它永远只靠手敲触发，就做成用户调用（加 `disable-model-invocation: true`），把触达权收归人。

两门用户调用的技能都需要的共享参考，可以两者都不放在技能里：它们谁也触发不了谁。把它做成一份普通文件（或一门模型调用的参考技能），让两边都能指向它。

## 按调用方式拆分（Splitting by invocation）

拆分里的「调用方式」这道切口（「序列」那道切口在 `SKILL.md` 里）：当你有一个独立的引导词、它应当自己触发一门技能时（一个你在 prompt 里真的会用的触发词），或者另一门技能必须够到它时，就拆出一门模型调用的技能。你为这段新的、常驻加载的 description 付上下文负载，所以那份独立的触达必须值回票价。

## 路由技能（Router skills）

当用户调用的技能多到超出你能记住的范围时，那份堆积起来的认知负载由一门**路由技能（router skill）**来治：一门用户调用的技能，它点名其他技能以及各自何时该够到，于是人只需要记住一门技能，而不是很多门。它只能提示，永远不能触发它们：用户调用的技能带 `disable-model-invocation: true`，除了人，谁都触发不了它们。
