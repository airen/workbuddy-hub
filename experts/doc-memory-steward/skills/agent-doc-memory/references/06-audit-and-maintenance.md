# 06 · 审计与维护

> 文档工作区最大的风险不是"写不出来"，是**写完没人维护，慢慢变成一堆过期的东西**。这一篇讲怎么防。

**因为全是 Markdown，所以它天然可审计。** 这是召回式记忆做不到的——你没法 grep 一个向量库。

## 什么时候审计

| 信号 | 该查什么 |
|---|---|
| 「文档越来越乱，没人看」 | 孤儿文档 + 断链 |
| 隔了很久回来接手（或新人接手） | 过期文档 + 索引是否可信 |
| 文档和代码打架 | 冲突 |
| 感觉"写了很多但没用" | 从没被引用的文档 |
| 每次收尾（轻量） | 索引是否同步 |

---

## 一键审计

```bash
python3 scripts/doc_audit.py <项目根目录>
python3 scripts/doc_audit.py <项目根目录> --stale-days 60     # 自定义过期阈值（默认 90 天）
python3 scripts/doc_audit.py <项目根目录> --fail-on-issue     # 有问题时以非零码退出（可进 CI）
```

脚本报告三类问题：

| 类别 | 定义 | 处理 |
|---|---|---|
| **断链** | `INDEX.md` 里指向了不存在的文件 | 立即修（改路径或删行） |
| **孤儿文档** | 项目里的 `.md` 不在 `INDEX.md` 里 | 要么登记进索引，要么删掉 |
| **过期** | 超过阈值天数没更新 | 复核：改对、标 `过期`、或标 `已废弃` |

> 孤儿文档是**最危险**的一类：它写了，但没人知道它存在，所以它**永远等于没写**——而且如果它内容过期，它就是一个埋着的雷。**"写了不同步索引"是文档工作区最常见的死法。**

---

## 四类问题与处理

### 1. 孤儿文档

**成因**：新建文档时忘了回 `INDEX.md` 加一行；或者搬文件后没更新索引。

**处理**：

- 内容有价值 → 登记进索引（补一句话说明 + 状态 + 日期）
- 内容是临时产物 / 已被取代 → 删除或标 `已废弃`
- **不要**让它就那么躺着

### 2. 断链

**成因**：文件改名 / 移动 / 删除后没更新索引或交叉引用。

**处理**：立即修。断链会让 agent 读到"文档不存在"，然后误判成"这个项目没有这方面的知识"——比没有索引更糟，因为它给出的是**错误的负面结论**。

### 3. 过期文档

**判据不只是时间**，还要看**领域变动频率**：

| 领域 | 敏感度 | 建议复核周期 |
|---|---|---|
| 依赖版本、API 用法、外部服务 | 高 | 30–60 天 |
| 架构决策、数据模型 | 中 | 90 天 |
| 术语表、团队约定 | 低 | 半年 |

**处理**（三选一，必须选一个）：

- 内容仍成立 → 更新 `最后更新` 日期（复核本身也是动作）
- 内容部分失效 → **就地改对**
- 内容完全失效 → 状态改 `已废弃`，写明被谁取代

> **不允许"什么都不做"。** 一份标着"现行"但其实已经过期的文档，是项目里最危险的东西。

### 4. 冲突

**三种冲突**：

| 冲突类型 | 表现 | 处理 |
|---|---|---|
| 文档 vs 代码 | 文档说 A，代码做 B | **以代码为准**，改文档 |
| 文档 vs 文档 | 两份决策互相矛盾 | 找出更晚的 / 更权威的，把另一份标 `已废弃` |
| 索引 vs 实际 | 索引说的和文件实际不符 | 修索引 |

**原则**：**现实永远是真相的来源。** 文档是现实的记录，不是现实的立法者。当两者冲突，改文档（除非现实本身是错的——那要先修现实）。

## 定期维护动作

### 每次任务收尾（轻量，30 秒）

- 新建 / 删文档了吗？→ 同步 `INDEX.md`

### 每个里程碑（中量）

- 跑一次 `doc_audit.py`
- 把本次里程碑涉及的决策 / 规格复核一遍状态

### 每季度 / 接手时（重量）

- 全量跑 `doc_audit.py --stale-days 90`
- 逐条处理过期文档（改 / 标废 / 删）
- 检查 `conventions.md` 是否还符合现状
- 检查 `glossary.md` 有没有漏掉新出现的黑话

## 审计报告长什么样

脚本输出示例：

```text
文档工作区审计 — /path/to/project
索引: docs/INDEX.md ｜ 收录 7 篇 ｜ 实际 9 篇 ｜ 阈值: 90 天

[断链] 1 处
  docs/INDEX.md:23  →  decisions/0004-cache.md（文件不存在）

[孤儿] 2 篇
  docs/research/redis-cluster.md       (未被索引收录, 更新于 2026-07-02)
  docs/specs/legacy-import.md          (未被索引收录, 更新于 2026-05-11)

[过期] 3 篇
  docs/decisions/0001-postgres.md      128 天未更新
  docs/research/stripe-webhook.md      96 天未更新
  docs/conventions.md                  104 天未更新

汇总: 断链 1 ｜ 孤儿 2 ｜ 过期 3
```

## 反模式

- ❌ 只在"想起来"的时候审计 → 设成里程碑动作
- ❌ 发现过期文档"先记下来以后处理" → 以后永远不会处理，且它会继续被当成真相
- ❌ 为了消灭孤儿文档而**删掉有内容价值的文档** → 应该登记进索引
- ❌ 让审计变成形式主义（跑完不看） → 每次至少处理掉断链与过期
- ❌ 用"文档太多了"当借口不维护 → 说明该删了，而不是该放弃维护
