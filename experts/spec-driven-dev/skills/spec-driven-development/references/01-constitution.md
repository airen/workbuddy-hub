# 01 · constitution（项目章程）

**命令**：`constitution`　**频率**：每项目**一次**（原则变了才更新）　**产物**：`.specify/memory/constitution.md`

## 它是什么

章程是**治理「规格如何变成代码」的原则集** —— 相当于项目的架构 DNA。后面每一个阶段（plan 的 Constitution Check、analyze 的合规扫描）都要拿它当尺子。

**核心特性**：原则不可变，应用可演化。修订必须走「文档化理由 → 维护者评审 → 向后兼容性评估」，并在文件头部的 Sync Impact Report 里带日期记录。

## 什么时候做

- 项目刚起步，还没有任何工程约定 → **建立**
- 已有约定散落在 README / CONTRIBUTING / 口头共识里 → **提炼成章程**
- 团队发现反复出现同类返工（测试缺失、抽象层过厚、依赖失控）→ **加一条原则**

## 执行步骤

1. **先读现有约定**。如果项目已有 `README.md`、`CONTRIBUTING.md`、`AGENTS.md`、CI 配置、lint 规则，**从中提炼**而不是凭空发明 —— 章程应该是"代码库已经在执行的模式的成文化"。
2. **问用户三件事**（缺一不可）：
   - 这个项目最不能妥协的工程原则是什么？（测试？模块化？性能？离线可用？）
   - 有没有必须遵守的外部约束？（合规、平台、部署环境、依赖政策）
   - 违反原则时，允许走例外吗？例外要走什么流程？
3. **写成条款**。条款用 **MUST / MUST NOT** 的祈使语气，每条带 **Rationale**（为什么这条原则存在）。
4. **定版本号**（治理语义化版本）：
   - **MAJOR**：向后不兼容的治理变更，或原则被删除/重定义
   - **MINOR**：新增原则/章节，或实质性扩充指导
   - **PATCH**：澄清与非语义性打磨
5. **同步模板**。章程变了，依赖它的模板（plan 的 Constitution Check 段）要一起改 —— 并在 Sync Impact Report 里记录"哪些模板已核对"。
6. **写 Sync Impact Report**（文件顶部的 HTML 注释块）：版本变化、变更理由、定义了哪些原则、核对了哪些模板、遗留 TODO。

## 条款从哪来

如果用户没有特别要求，用下面的**起手式原则**（经典 Spec Kit 九条款的现代化版本）：

| # | 条款 | 一句话 |
|---|---|---|
| I | **代码质量与架构纪律** | 分层清晰、职责分离、命名与类型不是可选项 |
| II | **测试背书变更（不可协商）** | 任何行为变更都必须带自动化测试，测试套件是硬关卡 |
| III | **接口与体验一致性** | 对外接口保持一套统一语汇与输出格式 |
| IV | **性能与资源纪律** | 明确启动成本、响应时间、离线/降级行为 |
| V | **最小依赖与安全的幂等文件操作** | 新增运行时依赖需论证；所有路径校验、操作幂等 |
| VI | **简洁优先（Simplicity）** | 初始实现项目数 ≤3，额外项目需在「复杂度追踪」里论证 |
| VII | **反抽象（Anti-Abstraction）** | 直接用框架特性，不要为了"未来可能换"而包一层 |
| VIII | **测试优先（Test-First）** | 先写测试、经用户确认、确认失败（红），再实现 |
| IX | **集成优先测试** | 优先真实依赖而非 mock，实现前先写契约测试 |

> 条款 IV–VI 属于「项目自定义治理」区 —— 上游 Spec Kit 不规定具体内容，由各项目自己填。别把别人的条款照抄进来。

## 关卡怎么运作

`plan` 阶段的 `## Constitution Check` 段落是**关卡**（GATE）：必须在 Phase 0 研究之前通过，Phase 1 设计之后**再检查一次**。

- 通过 → 继续。
- 违反 → **不是禁止**，而是必须写进 `plan.md` 的 `## Complexity Tracking` 表：

| Violation | Why Needed | Simpler Alternative Rejected Because |
|---|---|---|
| 第 4 个项目 | 当前需要 | 为什么 3 个项目不够 |

**没有进入复杂度追踪的违规 = 阻断合并的违规。** 这就是问责机制。

## 输出规范

- 文件路径：`.specify/memory/constitution.md`
- 模板：`templates/constitution-template.md`
- 语气：祈使句 + MUST。不要写成"我们建议…"。
- 每条原则必须能回答：**"违反了会怎样？"** 答不出来的原则是装饰品，删掉。
- 收尾时告诉用户：章程版本号、有几条原则、下一次什么时候需要更新它。
