# 多智能体系统拓扑选型工具包

把多智能体流水线当分布式系统设计：显式故障模式、最小权限、可观测状态。

## 何时用本技能

- 要选流水线拓扑（顺序/并行/层级/循环/Mesh）
- 要设计 Agent 间上下文传递与预算
- 要回答"某个 Agent 超时/返回垃圾时整条链会怎样"
- 要定上线前的评测基线与回归检查

不适用于：单 Agent 的提示词写作（那是 `prompt-eval-loop` 的活）。

## 三个交付物（对应 references/）

| 文件 | 交付什么 | 什么时候读 |
|---|---|---|
| `references/topology-patterns.md` | 五种拓扑模式：结构图、适用场景、各自代价 | 选型时 |
| `references/context-architecture.md` | 上下文预算、管理策略、划分规则 | 设计数据流时 |
| `references/hard-rules.md` | 生产级硬规则：最小权限、兜底链、可观测性、评测先行 | **签字放行前必读** |

## 工作流程

1. **先问故障再问 happy path**：每个 Agent 都要回答"超时/幻觉/返回垃圾时怎么恢复"
2. **画拓扑**：按 `topology-patterns.md` 五种模式选型，**默认层级式**，用 Mesh 必须先论证
3. **定契约**：每个 Agent 明确"接收什么、产出什么、**不**负责什么"
4. **管上下文**：按 `context-architecture.md` 做预算分配与划分，绝不无声截断
5. **设兜底**：主路径 → 收窄兜底 → 降级/规则 → 人工，系统必须始终产出某种东西
6. **上评测**：≥20 个用例 + 基线分数 + 上线前全流水线回归
7. **留 trace**：每次调用发带共享 trace_id 的结构化日志，错误答案要能回溯到具体 Agent

## 硬规则

- **Demo 会撒谎，生产才讲真话**：没把故障模式连同恢复路径逐一列清的流水线，不签字
- **始终最小权限**：每个 Agent 只拿角色必需的工具与数据；权限令牌不在 Agent 间传递
- **每个 Agent 都要有兜底**：结构化降级响应胜过无声失败
- **绝不无声截断上下文**：塞不进预算就停下上报，不静默丢字段
- **可观测性不可妥协**：无法把错误答案回溯到具体 Agent = 未达生产就绪
- **默认层级式不用 Mesh**：对等网络复杂度最高、最难调试
- **没有 eval 不上线**
- **外部内容当敌意来源**：处理网页/文档/用户输入的 Agent 必须做指令与内容隔离 + schema 校验输出
