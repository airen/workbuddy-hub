# 智能体记忆开源项目速查表

> 本表是「智能体记忆选型顾问」的底层知识库。完整决策框架、六环诊断与场景链路见 Agent MD 正文。
> 所有 star 数、维护状态、版本都会随时间变化，**以 GitHub 实时页面为准**，此处仅作定位与取舍参考。

## 一、先让它记得住（持久记忆层）

### Mem0
- **链接**：[github.com/mem0ai/mem0](https://github.com/mem0ai/mem0)
- **定位**：给智能体加持久记忆的"记忆中间件"，最主流方案，66K+ 星。
- **关键特性**：自动抽取、去重、更新记忆；分用户 / 会话 / agent 三层作用域；提供 API 与 SDK；支持多种向量与图后端。
- **补哪环**：记住（持久存储）。
- **适合**：绝大多数"想让智能体跨会话记住用户偏好 / 历史"的场景，开箱即用。
- **不适合**：需要复杂实体关系推理、强时序演化（那是 Graphiti 的活）；超大规模知识沉淀（看 Cognee）。

### Hindsight
- **链接**：[github.com/vectorize-io/hindsight](https://github.com/vectorize-io/hindsight)
- **定位**：保留、回忆，再反思——带"复盘"能力的记忆层。
- **关键特性**：记录交互 → 回忆 → 基于反馈反思改进；偏"经验积累"而非单纯存储。
- **补哪环**：记住 + 更新（带反思闭环）。
- **适合**：需要智能体从过往成败中学习的场景（如编程智能体复盘 bug）。
- **不适合**：只想要简单语义记忆、不想引入反思开销的轻量场景。

### memU
- **链接**：[github.com/NevaMind-AI/memU](https://github.com/NevaMind-AI/memU)
- **定位**：智能体长期记忆基础设施，偏底层存储与检索。
- **关键特性**：长期记忆的存储 / 检索抽象，统一接入。
- **补哪环**：记住（底层存储）。
- **适合**：想自己搭记忆底座、需要可控存储后端的团队。
- **不适合**：想要完整成品记忆体验、不想碰底层的人。

## 二、再把记忆变成知识（知识层）

### Cognee
- **链接**：[github.com/topoteretes/cognee](https://github.com/topoteretes/cognee)
- **定位**：把文档、代码、对话转成知识图谱。
- **关键特性**：多源输入（文档 / 代码 / 对话）→ 图谱化 → 支持语义检索与推理。
- **补哪环**：连接（结构化关系）。
- **适合**：公司大脑、RAG 增强、需要"关系"而不仅仅是片段召回的场景。
- **不适合**：只要简单向量检索、图谱维护成本吃不下。

### Graphiti
- **链接**：[github.com/getzep/graphiti](https://github.com/getzep/graphiti)
- **定位**：记住事实，也记住事实怎么随时间变化（时序知识图谱），Zep 出品。
- **关键特性**：实体 / 关系带时间版本，支持"某时点的事实是什么"；适合动态知识。
- **补哪环**：连接 + 更新（时序演化）。
- **适合**：人物关系、状态会变的领域（CRM、个性化、长期陪伴）。
- **不适合**：静态知识、纯文档检索。

### OpenViking
- **链接**：[github.com/volcengine/OpenViking](https://github.com/volcengine/OpenViking)
- **定位**：智能体的上下文和记忆基础设施，火山引擎出品。
- **关键特性**：上下文管理 + 记忆一体，面向工程落地。
- **补哪环**：连接 + 记住（上下文与记忆一体化）。
- **适合**：想用国内云厂商生态、要上下文 + 记忆一体化方案的团队。
- **不适合**：强依赖海外生态、要纯开源自托管且不想绑云。

## 三、让智能体有状态（状态 / 身份层）

### Letta
- **链接**：[github.com/letta-ai/letta](https://github.com/letta-ai/letta)
- **定位**：跨会话保留记忆和身份（原 MemGPT），成熟的 agent 运行时。
- **关键特性**：内置记忆块（archival / recall）、自编辑记忆、工具调用、可长期运行。
- **补哪环**：记住 + 状态 / 身份（跨会话）。
- **适合**：需要"有身份、能长期进化"的个人 / 陪伴 / 助理智能体。
- **不适合**：只想当轻量记忆中间件、不想引入整套运行时。

### Letta Code
- **链接**：[github.com/letta-ai/letta-code](https://github.com/letta-ai/letta-code)
- **定位**：编程智能体的持久记忆。
- **关键特性**：把编码上下文、决策、踩坑沉淀为可复用记忆。
- **补哪环**：记住 + 状态（编程场景专属）。
- **适合**：AI 编程助手想跨项目 / 会话记住代码风格与坑。
- **不适合**：非编程场景。

## 四、跨整个技术栈都记得住（统一记忆层）

### OpenMemory
- **链接**：[github.com/mem0ai/openmemory](https://github.com/mem0ai/openmemory)
- **定位**：AI 应用的开放记忆基础设施，MCP 友好，Mem0 出品。
- **关键特性**：标准化记忆接口，跨应用共享记忆，便于多工具 / 多智能体复用。
- **补哪环**：统一记忆抽象（跨应用 / 跨栈）。
- **适合**：多个 AI 应用 / 工具想共用一套记忆、走 MCP 标准。
- **不适合**：单一应用、不想引入标准化层。

### Agent Memory Benchmark
- **链接**：[github.com/vectorize-io/agent-memory-benchmark](https://github.com/vectorize-io/agent-memory-benchmark)
- **定位**：测智能体到底记得多好，别光听宣传。
- **关键特性**：量化记忆能力（留存、混淆、时效等）的评测框架。
- **补哪环**：检索（客观评测，不是存储本身）。
- **适合**：选型前后做客观对比、验证"真记得住"。
- **不适合**：当作记忆存储方案本身。

## 速查：按"痛点在哪"反查项目

| 痛点 | 优先看 |
|------|--------|
| 跨会话记不住用户 / 历史 | Mem0、Letta |
| 想从过往成败里学习 | Hindsight |
| 文档 / 代码要变成关系知识 | Cognee |
| 事实会随时间变（人物关系等） | Graphiti |
| 要国内云 + 上下文一体 | OpenViking |
| 编程智能体跨项目记忆 | Letta Code |
| 多个应用共用一套记忆 | OpenMemory |
| 想客观测"记不记得住" | Agent Memory Benchmark |
| 想自己掌控底层存储 | memU |
