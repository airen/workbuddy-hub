# 质量属性场景工作表

> **把"高可用/高性能/可扩展"这类形容词，变成可度量、可验证、可设计的场景。**
> 原理见 `references/01-foundations-and-role.md`、`references/decision-frameworks.md`。

## 1. 六要素模板

| 要素 | 问题 | 填写 |
|------|------|------|
| **刺激源 Source** | 谁/什么触发？ | |
| **刺激 Stimulus** | 发生了什么？ | |
| **制品 Artifact** | 作用于什么？ | |
| **环境 Environment** | 什么条件下？ | |
| **响应 Response** | 系统应如何反应？ | |
| **响应度量 Measure** | 怎么判断成功？ | |

## 2. 场景卡（每个场景一张）

```markdown
### QAS-XXX：<场景简称>

- **质量属性**：性能 / 可用性 / 可修改性 / 安全性 / 可伸缩性 / 可测试性 / 可部署性
- **业务价值**：高 / 中 / 低
- **技术风险**：高 / 中 / 低
- **优先级**：(业务价值, 技术风险) = (H, H)

| 要素 | 内容 |
|------|------|
| 刺激源 | |
| 刺激 | |
| 制品 | |
| 环境 | |
| 响应 | |
| 响应度量 | |

- **关联驱动因素**：D1
- **当前满足情况**：满足 / 部分满足 / 不满足
- **验证方式**：压测 / 监控 / 审计 / 代码检查
- **架构方法**：<用什么架构手段满足它>
```

## 3. 各质量属性的场景写法示例

### 3.1 性能

| 要素 | 内容 |
|------|------|
| 刺激源 | 外部用户 |
| 刺激 | 发起下单请求 |
| 制品 | 订单服务 |
| 环境 | 促销峰值（10 倍日常流量） |
| 响应 | 正常创建订单并返回订单号 |
| 响应度量 | P99 延迟 < 2s，成功率 ≥ 99.9% |

> ⚠️ **必须用分位数，不用平均值。** 平均值会掩盖长尾。

### 3.2 可用性

| 要素 | 内容 |
|------|------|
| 刺激源 | 基础设施 |
| 刺激 | 单个可用区故障 |
| 制品 | 整个系统 |
| 环境 | 正常运行中 |
| 响应 | 流量自动切换到另一可用区 |
| 响应度量 | 30 秒内恢复服务，RPO = 0，RTO ≤ 30s |

### 3.3 可修改性

| 要素 | 内容 |
|------|------|
| 刺激源 | 产品经理 |
| 刺激 | 新增一种支付方式（如数字人民币） |
| 制品 | 支付模块 |
| 环境 | 开发期 |
| 响应 | 实现并上线 |
| 响应度量 | 改动 ≤ 2 人天，不影响其他支付方式，无跨服务改动 |

### 3.4 可伸缩性

| 要素 | 内容 |
|------|------|
| 刺激源 | 市场活动 |
| 刺激 | 流量增长 10 倍 |
| 制品 | 商品查询服务 |
| 环境 | 活动期间 |
| 响应 | 自动扩容，性能保持 |
| 响应度量 | 资源增加 ≤ 10 倍，P99 延迟增幅 ≤ 20% |

### 3.5 安全性

| 要素 | 内容 |
|------|------|
| 刺激源 | 攻击者 |
| 刺激 | 尝试越权访问他人订单 |
| 制品 | 订单 API |
| 环境 | 正常运行 |
| 响应 | 拒绝访问并记录审计日志 |
| 响应度量 | 100% 拒绝，告警在 1 分钟内触发 |

### 3.6 可测试性

| 要素 | 内容 |
|------|------|
| 刺激源 | 开发者 |
| 刺激 | 提交一个领域逻辑变更 |
| 制品 | 订单领域模块 |
| 环境 | 本地开发 |
| 响应 | 运行单元测试验证 |
| 响应度量 | 测试执行 < 10s，无需启动数据库/外部依赖 |

### 3.7 可部署性

| 要素 | 内容 |
|------|------|
| 刺激源 | 开发者 |
| 刺激 | 发布订单服务新版本 |
| 制品 | 订单服务 |
| 环境 | 生产 |
| 响应 | 灰度发布，异常自动回滚 |
| 响应度量 | 部署 < 10 分钟，回滚 < 2 分钟，不影响其他服务 |

## 4. 效用树（Utility Tree）

把场景按 `(业务价值, 技术风险)` 组织成树，用于排序与评审。

```
效用 Utility
├── 性能 Performance
│   ├── (H,H) 促销峰值下单 P99 < 2s          ← 最先分析
│   ├── (M,L) 报表查询 < 5s
│   └── (L,L) 后台管理页 < 3s
├── 可用性 Availability
│   ├── (H,H) 单可用区故障 30s 内切换
│   └── (M,M) 支付渠道故障时降级
├── 可修改性 Modifiability
│   ├── (M,M) 新增支付方式 ≤ 2 人天
│   └── (L,M) 新增报表 ≤ 3 人天
├── 安全性 Security
│   ├── (H,M) 敏感数据全程加密
│   └── (H,L) 越权访问 100% 拒绝
└── 可伸缩性 Scalability
    └── (M,H) 流量 10 倍自动扩容
```

**优先级判定**：

| (业务价值, 技术风险) | 处理方式 |
|---------------------|---------|
| (H, H) | **最高优先级**：架构必须专门设计，重点验证 |
| (H, L) | 高优先级：通常容易满足，但要验证 |
| (L, H) | 中优先级：风险高但价值低，考虑规避 |
| (L, L) | 低优先级：可以忽略或后期处理 |

## 5. 场景汇总表

| # | 质量属性 | 场景 | 响应度量 | 优先级 | 当前状态 | 架构方法 |
|---|---------|------|---------|--------|---------|---------|
| QAS-1 | 性能 | 促销峰值下单 | P99 < 2s，成功率 ≥ 99.9% | (H,H) | 部分满足 | 读写分离 + 缓存 + 削峰 |
| QAS-2 | 可用性 | 单可用区故障 | 30s 切换，RPO=0 | (H,H) | 不满足 | 多可用区 + 同步复制 |
| QAS-3 | 可修改性 | 新增支付方式 | ≤ 2 人天 | (M,M) | 满足 | 端口与适配器 |
| QAS-4 | 安全性 | 越权访问 | 100% 拒绝 | (H,L) | 满足 | 服务端授权校验 |

## 6. 常见错误

| 错误 | 纠正 |
|------|------|
| "系统要快" | 给数字：P99 < X ms，在什么负载下 |
| "要高可用" | 给场景：什么故障，多久恢复，RPO/RTO |
| 用平均值衡量延迟 | 用 P95/P99 分位数 |
| 没有环境描述 | 必须说明"在什么条件下"（正常/峰值/降级） |
| 场景无法验证 | 必须能被压测/监控/审计验证 |
| 场景太多没有优先级 | 用效用树排序，聚焦 (H,H) |
| 场景与架构决策脱节 | 每个场景要标注对应的架构方法 |
