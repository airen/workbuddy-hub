# AGENTS.md — UI 设计军规

> 本文件是 **Codex / Cursor / 其它读取 `AGENTS.md` 的编码 agent** 的等价入口。
> 把它放到项目根目录（或 `~/.codex/AGENTS.md` 作为全局），agent 写界面时就会按下面的规则约束自己。
> 完整 26 条详解在 `references/`，可直接填的模板在 `templates/`。

## 何时启用

当你要**写或改任何有界面的东西**时，按本文件执行：页面、组件、卡片、表单、列表、表格、导航、弹窗、仪表盘、落地页、定价页、后台、小程序页面。

用户说这些话时尤其要启用：「界面太丑」「一股 AI 味」「AI 塑料风」「看着廉价」「像草台班子」「不够高级」「帮我美化 UI」「颜色好乱」「太挤了」「界面很平没有重点」「假数据一眼假」「图标太普通」「一点动效都没有」「帮我做设计评审」「UI 自检」。

不适用：纯后端 / CLI / 脚本 / 数据处理，没有视觉界面。

## 四条铁律

1. **先定基调，再动手。** 字体气质、色彩倾向、圆角大小、文案语气四项一旦选定，全站一致。**模糊词（高级 / 精致 / 克制）必须先翻译成可观察的决定**（规则 21）。
2. **先定首屏骨架，再写文案。** 骨架必须在写任何文案之前决定，否则必然滑向"左边大标题 + 右边一张装在圆角卡片里的产品界面"（规则 22）。
3. **先灰度，后上色。** 骨架阶段只用黑白灰 + 字重 + 间距 + 尺寸交代层级；颜色只在最后强化关键操作与核心状态。
4. **交付前必须自检，能派独立评审就派。** 按 `templates/UI-自检清单.md` 过一遍，不合格项当场改掉；有隔离的、能看图的执行者时再派一个独立评审（规则 26）。

## 工作流（10 步）

| 步 | 做什么 | 详见 |
|---|---|---|
| 1 | 定基调：字体 / 色彩 / 圆角 / 措辞 + **模糊词翻译成决定**（规则 01–02、21） | `references/01-style-and-start.md`、`references/09-design-direction.md` |
| 2 | **定首屏骨架**：内容页首屏就是第一排内容；说服页从 8 种骨架里选（规则 22） | `references/09-design-direction.md` |
| 3 | 搭层级：字重 + 颜色做层级、弱化配角、删标签、按钮金字塔（规则 03–06） | `references/02-visual-hierarchy.md` |
| 4 | 空间布局：先过度留白、约束宽度、组间距 > 组内距、拒绝等比缩放（规则 07–10） | `references/03-space-and-layout.md` |
| 5 | 排版：行长 45–75 字符、行高随行长与字号变、基线对齐、**中文另给一套值**（规则 11–12） | `references/04-type-and-text.md` |
| 6 | 色彩：完整色阶、浅底深字、颜色 + 图标双通道、配色两问自检（规则 13–15） | `references/05-color-and-a11y.md` |
| 7 | 质感：强调色边框、图片文字蒙版、图标不放大、**按气质选图标库**（规则 16–18、24） | `references/06-texture-and-imagery.md`、`references/10-icons-motion-review.md` |
| 8 | 细节与内容：慎用边框、空状态优先、**示例数据要像真的**（规则 19–20、23） | `references/07-details-and-empty-state.md`、`references/09-design-direction.md` |
| 9 | **做三处基本动效**（规则 25） | `references/10-icons-motion-review.md` |
| 10 | 交付前自检（61 项）+ 独立评审（规则 26） | `templates/UI-自检清单.md` |

写代码前先读 `references/08-engineering-parameters.md`，把设计令牌（间距刻度 / 字号行高配对表 / 色阶 / 圆角 / 阴影）落到项目里，后面所有组件都从令牌取值。

## 26 条军规速查表

| # | 规则 | 一句话判据 |
|---|---|---|
| 01 | 为你的设计选择一种个性 | 字体 / 色彩 / 圆角 / 措辞四项，全站一致 |
| 02 | 别着急上色 | 灰度下能读懂层级，才算骨架成立 |
| 03 | 字号并非万能 | 层级 = 字重 + 颜色，不只靠字号 |
| 04 | 通过弱化来凸显重点 | 突出不了主角，就去弱化配角 |
| 05 | 不到万不得已别用标签 | 格式或上下文能自明，就删标签 |
| 06 | 别让"语义"决定按钮样式 | 主要实心 / 次要线框 / 辅助文本 |
| 07 | 从"过度留白"开始 | 先给多，再收紧 |
| 08 | 不必非得填满整个屏幕 | 内容宽度按需约束，不撑满 |
| 09 | 间距的"亲疏"之别 | 组间距 > 组内间距 |
| 10 | 等比缩放并非总是有效 | 大元素在小屏要收得更狠 |
| 11 | 控制文本行长，动态适配行高 | 行长 45–75 字符，行高随行长与字号变 |
| 12 | 以基线对齐，而非居中 | 混排用 `align-items: baseline` |
| 13 | 你需要的颜色远比想象中更多 | 中性 8–10 档 + 主色 5–10 档 + 语义色 |
| 14 | 巧用"浅底深字" | 浅底深字（反转对比），不用深底白字 |
| 15 | 不要只靠颜色传递信息 | 颜色 + 图标双通道 |
| 16 | 用强调色边框为设计添彩 | 一道彩条，最小代价换焦点 |
| 17 | 图片上的文字需要稳定的对比度 | 治背景：蒙版 / 降对比 / 单色叠底 |
| 18 | 万物皆有其适用尺寸 | 图标不放大，截图不缩小 |
| 19 | 慎用边框 | 先试背景色差、留白、阴影 |
| 20 | 别忽视"空状态"的设计 | 空状态优先设计，给 CTA 并隐藏空壳控件 |
| 21 | 模糊词必须翻译成决定 | 「高级 / 克制」→ 色相上限、网格公差、占比预算 |
| 22 | 先定首屏骨架，再写文案 | 内容页首屏就是第一排内容；左右分栏一轮最多一次 |
| 23 | 示例数据要像真的 | 不整齐的指标、有层次的时间、说具体动作的按钮 |
| 24 | 图标是一套语言，不是默认值 | 按气质选库，描边跟字重走，能不用就不用 |
| 25 | 每个界面先做三处动效 | 主操作反馈 / 状态切换来路 / 首次出场 |
| 26 | 交付前派一次独立评审 | 隔离上下文、只看画面、10 分制且必须说清差距 |

## AI 塑料风症状速查（写完先自诊）

出现任一条 → 骨架没搭对，回第 1–3 步：

- 满屏紫蓝渐变 + 玻璃拟态 + 到处发光阴影
- 层级全靠字号，辅助文字 12px 还发灰
- 所有间距都是 16px，卡片里外一样
- 每个区块都套 1px 灰边框
- 三个按钮全是高饱和实心
- 段落横跨 1400px 全宽，行长 200+ 字符
- 图标被拉大、截图被缩小，比例失调
- **首屏左边大标题 + 按钮，右边一张装在圆角卡片里的产品界面**
- **假数据是整数 + 张三李四 + "2 小时前"**
- **图标还是 Lucide 默认的 24px / 2px 圆头描边**
- **按下按钮、切换标签、增删列表毫无反应**

## 硬数值（写代码时直接取用）

```
间距刻度：4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96 / 128（px）
组内距 8–12，组间距 32–48（比例 3–4 倍）

行高：大标题 1.1–1.2 ｜ 小标题 1.3 ｜ 正文 1.55 ｜ 宽段落 1.75
中文：正文 1.6–1.75 ｜ 多行中文标题 1.2–1.35
禁止全局 line-height: 1.5

字号：H1 40 / H2 32 / H3 24 / 正文 16 / 辅助 14（桌面）
中文正文：阅读型 16–18 ｜ 产品界面 14–16 ｜ 高密度工具 13–14
移动端：字号越大缩得越狠（H1 28–32，正文 15–16）

行长：正文 max-width: 65ch（45–75 字符）
表单：max-width: 28–32rem

文字色：主 #0f172a ｜ 正文 #475569 ｜ 辅助 #94a3b8（各配字重）
字重：不低于 400

对比度：正文 ≥ 4.5:1 ｜ 大字号 / 图形 ≥ 3:1
彩色标签：浅底（50 档）+ 深字（700 档）

圆角：全站 ≤ 2 种半径
阴影：只用 sm / md / lg 三档中性阴影，禁止发光阴影
分区：背景色差 > 留白 > 阴影 > 边框（边框是最后手段）

图标：描边粗细跟字重走（细字 1–1.5px，粗黑体 2px+ 或实心）
      尺寸约为字号的 1–1.25 倍，按视觉中心对齐
动效：按下 150–300ms ｜ 下拉 180–250ms ｜ 面板 250–400ms ｜ 整页 350–500ms
      过冲：大面积 ≤2%，小物件 10–20%
      手感（刚度/阻尼）：咔嗒 350–400/10–15 ｜ 滑入 250–300/20–25 ｜ 流淌 150–200/30–40
```

## 输出规范

- **要代码就给能跑的代码**，把令牌以 CSS 变量或 Tailwind `@theme` 形式写进去，不要只给描述
- **要评审就给可执行结论**：按「问题 → 违反哪条规则 → 具体怎么改（改后的值 / 类名 / 代码片段）」三段式，不要只说"这里不太好看"
- **独立评审单独输出**：按「位置 / 观察与证据 / 影响 / 建议 / 验证」五项写，**分数必须附带具体差距**
- 数值给具体值（`padding: 24px`、`line-height: 1.6`），不要写"适当留白"
- 一次只改一处主要问题，先说结构性（骨架 / 层级 / 间距 / 宽度），再说细节（圆角 / 阴影）
- 示例数据要像真的：`1,238 位用户`、`+1.83%`、"昨天 16:12"；按钮写具体动作
- 语言跟随用户
