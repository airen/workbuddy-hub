# 01 ｜ 动手之前：定好风格基调与起步策略

> 覆盖 **规则 01–02**。这一章决定后面所有决策的坐标系。**没定基调就写代码，等于让每个组件各说各话。**

---

## 规则 01：为你的设计选择一种个性

每一项设计都拥有某种独特的个性。一个银行网站会力求传达**安全与专业**，一个新潮的初创公司则希望设计让人觉得**有趣又俏皮**。

个性听起来抽象，但它其实由**四个具体因素**决定。选完这四项，风格就定了：

| 因素 | 选项 → 传递的感觉 |
|---|---|
| **字体选择** | 衬线字体 → 优雅 / 古典；圆体无衬线 → 俏皮；中性无衬线 → 简约克制 |
| **色彩倾向** | 蓝 → 稳妥、熟悉；金 → 昂贵、精致；粉 / 明亮色系 → 有趣、不严肃 |
| **边框圆角** | 小圆角 → 中性；大圆角 → 活泼俏皮；直角 → 严肃、正式 |
| **语言措辞** | 客观疏离 → 官方专业；友好随意 → 亲切 |

**关键约束：同一个界面里保持一致性。** 四项一旦选定，随后的视觉决策才不会互相打架。

### 两套典型配方

| | 严肃专业（如银行、B 端后台） | 俏皮亲切（如社交、C 端产品） |
|---|---|---|
| 字体 | 衬线标题 + 严谨无衬线正文 | 圆体无衬线 |
| 色彩 | 深蓝稳重、低饱和 | 明快多彩、高饱和 |
| 圆角 | 小圆角（4–6px）或直角 | 饱满大圆角（12–20px） |
| 措辞 | 客观、正式 | 随和、口语 |

### 落地建议

- 不要为每个页面单独选风格。**基调是产品级的**，写进设计令牌（见 [08-engineering-parameters.md](08-engineering-parameters.md)）。
- 用 Tailwind 时，把基调固化在 `@theme` 里：`--font-sans`、`--radius-*`、`--color-brand-*`，**不要在每个组件里现编**。
- 圆角尤其容易失控：一个页面里同时出现 4px / 8px / 12px / 999px 四种圆角，就是没定基调。

## 规则 02：别着急上色

在设计新功能的最早期，**不要过分纠结字体、阴影、图标这类底层微观细节**。这些细节最终当然重要，但绝不是在起步阶段。

即便你已经准备进入更高保真度，也要**克制住立即引入色彩的冲动**。

**在灰度模式下设计**，会逼你必须完全依靠**间距、对比度、字重与尺寸**来完成所有核心设计工作。仅凭黑白灰，你必须清楚地交代出主次层级与信息的亲疏归属。

这样做挑战稍大，但最终你会构建出一个**更清晰、层级分明的稳健骨架**。后续再用色彩来强化关键操作与核心状态，效果就水到渠成、轻而易举。

### 灰度阶段的自检问句

把页面调成灰度（或先不写颜色），问自己：

1. 不看颜色，我能一眼看出**哪个是标题、哪个是正文、哪个是辅助说明**吗？
2. 我能看出**哪个按钮是主要操作**吗？
3. 信息之间的**亲疏关系**（谁和谁是一组）清楚吗？
4. 页面有"呼吸感"还是"糊成一片"？

四问都过，才进入上色阶段。

### 上色的正确姿势

灰度骨架完成后，**颜色只做两件事**：

- **强化关键操作**：主按钮、激活态导航
- **强化核心状态**：成功 / 警告 / 错误、选中

**不要**用颜色去弥补层级缺失。层级是骨架的职责，颜色只是点睛。

### 反例清单（AI 最爱犯）

- 一上来就 `bg-gradient-to-r from-purple-500 to-pink-500` —— 层级还没搭就先上渐变
- 每个卡片都加 `shadow-lg` + 玻璃拟态 + 发光边框 —— 用特效替代结构
- 所有文字用同一个灰度，靠字号硬撑层级 —— 灰度阶段没过关
