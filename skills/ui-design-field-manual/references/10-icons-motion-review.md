# 10 ｜ 图标、动效与独立评审

> 覆盖 **规则 24–26**。三条都是"做完之后"的质量关：图标有没有默认成 Lucide、动效有没有、谁来复核。

---

## 规则 24：图标是一套语言，不是默认值

**模型的默认永远是 Lucide 或 Heroicons**：24px、2px 描边、圆头端点。

库本身没有问题，**问题是每个界面都用同一套、同一种摆法**。图标和字体一样，是设计语言的一部分。

### 按气质选型

| 方向的气质 | 可以考虑 | 特点 |
|---|---|---|
| 精致、编辑、奢侈 | Phosphor 的 Thin / Light，Iconoir | 细描边，配细字重的衬线或无衬线 |
| 工业、仪器、企业工具 | Carbon，Material Symbols 的 Sharp，Radix Icons | 直角端点、网格严格；Radix 专为 15px 紧凑界面设计 |
| 友好、圆润、消费 | Phosphor 的 Fill / Duotone，MingCute | 圆角端点，实心或双色 |
| 中文产品，需要大量业务图标 | IconPark，Remix Icon | 覆盖面广；IconPark 能调描边粗细、端点和主题 |
| 需要连续调粗细和填充 | Material Symbols | 可变字体，填充 / 字重 / 光学尺寸都能连续调 |
| 像素、游戏、复古 | Pixelarticons | 像素网格 |
| 品牌标志 | Simple Icons | 各品牌标志的矢量形状 |

> 用 Iconify 可以按名称取到上面大多数库的单个 SVG。

### 六条使用规则

1. **一个产品只用一套。** 需要补缺时，挑描边、端点和圆角一致的，统一成相同的画布尺寸与描边宽度。
2. **粗细跟字重走。** 图标描边接近同尺寸正文的笔画粗细：**细字配 1–1.5px，粗黑体配 2px 以上或实心**。
3. **尺寸约为字号的 1–1.25 倍**，按**视觉中心**和文字对齐，不按外框。
4. **能不用就不用。** 编辑类方向常用字符本身：`→` `↗` `※` `§`、编号、缩写。只在能加快识别的地方用图标。
5. **品牌时刻手绘。** 核心动作、空状态这类少数位置，可以用方向自己的线条语言画专属 SVG；通用动作仍用库。
6. **小样内联。** 自包含小样只内联用到的 SVG，**不引用图标字体或 CDN**。

### 许可要核对

多数图标库是 MIT / Apache / ISC。**⚠️ SF Symbols 只能用在 Apple 平台的界面里，不能用于网页。** 需要署名的库按要求署名。

### 顺带两条图标相关的判据

- **陌生图标必须配可见文字**；纯图标按钮仍需可访问名称。
- **箭头符号有含义**：`↗` 表示打开新页面或外部链接；提交、检查这类原地动作**不用** `↗`。

## 规则 25：每个界面先做三处动效

完全不动的界面像一张截图：按下没有回应，切换没有来路，用户只能猜刚才发生了什么。

**新界面和改动了操作流程的界面，先把这三处做出来**（小改动不加）：

| # | 动效 | 要求 |
|---|---|---|
| 1 | **主操作的反馈** | 按下立刻有回应，完成时交出一个结果：按钮陷下去再弹回、勾号画出来、数字滚到新值 |
| 2 | **一处状态切换的来路** | 选中 / 展开 / 换视图 / 增删列表项时，让人看见东西从哪里来、到哪里去 |
| 3 | **第一次进入时的一次出场** | 主角先到，其余按阅读顺序跟上；**只在首次进入时播放** |

> 这三处之外再加动效，先问一句：**如果要手写一周才能做出来，还值得做吗？**
> 滚动淡入、视差、跟随鼠标、装饰性循环最容易变成干扰。每个动效都要承担**反馈 / 引导 / 连续 / 品牌表达**中的一项。

### 手感表：用「动作 + 实物」定参数

手感从方向的材质和调性推出。**用实物做参照来选弹簧参数**（刚度 / 阻尼）：

| 动作 | 实物参照 | 刚度 / 阻尼 | 适合 |
|---|---|---|---|
| **咔嗒** | 磁铁吸合、卡扣、拨动开关 | 350–400 / 10–15 | 按钮、开关、下拉展开 |
| **滑入** | 气压闭门器、抽屉阻尼 | 250–300 / 20–25 | 底部面板、抽屉、折叠 |
| **流淌** | 倒蜂蜜、雾气弥散 | 150–200 / 30–40 | 页面转场、主视觉出现 |
| **砸落** | 锤击、重物落桌 | 400–500 / 5–10 | 确认选择、完成反馈 |
| **回弹** | 橡皮球、蹦床 | 300 / 8 | 庆祝提示、儿童与游戏 |
| **漂浮** | 氦气球、飘絮 | 100 / 25 | 冥想、梦幻场景、空闲循环 |

- **重的材质**（石、金属、陶）偏咔嗒和砸落；**轻的材质**（纸、布、雾）偏漂浮和流淌。
- **高频操作用短促的动作**；少见的品牌时刻才用绵长的。

### 过冲幅度跟着面积走

| 对象 | 过冲上限 |
|---|---|
| 整页、面板这类**大面积** | **1–2%**（再多整块画面会晃） |
| 徽章、勾选标记这类**小物件** | **10–20%**（显得有弹性） |

### 呼应：让动作彼此接上

生硬的动效各动各的：按钮自己闪一下，面板自己滑出来，数字直接换掉。**好的动效像一句话**——一个动作引起的变化沿同一条路传下去，前一段的终点是下一段的起点。

- **从被操作的地方出发。** 点"加入购物袋"，商品缩成一个点飞进袋子，袋子上的数字跟着跳一下。
- **一次切换朝一个方向。** 卡片往左滑，标题、序号和底色也往左换。方向一乱就成了几段互不相干的动画。
- **主角先动，其余被带动。** 被影响的东西**晚 40–80ms** 跟上，幅度更小。
- **形状接力。** 按钮展开成面板，搜索图标拉长成输入框，播放键变成暂停键。

### 时长表

| 对象 | 时长 | 要点 |
|---|---|---|
| 按下、开关、选中指示 | **150–300ms** | 按下缩到 0.96–0.98，**按下时立即生效（约 80ms）**，松开再弹回 |
| 下拉、气泡、提示 | 180–250ms | 从触发点方向展开，缩放从 0.96 左右开始，**不从 0 开始** |
| 面板、抽屉、侧栏 | 250–400ms | 按移动距离取值，越远越长 |
| 整页或视图切换 | 350–500ms | **超过 500ms 就会让人等** |
| 首次进入依次出现 | 每项间隔 40–80ms | 总长不超过 600ms，只在首次进入播放 |

- 悬停上浮 **2–4px**，阴影随之加深。**位移超过 20px 的悬停效果会显得轻浮。**
- **离开比进入快**：退出时长约为进入的 60–70%。

### 看不见的结果要说出来

一次点击产生了看不见的副作用（复制到剪贴板、后台保存、发送），用一条短暂提示**说出结果本身**——例如「已复制：……」——而不是只说「成功」。

### 检查动效

**静态截图证明不了动效。** 三处基本动效都要留证据：一段 **3–5 秒录屏**，或**开始 / 中间 / 结束三帧**，并写明触发它的动作。

把播放速度调到 10%，在过渡进行到一半时截图，看有没有重影、跳动、元素突然出现。最后开启系统「**减少动态效果**」再走一遍——所有状态应直接到位。

## 规则 26：交付前派一次独立评审

**自己检查自己写的界面，等于自己判自己的卷。** 只要环境里有隔离的、能看图的执行者，就派一个**没有本次对话历史**的评审者。

| 情况 | 怎么做 |
|---|---|
| 有隔离、能看图的执行者 | **派一个独立评审者**（新上下文） |
| 没有 | 主 Agent 自检，但**必须标明「未独立评审」** |
| 完全不能看图 | 只给结构或源码诊断，**不根据文件名猜画面**，不给视觉评分 |

### 交接：给什么 / 不给什么

| 给 | 不给 |
|---|---|
| 用户任务、受众、交付范围、目标设备 | 制作者的论证、已投入的时间 |
| 已确定的方向、品牌与不可改变的约束 | 源码、实现细节、技术借口 |
| 当前版本截图，注明页面、状态与逻辑视口 | 旧版本截图、旧评分、旧评审结论 |
| 实际看过的必要参考及其用途 | 预设问题清单、希望评审者赞同的答案 |
| 动效的 3–5 秒录屏或三帧，并写明触发动作 | 「必须给到某个分数」这类暗示 |

> ⚠️ **截图文件必须能被评审者访问**，交接前确认属于当前版本。**单张截图不能证明提交或键盘行为正确。**

### 可直接使用的评审任务

> 根据提供的用户任务、设计方向、约束和当前画面评审设计。先用一两句话说出这个画面想成为什么体裁和风格；再说出它属于什么品类，举出这个品类里两三个风格最鲜明的产品，说出它们在首屏和控件上通常怎么做。画面违背这些共识的地方，判断是有意的偏离，还是没认出品类；同时看画面是不是某个标杆的复制。
>
> 先看主构图、阅读顺序、主视觉和内容与操作的关系，再看排版、空间、色彩和细节。留意过度、夸张或一看就是模型生成的做法并扣分：**首屏左边大标题、右边说明或图片的默认分栏；无来由的渐变与发光；处处圆角卡片；表情符号当图标；随意给文字上色；空泛或晦涩的比喻式文案**。
>
> 多个元素同时争当主角、处处都在用力，也算问题；反过来，**处处及格却没有一处让人记住，也要指出来**，并说出最值得集中发力的位置。
>
> 单独列出两类小问题：**可以直接删掉的文字**，以及对齐、圆角、阴影、标点、状态这类看得出的细节瑕疵。表格和列表要放大看，各列的行线和基线是否对齐。
>
> 每处问题写清**位置、观察、影响和可执行的调整方向**，必要时给伪代码或属性关系，不写含糊的散文。**敢下判断**，给出有主见的建议，不退回安全、容易的做法。没有明显问题时直接说明，**不为凑数提出修改**。
>
> 最后按 **10 分制**打分，表示当前画面离顶尖水准还有多远。只提供评审，**不修改文件**。未看到或无法验证的内容明确说明。

### 反馈格式（评审者必须按这个回）

每条问题包含五项：

| 项 | 内容 |
|---|---|
| **位置** | 页面、区域、状态或元素 |
| **观察与证据** | 实际看到了什么。**不能只说"普通""不高级"** |
| **影响** | 妨碍了识别、任务完成、视觉焦点，还是选定方向 |
| **建议** | 可执行的调整，必要时给属性关系或布局示意 |
| **验证** | 改完该检查什么；并指出这条是否只是主观偏好 |

> **分数必须附带具体差距。只有数字的评审不算有效。**
> 不同模型给出的分数不直接比较，也不把分数当作审美事实。**分数高但用户不喜欢时，以用户判断为准。**

### 主 Agent 怎么处理反馈

1. **只做一轮。** 改完由主 Agent 和基线做前后对比，**不为分数复查**。
2. **先处理**任务阻碍、内容错误、明显层级问题，再处理有依据的精修。
3. 评审列出的「**可以直接删掉的文字**」默认照删；只有删了会影响理解时才保留，并写一句理由。
4. **改在共享的令牌和组件上**，不在单个页面上覆盖。
5. 建议**违反用户约束、只表达另一种偏好、或缺乏证据**时，可以不采纳并保留简短理由。
6. **出现持续换风格、互相推翻、或细节调整无可见收益时，停止美学循环**，保留最符合任务与方向的版本。停止不能掩盖仍然存在的功能缺陷。

## 本章速记

1. **图标不是默认值**：选一套、描边跟字重走、能不用就不用
2. **先做三处动效**（主操作反馈 / 状态切换来路 / 首次出场），手感用「动作 + 实物」定参数
3. **交付前派独立评审**，10 分制且**必须附带具体差距**；只做一轮，改在共享令牌上
