# 04 ｜ 文本与排版：把控行长、行高与基线对齐

> 覆盖 **规则 11–12**。这一章解决"读起来累、混排别扭"。

---

## 规则 11：控制文本行长，动态适配行高

在设计文本样式时，很多人喜欢在全局 CSS 里**写死一个 `line-height: 1.5`**，然后任由文字容器随意铺满屏幕。这是错的。

### 行高与行长成正比

行间距的核心目的，是**帮助读者读完一行后轻松折返回下一行的开头**。

- 行长越长，视线水平跳跃距离越远；
- 行间距过小，就极易**读错行或串行**。

因此：**行高应该与行长成正比。**

| 段落宽度 | 建议行高 |
|---|---|
| 较窄（< 50 字符） | 1.5 左右 |
| 较宽（70–90 字符） | 1.8 |
| 极宽（> 90 字符） | 2.0 |

### 行高与字号成反比

小字号文本需要**充足的行距**来引导视线；但当字号变大（如大标题）时，字面本身已足够清晰醒目，若仍套用 1.5，标题就会**松散脱节、形如散沙**。

| 字号 | 建议行高 |
|---|---|
| 12–14px | 1.5–1.7 |
| 16–18px | 1.5–1.6 |
| 24–32px | 1.3–1.4 |
| 40px+ 大标题 | **1.1–1.2** |

### 黄金区间

> **控制段落行长在每行 45–75 个字符（约 20–35em）**，并让行高随行长和字号**动态调整**，是保证舒适排版阅读的基础。

### 工程落地

```css
/* ❌ 全局写死 */
body { line-height: 1.5; }

/* ✅ 分层设置 */
:root {
  --lh-tight:  1.15;  /* 大标题 40px+ */
  --lh-snug:   1.3;   /* 小标题 24–32px */
  --lh-normal: 1.55;  /* 正文 */
  --lh-relaxed:1.75;  /* 宽段落 / 长文 */
}
.prose        { max-width: 65ch; line-height: var(--lh-normal); }
.prose--wide  { max-width: 85ch; line-height: var(--lh-relaxed); }
h1, .hero     { line-height: var(--lh-tight); }
```

- ❌ 优化前：文本横跨整个大屏未做约束，行长过长且行间过密，换行极易读错行
- ✅ 优化后：段落宽度约束在 45–75 字符黄金区间，行高与行长协同适配，阅读平稳流畅

## 规则 12：以基线对齐，而非居中

设计中经常需要在同一行里使用**不同大小的文字**。比如卡片头部左侧是大号标题，右侧是小号辅助操作（如"查看全部"或时间戳）。

**很多人的第一反应**是写一个 `align-items: center` 垂直居中，以求几何上的平衡。

- 如果文字之间**离得很远**，问题还不显眼；
- 但**挨得很近**时，不协调感暴露无遗——小字看起来像**孤零零地漂浮在空中或下沉悬挂**，非常别扭。

### 更专业的做法：沿基线（baseline）对齐

**所谓基线，就是所有字母仿佛都"坐"在上面的那条隐形横线。** 人类的阅读视线早已习惯顺着这条基准线平移。

改用 `align-items: baseline`，文字的视觉重心立刻稳稳落地，整体呈现出更规整、更严谨的美感。

### 工程落地

```html
<!-- ❌ 几何居中：小字视觉悬空 -->
<div class="flex items-center">
  <h3 class="text-2xl font-bold">Who to follow</h3>
  <span class="text-xs text-blue-600">Refresh</span>
</div>

<!-- ✅ 基线对齐：视觉底盘扎实 -->
<div class="flex items-baseline gap-2">
  <h3 class="text-2xl font-bold">Who to follow</h3>
  <span class="text-xs text-blue-600">Refresh</span>
</div>
```

| 场景 | 用什么 |
|---|---|
| 同一行混排不同字号文字 | `align-items: baseline` |
| 图标 + 文字（图标需微调） | `items-center` + 图标 `translate-y` 微调 |
| 纯图标并排 | `items-center` |

**判据**：一行里如果出现"大标题 + 小字链接/时间戳"，默认就该用 baseline。

- ❌ 优化前：几何绝对居中（`align-items: center`），不同字号混排时小字视觉上悬空错落
- ✅ 优化后：沿字母隐形基线平齐对齐（`align-items: baseline`），视觉底盘扎实稳健

## 中文排版补充（英文规则不能直接照搬）

上面 45–75 字符的行长是**拉丁字母**的经验值。中文单字信息密度高，同一段行长的**字数**要少得多，字号和行高也要另给。

### 中文正文起步字号

| 页面类型 | 正文起步 | 说明 |
|---|---|---|
| 阅读型页面（文章、文档、介绍页） | **16–18px** | 长时间阅读，宁大勿小 |
| 产品界面（后台、工具、App） | **14–16px** | 密度与可读性的平衡点 |
| 每天长时间使用的高密度工具 | **13–14px** | 只在信息密度确实需要时下探 |

**正文行高 1.6–1.75**（比英文的 1.5 更松）。**操作文字通常 14–16px。**

> 这些是**起点，不是死规定**。但**不要靠 9–12px 的说明、低对比细字或压缩行高营造"精致"** —— 那不是精致，是难读。信息太多先删冗余、调层级或重排。

### 中文多行标题

**多行中文标题通常先用 1.2–1.35 的行高**，按真实字形检查。

- **不要照搬英文大写海报的极紧行高**（那是为全大写拉丁字母设计的，中文字面更高）
- **不要把标题高度固定为单行** —— 中文标题折行是常态
- **不要用负 margin 挤压后续内容**

展示字确需更紧时，**必须看过每个支持视口的实际换行**，确认字形不碰撞。

### 中文断行要主动控制

`text-wrap: pretty` 或 `balance` **只能减少孤字，不能消除**。还需要：

- **数字与单位**（`38 秒`、`47 分钟`）、**不可拆的词**（`不会`）用 `white-space: nowrap` 包起来
- **首屏说明、页边批注**这类短段落按语义手动断句
- **行末只剩一两个字，或者词被拆到两行，都算缺陷**

### 验收要看什么

看**长标题、两到三行正文、中英混排、数字与单位、字体回退**；在窄屏和放大阅读后检查行间、上下区块及按钮内部。

> **文字重叠、截断关键信息、被相邻区域压住，属于未完成。**
> 先修**行高、内容驱动高度和容器伸缩**，再考虑减小字号。

### 中英混排

- 检查**基线**是否对齐（英文 x-height 与中文字面高度不同）
- 检查**视觉重量**是否一致（同字号下中文看起来更重，英文更轻）
- 中英之间按需加间隙，不要依赖浏览器默认

## 本章速记

1. **禁止全局写死 `line-height: 1.5`** —— 按层级给值
2. 行长 **45–75 字符**，行高随行长**正比**、随字号**反比**
3. 大标题行高收到 **1.1–1.2**
4. 一行混排不同字号 → **`items-baseline`**
5. **中文另给一套值**：正文 16–18 / 14–16 / 13–14px，行高 1.6–1.75，标题 1.2–1.35
6. **中文断行要主动控制**，`text-wrap: pretty` 只减少孤字
