# 09 ｜ 从模糊词到结构：方向、骨架与内容

> 覆盖 **规则 21–23**。这三条解决动手之前最容易含糊过去的三件事：用户说的"高级"到底指什么、首屏长什么样、界面里的假数据像不像真的。

---

## 规则 21：模糊词必须翻译成决定

**"高级、精致、克制、大气、简洁、有质感"不能当作设计理由。** 这类词说出来的时候什么也没决定——它们只是感觉，不是指令。

用户（或你自己）说出这类词时，**先翻译成可观察的决定**，再动手：

| 模糊词 | 必须翻译成 |
|---|---|
| **高级** | 先说是哪一种高级；再定字体对比度、分隔方式、间距尺度、色相数量 |
| **精致** | 公差：字距怎么调、对齐到几像素网格、阴影最多几级、色相最多几种 |
| **克制** | **饱和度预算**：强调色不超过画面 **10%**；动效幅度上限；色相数量上限 |
| **简洁** | 密度档位，**以及删掉什么、为什么删**。简洁是结果，不是指令 |
| **大气** | 尺度：主标题多大、主图占多少面积、留白是基准的几倍 |
| **有质感** | 材质与光：用哪种表面、主光从哪来、边缘怎么处理 |
| **活泼** | 圆角半径、动效过冲幅度、插画语言、文案语气 |
| **粗糙** | 用哪些手段、各用到什么程度（错位多少像素、旋转多少度） |

**判据**：翻译不出可观察决定的词，**从理由里删掉**。

### 用户说"再高级一点"时怎么办

不要猜，也不要硬调。二选一：

1. **用上面的表追问一句**：「你是想要更少的色相，还是更严的网格，还是更大的留白？」
2. **拿两版并排让用户比** —— 比较比形容词有效得多。

### 落地

翻译结果直接写进 [../templates/设计基调卡.md](../templates/设计基调卡.md)：色值栏、间距刻度栏、以及「本产品绝对不做」那三条。

## 规则 22：先定首屏骨架，再写文案

### 先回答一个问题：用户来首屏是看什么、做什么？

| 页面类型 | 首屏是什么 |
|---|---|
| **来看内容、挑东西、干活的页面**（画廊、商店、信息流、文档、作品集、工具、后台） | **首屏就是第一排内容本身。** 导航 + 标题 + 筛选合计不超过一两行；第一排内容必须完整出现在首屏。**不放首屏口号**，也不放解释"这个页面是干什么的"的段落 |
| **来说服人的页面**（落地页、品牌页、发布页、展览页） | 才从下面的骨架表里选 |
| **两种都有**（如商店首页顶上有一块活动横幅） | **以用户最常来做的事为准**：横幅可以留，但不能把第一排商品推出首屏 |

**这条极重要**：给"来看内容"的页面套说服型骨架（大标题 + 说明 + 按钮），是 AI 生成后台/工具类界面最典型的错误。

### 说服型页面的 8 种首屏骨架

每个方向**先选一个骨架，再用 3–5 个方框画出首屏线框**（每块是什么、占首屏多大面积、阅读从哪里开始）：

| 骨架 | 首屏长什么样 |
|---|---|
| **满版图像压字** | 一张图占满首屏，标题和动作压在图的安全区里 |
| **居中单一物件** | 一个物件或一句话居中，四周是大面积空白 |
| **画面即界面** | 首屏就是产品界面或一件实物本身，标题、导航和按钮都长在它上面 |
| **满版文字** | 文字本身就是画面，字大到占满首屏、跨过边缘或被裁切 |
| **通栏上下堆叠** | 通栏大标题横跨整个宽度，下面紧接内容 |
| **网格拼贴** | 多块内容同时出现，按网格或拼贴排列，没有单一主角 |
| **纵排或斜向** | 文字竖排、斜切或旋转，打破从左到右的阅读 |
| **左右分栏** | 文字一侧，画面一侧。**这是模型的默认，一轮最多一个方向使用**，并写出为什么非它不可 |

### 三条硬规则

1. **同一轮的方向，骨架互不相同。**
2. **左右分栏最多出现一次。** 所谓"大标题九栏、说明三栏"同样算左右分栏。
3. **骨架定好之后再写文案。** 文案去适应骨架，不让骨架去适应"标题 + 说明 + 按钮"的组合。

### 为什么这条非写不可

模型最顽固的习惯是**左右分栏**：一边大标题，另一边说明、按钮或一张图。换字体、换配色、换材质都改不了它——**因为它在写文案之前就定下来了**：先想好标题、一段说明、一个按钮，把它们摆好，自然就是左右两栏。

而最常见的模板核心还不是分栏本身，是**"左边标题和两个按钮，右边一张装在圆角卡片里的产品界面"**。那张卡片几乎总是该删的：

- 要么**让产品界面本身占满首屏**；
- 要么换成一张**跨越版面结构**的图、一个色块或一个图形装置——**不能是装在卡片里的界面**。

**判据**：把首屏线框单独画出来，眯眼看明暗块面。如果两个方向的块面分布相似（都是左边一大块、右边一小块），即使字体颜色都不同，也是同一骨架 —— **回去重选，不要靠换装饰补救**。

## 规则 23：示例数据要像真的

示例数据会暴露模板感，**即使视觉层已经做得很好**。这是 AI 生成界面最容易被一眼识破的地方。

### 必须避开的六种假数据

| 假数据 | 为什么假 |
|---|---|
| **整数指标**（1,000 位用户、+10%、$10,000） | 真实数据几乎从不这么整齐 |
| **张三李四 + 示例公司**（Acme、某某科技） | 一眼就是占位符 |
| **每条都是"2 小时前"** | 真实时间戳是散乱的 |
| **写着"标题""描述""内容"的占位字** | 等于没写 |
| **反复出现的"了解更多""立即开始""点击这里"** | 空泛，不说具体动作 |
| **库名 / 技术栈当演示内容** | 用户不关心你用了什么 |

### 真实数据长什么样

- 指标不整齐：**1,238 位用户**、**+1.83%**、**$103,482**
- 时间有层次：**"刚刚"**、**"昨天 16:12"**、**"3 月 14 日"**、**"2026-01-08"**
- 名字有长有短：**李一** 和 **欧阳振华** 都要能排下（顺带验证长名字的排版）
- 按钮说出**具体动作**：「保存草稿」「周二发送」「导出为 CSV」，而不是「提交」「确定」

### 多个演示要共用一个虚构世界

页面上有很多演示（组件目录、模板库、功能展示）时，让它们**共用同一个具体的虚构场景**：同一个产品、同一批人、同一组文件和数字。

演示之间互相呼应，比各自编一条"示例标题"可信得多。

### 制作说明不写进画面

**画面上不出现**「示例」「示意图」「待核实」「按钮未接入」「仅保存在本机」这类制作说明。

它们写进**交付说明**里，不写进界面。同理，**不伪造业务成功、客户评价或产品指标**。

## 本章速记

1. **模糊词 → 可观察的决定**，翻译不出来就从理由里删掉
