# 05 ｜ 色彩与无障碍：搭建实用色阶，兼顾识别度与对比度

> 覆盖 **规则 13–15**。这一章解决"颜色乱、刺眼、色盲用户看不懂"。

---

## 规则 13：你需要的颜色，远比想象中更多

你是否用过那种**在线调色板生成器**？选定一个初始颜色，微调几个选项，它就"赐予"你一套看似完美的**五色方案**，号称足够搭整个网站。

**这种"五色方案"根本没法做真实产品。** 除非你希望界面看起来像灾难现场：满屏刺眼的大黄底、突兀的深红报错条、生硬的深蓝侧边栏……把这 5 个颜色生搬硬套到所有组件上，页面立刻变成**毫无层级的车祸现场**。

> **只靠五个十六进制颜色码，你什么像样、舒适的东西都做不出来。**

### 真实产品依赖一套庞大的色彩系统

| 类别 | 档数 | 用途 |
|---|---|---|
| **中性灰色系** | **8–10 档** | 界面绝大多数元素：文本、主背景、面板底色、细边框、表单控件。从极深的近黑文字，以均匀步长过渡到柔和近白 |
| **品牌主色** | **5–10 档** | 核心操作按钮、激活态导航，决定产品整体气质。极浅色用于轻量背景，深色用于文字，基准色用于按钮 |
| **语义强调色** | **各 5–10 档** | 红（报错/破坏）、黄（预警/提示）、绿（成功/正向）、青或紫（新功能） |

即使语义色在界面中只是画龙点睛，**也需要准备好由浅到深的色阶**。

> 一个成熟的 UI 系统，包含**十种不同颜色、每种各有 5–10 个色阶**是极其常见的。
> **唯有备齐完整的色阶梯队，浅底才不会抢戏，深字才不会发虚，界面才能呈现出呼吸般的自然层次。**

### 工程落地

用 Tailwind 时直接用官方色阶（`slate-50 … slate-950`）就是一套现成的 10 档中性色。自建时按下面的方法生成：

```
中性色阶（10 档）：50 / 100 / 200 / 300 / 400 / 500 / 600 / 700 / 800 / 900 / 950
主色阶（10 档）：同上，用 OKLCH 或 HSL 保持感知均匀
语义色：每个语义一组，浅色档做背景、深色档做文字
```

- ❌ 优化前：在线生成器给出的孤立 5 色方案 → 生搬硬套导致界面刺眼混乱
- ✅ 优化后：预先规划的完整色阶系统（Primary / Neutral / Accents 梯队）→ 呈现呼吸般的高级秩序

> 具体生成公式与推荐取值见 [08-engineering-parameters.md](08-engineering-parameters.md)。

## 规则 14：无障碍不一定难看：巧用"浅底深字"

为保证可读性，**Web 内容无障碍指南（WCAG）建议普通文本与背景的对比度至少达到 4.5:1**。

在"白底黑字"的常规页面上这很容易。但为**标签（Badge）、警告框**等彩色小组件设计样式时，事情就棘手了。

### 常见错误

很多人的习惯是**在彩色背景上放白色文字**。但你会惊讶地发现：**为了让白色文字达到 4.5:1，彩色背景往往需要调得非常深、非常暗**。

如果这个小标签只是一个普通的辅助状态，深色的高饱和背景就会在页面上**极其"抢戏"**，硬生生破坏整个页面的主次视觉层级。

### 绝佳技巧：反转对比

> **与其在深色背景上放浅色文字，不如反过来——在浅色背景上使用深色的彩色文字。**
> 例如：**浅黄底 + 深金棕字**，**浅红底 + 暗红字**。

这样不仅保留了色彩承载的语义与强调作用，而且**柔和舒适，绝不会喧宾夺主**干扰页面的主要功能。

### 工程落地

```html
<!-- ❌ 深底白字：对比达标但刺眼抢戏 -->
<span class="bg-emerald-600 text-white px-2 py-0.5 rounded text-xs">Approved</span>

<!-- ✅ 浅底深字：柔和融入，对比度更高（可达 AAA） -->
<span class="bg-emerald-50 text-emerald-700 px-2 py-0.5 rounded text-xs">Approved</span>
```

**配方表（浅底 / 深字）**：

| 语义 | 浅底 | 深字 |
|---|---|---|
| 成功 | `emerald-50` / `#ecfdf5` | `emerald-700` / `#047857` |
| 警告 | `amber-50` / `#fffbeb` | `amber-800` / `#92400e` |
| 错误 | `red-50` / `#fef2f2` | `red-700` / `#b91c1c` |
| 信息 | `blue-50` / `#eff6ff` | `blue-700` / `#1d4ed8` |

- ❌ 优化前：使用深色高亮背景标签，虽然对比达标但视觉过于刺眼，抢占主要内容视线
- ✅ 优化后：采用"浅底深字"（反转对比），对比度大幅提升（达 AAA 级）且柔和融入界面

## 规则 15：不要只靠颜色传递信息

颜色无疑是强化信息、辅助理解的绝佳工具，**但千万要避免过度依赖它**。否则，对**色觉障碍**（如红绿色盲）用户，或在屏幕反光、弱光环境下，界面的状态传达就会彻底失效。

比如财务 / 数据卡片中，**仅靠红色文字表示下跌、绿色文字表示上涨**——对红绿色盲用户来说，两者看起来几乎毫无差别。

### 解法：增加另一种信息传递的维度

在颜色之外，加入**向上的箭头、向下的三角、勾选框或警告感叹号**等图形符号。

**双通道传达意味着即使完全剥离颜色，用户只看图标也能毫不费力地读懂状态。**

### 准则

> **颜色应该始终作为辅助工具，用来强化设计本身已经传达的信息；绝不应将其作为信息传递的唯一手段。**

### 工程落地

```html
<!-- ❌ 单通道 -->
<span class="text-red-600">-1.1%</span>
<span class="text-green-600">+1.4%</span>

<!-- ✅ 双通道：颜色 + 方向图标 -->
<span class="inline-flex items-center gap-1 text-red-600">
  <svg><!-- ↓ 向下箭头 --></svg> -1.1%
</span>
<span class="inline-flex items-center gap-1 text-green-600">
  <svg><!-- ↑ 向上箭头 --></svg> +1.4%
</span>
```

**注意**：涨跌配色遵循中国习惯（**涨红跌绿**），但这不影响规则本身——无论什么配色，都要加图形符号。

- ❌ 优化前：仅靠红绿文字颜色区分涨跌，色盲或弱光环境下状态极难识别
- ✅ 优化后：增加方向箭头与图标符号，双重通道确保信息百分之百送达

## 本章速记

1. **五色方案做不出产品** —— 中性 8–10 档 + 主色 5–10 档 + 语义色各 5–10 档
2. 彩色小标签用 **浅底深字**，不用深底白字
3. 状态传递必须 **颜色 + 图标双通道**
4. 对比度红线 **4.5:1**（正文）/ **3:1**（大字号与图形）
