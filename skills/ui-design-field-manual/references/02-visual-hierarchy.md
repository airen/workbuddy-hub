# 02 ｜ 视觉层级：克制使用大小，学会调配主次

> 覆盖 **规则 03–06**。这一章解决"页面糊成一片、看不出重点"。

---

## 规则 03：字号并非万能

**过分依赖字号来区分层级，是一种常见的误区。** 它会导致主要内容过大、次要内容过小，版面显得单薄散乱。

与其只靠字号，不如用**字重和颜色**达到同样的目的：

- **用字重强调重点**：主要元素加粗（**600 或 700**），这样你可以选用更克制、更合适的字号，同时依然稳稳凸显其统摄地位。
- **用颜色弱化次要文字**：辅助文字用**较浅的颜色（中灰 / 浅灰）**，而不是一味缩小字号。这既能清晰表明其从属地位，又能在最大程度上保证易读性。

### 一套够用的文字层级

| 角色 | 颜色 | 字重 |
|---|---|---|
| 深色主内容（标题、关键数据） | 近黑（如 `#0f172a`） | 600–700 |
| 灰色次要内容（正文、描述） | 中灰（如 `#475569`） | 400–500 |
| 浅灰色辅助说明（时间戳、备注） | 浅灰（如 `#94a3b8`） | 400 |

**两到三种文字颜色 + 两种字重**就足够构建细腻的层级。

> ⚠️ **避免使用低于 400 的过细字重**——小字号下极难看清。
> ⚠️ 不要用"小字 + 浅灰"同时弱化——那是双重削弱，会掉到可读性红线以下。弱化只用一个维度。

### 反例 / 正例

- ❌ 优化前：纯靠字号大小拉开层级，主标题膨胀到 48px，辅助文字缩到 11px 还发灰
- ✅ 优化后：主标题加粗赋深黑、字号收敛；次要文字适度缩小并降低明度，层级均衡温润

## 规则 04：反其道而行之：通过弱化来凸显重点

你会遇到这种窘境：**核心元素不够醒目，但你已经用尽方法，再也想不出新花样来强调它。**

比如给当前选中的导航项换上高亮色，想让它"跳"出来——但旁边同样深色加粗的未选中项一比，它还是不够突出。

**与其一味给目标元素"加戏"，不如换个思路：想想怎样弱化那些与之竞争的元素。**

把未选中项的文字颜色调浅、字重降为常规，让它们**悄然退为背景**。给周边喧闹的元素按下静音键，主角即便不施浓墨重彩，也会立刻成为视觉焦点。

### 工程落地

```css
/* ❌ 加戏：选中项越来越重 */
.nav-item.is-active { color: var(--brand-600); font-weight: 700; }

/* ✅ 静音：未选中项退为背景 */
.nav-item           { color: var(--gray-400); font-weight: 400; }
.nav-item.is-active { color: var(--gray-900); font-weight: 600; }
```

**判据**：如果为了突出 A 你不断给 A 加权，但页面同时有三个"很重"的元素，问题不在 A，在于 B 和 C 没有被弱化。

## 规则 05：不到万不得已，别用标签

> 先说明：这里讨论的**不是表单**，而是**向用户展示数据**的界面。

展示数据时，我们很容易不自觉地采用数据库式的 **"标签: 数据值"** 格式（如 `邮箱: jane@example.com`）。问题在于：**它让所有数据获得同等重要性**，整个页面平摊权重，很难建立视觉层级。

### 大多数情况下，格式本身就自明

| 数据 | 靠什么自明 |
|---|---|
| `jane@example.com` | 格式 → 一看就是邮箱 |
| `(555) 765-4321` | 格式 → 电话 |
| `$19.99` | 格式 → 价格 |
| 姓名下方的"客户支持" | 上下文 → 不需要"部门:"前缀 |
| 某人姓名下方的"客户支持" | 位置 → 不需要"职位:"前缀 |

**省掉不必要的标签**，把关键识别信息（**人名、标题**）**加大加粗置顶**，界面瞬间干净利落。

### 例外：什么时候**必须**保留标签

做**技术规格表 / 数据看板**时，用户需要靠"厚度""功耗"这类**指标名**来检索数据——此时不仅应保留标签，还可以**让标签颜色略深于数据本身**。

**判据**：用户是"扫一眼就知道"，还是"要找某个字段"？前者删标签，后者留标签。

## 规则 06：别让"语义"决定按钮样式

页面上有多个操作时，开发者容易掉进一个陷阱：**只根据操作的语义（semantics）设计**，给每个按钮都套上醒目的高饱和实心填充。

但页面操作应遵循**重要性金字塔**：大多数页面只有**一个核心主要操作**、**一两个次要操作**、**几个很少用到的辅助操作**。

| 层级 | 视觉 |
|---|---|
| **主要操作** | 最醒目：实心填充 + 高对比度背景 |
| **次要操作** | 清晰但不过分突出：线框样式，或低对比度浅色背景 |
| **辅助操作** | 容易找到但绝不抢戏：朴素的文本链接 |

### 破坏性操作怎么放

即使是破坏性 / 高风险操作（如**删除**），**如果它不是当前页面的主要任务**，也应先设计成次要或辅助按钮样式。**只在用户点击后弹出的确认对话框中，才把它升格为醒目鲜红的主要操作。**

> 这条极重要：把"删除"做成常驻的红色实心按钮，是 AI 生成界面最典型的事故之一。

### 工程落地（Tailwind 示例）

```html
<!-- ❌ 语义化陷阱：三个操作全是实心 -->
<button class="bg-red-600 text-white px-4 py-2 rounded">Delete Listing</button>
<button class="bg-blue-600 text-white px-4 py-2 rounded">Edit</button>
<button class="bg-green-600 text-white px-4 py-2 rounded">Publish</button>

<!-- ✅ 金字塔：主实心 / 次线框 / 辅文本 -->
<button class="text-slate-500 hover:text-slate-700 text-sm">Delete Listing</button>
<button class="border border-slate-300 text-slate-700 px-4 py-2 rounded-lg">Edit</button>
<button class="bg-slate-900 text-white px-4 py-2 rounded-lg">Publish</button>
```

**判据**：数一数页面上"最重"的元素有几个。**超过一个，就是没有主次。**

---

## 本章速记

1. 层级 = **字重 + 颜色**，不只靠字号
2. 突出不了主角 → **去弱化配角**
3. 数据展示**删标签**，规格表**留标签**
4. 按钮按**重要性金字塔**分级，不按语义分级
