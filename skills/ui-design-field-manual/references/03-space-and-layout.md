# 03 ｜ 空间与布局：留白做减法与拒绝过度拉伸

> 覆盖 **规则 07–10**。这一章解决"页面很挤 / 很空 / 很散 / 手机上炸开"。

---

## 规则 07：从"过度留白"开始

想让设计更整洁清爽，最简单的方法之一，就是**给每个元素多留出一点"呼吸"的空间**。

但平时我们的常规做法几乎总是**为设计"加"留白**——哪里太挤了，就稍微加一点 margin / padding，直到看起来顺眼为止。

**这种"加法"思路的问题**：元素往往只获得了"不至于看起来太糟糕"所需的**最小空间**。而要让设计真正出色，你通常需要**多得多的留白**。

### 正确的做法是反其道而行之

> **先给元素远超所需的空间，然后再慢慢收紧减少，直到你对结果满意为止。**

在实践中你会发现：当你聚焦于单个元素时感觉"**有点多**"的留白，放到整个界面的大背景下，效果往往是"**刚刚好**"。

### 工程落地

- 起步时先把 `padding` 设成直觉值的 **1.5–2 倍**，再往回收
- 卡片内边距不要低于 `24px`（移动端不低于 `16px`）
- 页面主内容区上下留白给足，别让内容贴着视口边缘

- ❌ 优化前：内边距与间距紧凑逼仄，内容紧贴卡片边框，呼吸感极差
- ✅ 优化后：先给足充裕留白再适度收紧，内容松弛舒展，品质感跃然而出

## 规则 08：不必非得填满整个屏幕

还记得 960px 曾是桌面设计的事实标准宽度吗？如今我们在高分辨率显示器上起手就建一个 1200–1400px 宽的画布。但请记住：

> **拥有空间，不代表你就必须用满它。**

如果你只需要 **600px** 的宽度来展示表单或内容，那就**只用 600px**。刻意拉伸布局、把元素做得过宽，**不仅不会显得大气，反而会让界面稀疏散乱、难以阅读**。

在屏幕边缘留出额外的留白总是有益无害的。**不要仅仅因为导航栏是全宽的，就把界面里的所有区块都强行撑满。**

### 如果在大画布上设计小界面束手无策

**先缩小画布**（例如从 400px 左右的移动端宽度开始设计）。当你对小界面的紧凑布局满意后，再把它放进大屏幕；或者通过**分栏**把辅助信息拆分到侧栏。

**给每个元素它真正需要的空间就好。**

### 工程落地

```css
/* ❌ 表单机械撑满 */
.form { width: 100%; }

/* ✅ 按内容需求约束最大宽度 */
.form { width: 100%; max-width: 32rem; }      /* 512px，表单最佳区间 */
.prose { max-width: 65ch; }                    /* 正文 45–75 字符 */
```

常见最大宽度参考：

| 内容类型 | max-width |
|---|---|
| 表单 / 登录框 | 28–32rem（448–512px） |
| 正文段落 | 60–70ch |
| 仪表盘主内容 | 72–80rem（1152–1280px） |
| 全宽区块的内层容器 | 同主内容，**不要跟着导航栏一起撑满** |

- ❌ 优化前：表单元素机械撑满屏幕，输入框横向过度拉伸，阅读与操作体验极差
- ✅ 优化后：按内容需求约束最大宽度，表单紧凑聚合，阅读与输入极为舒适

## 规则 09：间距的"亲疏"之别

用边框或背景色把几组元素明确分开时，归属关系一目了然。但**如果没有这类明确的分割，元素之间的关系就很容易模糊**。

### 两个经典场景

1. **表单**：如果标签下方的间距，和输入框下方的间距完全一样，标签和对应输入框之间就**缺少"归属感"**。用户需要费力辨认，甚至可能把信息填错地方。
2. **排版**：如果章节小标题离上一段的距离，和离下一段的距离一样近，标题就**无法明确归属于下文**。

### 黄金法则

> **当你需要用间距来组织元素时，组与组之间的间距，一定要大于组内元素之间的间距。**

**增大模块之间的间隔、收紧同组元素之间的距离**，无需添加任何辅助线条，内容的归属感就会瞬间清晰自明。

### 工程落地

```css
/* ❌ 一律 16px，归属模糊 */
.field { margin-bottom: 16px; }

/* ✅ 组内 8px，组间 32px（4 倍） */
.field-label      { margin-bottom: 8px; }   /* 标签 ↔ 输入框：组内 */
.form-group       { margin-bottom: 32px; }  /* 字段组 ↔ 字段组：组间 */
```

**推荐比例：组间距 = 组内距的 2–4 倍。** 宁可差距大一点，也不要"差不多"。

- ❌ 优化前：标签与输入框间距、输入框与下一组间距完全均等，归属关系模糊割裂
- ✅ 优化后：缩紧组内距、拉开组间距，信息结构逻辑绑定一目了然

## 规则 10：等比缩放并非总是有效

我们很容易想当然地认为，界面中所有元素都该按**固定比例**缩放。

比如大屏幕上正文 18px、标题 45px（2.5 倍），于是很自然地用 `2.5em` 定义标题，以为这样能保证所有设备比例一致。

**但问题来了**：移动端为保证合适行长把正文缩到 14px 时，标题仍按 2.5em 缩放，就会算出 **35px**——**这在手机屏幕上显得过于庞大、笨拙，且极易折行撑爆屏幕**。

> 小屏幕上，更合适的标题字号可能是 **20–24px**（仅为正文的 **1.5–1.7 倍**）。

### 基本原则

> **在大屏幕上尺寸越大的元素，缩放到小屏幕时，其缩小的比例也应该越大。**
> **大元素和小元素之间的尺寸差距，在小屏幕上应该被主动收敛。**

抛开"万物皆需等比缩放"的执念，给各个元素独立微调的自由，你的移动端设计才会自然舒适。

### 工程落地

| 元素 | 桌面 | 移动端 | 缩放比 |
|---|---|---|---|
| 正文 | 18px | 14–16px | ≈ 0.8 |
| H2 | 45px | 20–24px | ≈ 0.5 |
| H1（Hero） | 64px | 32–36px | ≈ 0.5 |

**规律：字号越大，缩得越狠。** 不要用单一 `clamp()` 比例通吃所有层级。

- ❌ 优化前：移动端机械套用桌面端 2.5em 相对比例，标题 35px 巨大拥挤、两行撑爆屏幕
- ✅ 优化后：打破等比缩放执念，小屏标题独立收敛至 20–24px，整体比例和谐自然

---

## 本章速记

1. 留白**先加后减**，起步给 1.5–2 倍
2. 内容**按需约束宽度**，不因为导航栏全宽就全宽
3. **组间距 > 组内间距**（2–4 倍）
4. **大元素在小屏要缩得更狠**，拒绝等比缩放执念
