# UI 设计军规

**核心判断**：AI 写出来的界面丑，从来不是"艺术细胞"问题，而是**视觉秩序缺失**。间距没有刻度、层级只靠字号、颜色生搬硬套、边框到处乱画、假数据一眼假、按下按钮毫无反应——这些都是可以被规则约束、被检查、被修正的工程问题。

本技能把这套秩序固化成 **26 条军规**（20 条基础 + 6 条进阶），并落成 agent 可执行的四件事：**动手前定基调与骨架 → 分阶段搭视觉 → 做动效 → 交付前自检与独立评审**。

> 方法底座：《Refactoring UI》（Adam Wathan / Steve Schoger）的设计工程化视角 —— 把 UI 设计拆成可计算、可度量、可建立规则的系统体系。

## 什么时候用

出现下面任何信号，主动加载本技能，**不要等用户说"帮我美化"**：

- 用户要新建或改动**任何有界面的东西**：页面、组件、卡片、表单、列表、表格、导航、弹窗、仪表盘、落地页、定价页、后台、小程序页面、邮件模板
- 用户抱怨成品观感：「太丑了」「一股 AI 味 / AI 塑料风」「看着廉价」「草台班子」「不高级」「颜色好乱」「太挤了」「排版难受」「界面很平没有重点」「假数据一眼假」「图标太普通」「一点动效都没有」
- 用户要求做**设计评审 / UI 自检 / 视觉走查**，或问「这个界面能不能上线」
- 用户想建立**设计令牌 / 设计系统 / 风格规范**（字号、行高、间距、色阶、圆角、阴影）
- 你自己**即将写界面代码**（HTML / CSS / Tailwind / React / Vue / 小程序 WXSS）——这是最主要的触发点

## 不适用

- 纯逻辑、纯数据、纯后端、CLI / 脚本，没有视觉界面 → 不加载
- 用户要的是品牌 VI / 平面海报 / 插画创作 → 属于视觉设计而非界面设计，本技能的规则只覆盖界面
- 用户只要一段"设计科普"，不需要落到代码或评审结论 → 直接回答即可

## 四条铁律（其余规则都是它们的展开）

1. **先定基调，再动手。** 字体气质、色彩倾向、圆角大小、文案语气四项一旦选定，整个界面保持一致。**模糊词（高级 / 精致 / 克制）必须先翻译成可观察的决定**（规则 21）。没有基调就开始写代码，等于让每个组件各说各话。
2. **先定首屏骨架，再写文案。** 骨架必须在写任何文案之前决定，否则必然滑向"左边大标题 + 右边一张装在圆角卡片里的产品界面"（规则 22）。
3. **先灰度，后上色。** 骨架阶段只用黑白灰 + 字重 + 间距 + 尺寸把层级交代清楚；颜色只在最后用来**强化关键操作与核心状态**，不用来救场。
4. **交付前必须自检，能派独立评审就派。** 界面"能跑"不等于"能交付"。按 [templates/UI-自检清单.md](templates/UI-自检清单.md) 过一遍，把不合格项当场改掉；有隔离的、能看图的执行者时，**再派一个独立评审**（规则 26）。

## 工作流

### 第 0 步：判断用户要什么（一次问全，别挤牙膏）

| 用户意图 | 走哪条路 | 最少要问出 |
|---|---|---|
| 「帮我做/改一个页面/组件」 | **生产**：走第 1–10 步 | 给谁用 · 产品气质（专业稳重 / 亲和活泼 / 极简克制）· 有没有品牌色 · 技术栈（Tailwind / 原生 CSS / 小程序…） |
| 「这个界面为什么丑 / 帮我评审」 | **诊断**：直接跳第 10 步 | 截图或代码 · 目标用户 · 最在意的问题（层级 / 间距 / 颜色 / 内容 / 细节） |
| 「帮我定一套设计规范 / 令牌」 | **建体系**：直接跳到 [references/08-engineering-parameters.md](references/08-engineering-parameters.md) | 品牌主色 · 产品气质 · 目标平台（Web / 小程序 / 移动端）· 是否需要深色模式 |

> **允许先假设后确认**：用户答不全时，按「专业稳重、中性灰 + 单一主色、8px 间距刻度」这套安全默认起步，把假设**明确写出来**并标 `待确认`，**不要因为信息不全就不产出**。

### 第 1 步：定基调（规则 01–02、21）

先用 [templates/设计基调卡.md](templates/设计基调卡.md) 把四项钉死：**字体 · 色彩倾向 · 圆角 · 措辞**。

- **规则 01 为设计选择一种个性**：衬线 = 优雅古典；圆体无衬线 = 俏皮；中性无衬线 = 简约克制。蓝 = 稳妥专业；金 = 昂贵精致；粉 / 亮色 = 有趣。小圆角 = 中性；大圆角 = 活泼；直角 = 严肃正式。
- **规则 02 别着急上色**：先灰度设计，逼自己只用**间距、对比度、字重、尺寸**完成全部核心设计工作。骨架稳了再上色，效果水到渠成。
- **规则 21 模糊词必须翻译成决定**：用户说「高级 / 精致 / 克制 / 简洁」时，**先翻译成可观察的决定**（色相数量上限、网格公差、强调色占比 ≤10%、阴影最多几级），再动手。**翻译不出来的词从理由里删掉。**

详见 [references/01-style-and-start.md](references/01-style-and-start.md) 与 [references/09-design-direction.md](references/09-design-direction.md)。

### 第 2 步：定首屏骨架（规则 22）

**先回答一个问题：用户来首屏是看什么、做什么？**

- **来看内容 / 挑东西 / 干活的页面**（画廊、商店、信息流、文档、后台、工具）→ **首屏就是第一排内容本身**，导航 + 标题 + 筛选合计不超过一两行，不放首屏口号。
- **来说服人的页面**（落地页、品牌页、发布页）→ 才从 8 种骨架里选一个（满版图像压字 / 居中单一物件 / 画面即界面 / 满版文字 / 通栏上下堆叠 / 网格拼贴 / 纵排或斜向 / 左右分栏）。

**硬规则**：同一轮里骨架互不相同；**左右分栏最多出现一次**；骨架定好再写文案。

详见 [references/09-design-direction.md](references/09-design-direction.md)。

### 第 3 步：搭视觉层级（规则 03–06）

- **规则 03 字号并非万能**：别靠字号拉开层级。用**字重**（600/700）强调重点，用**颜色**（中灰 / 浅灰）弱化次要，而不是把辅助文字缩到看不清。全套只用**两到三种文字颜色 + 两种字重**。
- **规则 04 通过弱化来凸显重点**：目标元素不够突出时，**不要给它加戏，去给竞争者静音**——把未选中项调浅、降字重，让它们退成背景。
- **规则 05 不到万不得已别用标签**：数据展示界面不要"标签: 数据值"平摊权重。格式能自明（邮箱 / 电话 / 价格）或上下文能自明（姓名下方的"客户支持"）就删掉标签，把关键识别信息加大加粗置顶。
- **规则 06 别让语义决定按钮样式**：按**重要性金字塔**设计——主要操作实心高亮、次要操作线框 / 浅底、辅助操作纯文本链接。破坏性操作（删除）若非当前主任务，也先降级，只在确认弹窗里升格为醒目主按钮。

详见 [references/02-visual-hierarchy.md](references/02-visual-hierarchy.md)。

### 第 4 步：空间与布局（规则 07–10）

- **规则 07 从"过度留白"开始**：先给远超所需的留白，再慢慢收紧，直到满意。聚焦单个元素时觉得"有点多"的留白，放到整个界面里往往"刚刚好"。
- **规则 08 不必填满整个屏幕**：需要 600px 就只用 600px。**约束内容最大宽度**，不要因为导航栏是全宽就把所有区块都撑满。
- **规则 09 间距的"亲疏"之别**：**组间距必须大于组内间距**。缩紧组内距、拉开组间距，归属感自然成立，无需画线。
- **规则 10 等比缩放并非总是有效**：大屏幕上越大的元素，缩到小屏时缩小比例应越大。移动端标题不要机械套用桌面端的 2.5em。

详见 [references/03-space-and-layout.md](references/03-space-and-layout.md)。

### 第 5 步：文本与排版（规则 11–12）

- **规则 11 控制行长，动态适配行高**：段落约束在**每行 45–75 字符**（约 20–35em）。行高与行长**成正比**（窄段落 1.5，宽段落 1.8–2.0），与字号**成反比**（大标题收紧到 1.1–1.2）。**禁止全局写死 `line-height: 1.5`。**
- **规则 12 以基线对齐，而非居中**：同一行混排不同字号时，用 `align-items: baseline`，不要用 `center`。小字居中会视觉悬空。
- **中文额外注意**：阅读型页面正文 **16–18px** 起步，产品界面 **14–16px**，高密度工具 **13–14px**；正文行高 **1.6–1.75**。中文断行要主动控制——数字与单位（`38 秒`）、不可拆的词用不换行包起来，行末只剩一两个字算缺陷。

详见 [references/04-type-and-text.md](references/04-type-and-text.md)。

### 第 6 步：色彩与无障碍（规则 13–15）

- **规则 13 你需要的颜色远比想象中更多**：五色方案做不出真实产品。需要**中性灰 8–10 档 + 品牌主色 5–10 档 + 语义强调色各 5–10 档**（红报错 / 黄预警 / 绿成功 / 青或紫新功能）。
- **规则 14 无障碍不一定难看**：彩色小标签不要用"深底白字"，改用**浅底深字（反转对比）**——浅黄底 + 深金棕字。既满足 WCAG 4.5:1，又柔和融入。
- **规则 15 不要只靠颜色传递信息**：涨跌、状态必须**颜色 + 图形符号双通道**（箭头 / 三角 / 勾选 / 感叹号）。颜色只是强化，不能是唯一手段。

**配色两问自检**（过不了就回产品重找）：① 去掉所有发光和模糊后，配色还成立吗？② 能说出一个用类似配色的成功产品或出版物吗？——这组颜色是从产品内容 / 用户 / 品牌推出来的，还是放在哪个产品上都不出错的安全色？

详见 [references/05-color-and-a11y.md](references/05-color-and-a11y.md)。

### 第 7 步：质感、图片与图标（规则 16–18、24）

- **规则 16 用强调色边框为设计添彩**：在平淡的卡片顶部、选中导航项、提示框侧边加一道彩色条，用最小视觉代价换来焦点与设计感（**一个页面不超过 2–3 处**）。
- **规则 17 图片上的文字需要稳定的对比度**：问题在背景不在文字。叠加半透明深色蒙版（`rgba(0,0,0,.4~.6)`）、降低图片对比度、或品牌单色正片叠底，再配柔和的文字光晕阴影。
- **规则 18 万物皆有其适用尺寸**：不要把 24px 图标拉到 64px（线条会变得笨拙粗壮），正确做法是**保持图标原尺寸，外包一个浅底色圆形容器**。也不要把完整网页截图缩 70% 塞进小卡片。
- **规则 24 图标是一套语言，不是默认值**：模型的默认永远是 Lucide / Heroicons（24px、2px 描边、圆头）。**按方向气质换一套**（精致→Phosphor Thin；工业→Carbon / Radix；中文业务→IconPark），**描边粗细跟字重走**（细字 1–1.5px，粗黑体 2px+ 或实心）。能不用就不用——`→` `↗` `※` `§`、编号也是表达。

详见 [references/06-texture-and-imagery.md](references/06-texture-and-imagery.md) 与 [references/10-icons-motion-review.md](references/10-icons-motion-review.md)。

### 第 8 步：细节与内容（规则 19–20、23）

- **规则 19 慎用边框**：别急着画 1px 灰线。先用**背景色差**（页面 `#f8fafc` / 卡片 `#ffffff`）、**留白间距**、**微弱阴影**来分区。界面布满网格线会像噪点爆炸的 Excel。
- **规则 20 别忽视"空状态"**：空状态要**优先设计**。① 提供清晰的 CTA（友好插画 + "创建你的第一个项目"按钮）；② **隐藏无关的空壳控件**（标签页 / 筛选器 / 排序在首条内容出现前没有意义）。**加载态与错误态同样不能漏。**
- **规则 23 示例数据要像真的**：避开整数指标（1,000 位用户 / +10%）、张三李四、每条都是"2 小时前"、写着「标题」「描述」的占位字。真实数据是不整齐的（**1,238 位用户**、**+1.83%**、"昨天 16:12"）；按钮说具体动作（「保存草稿」而不是「提交」）；多个演示共用一个虚构世界。**画面上不出现「示例」「示意图」「未接入」这类制作说明。**

详见 [references/07-details-and-empty-state.md](references/07-details-and-empty-state.md) 与 [references/09-design-direction.md](references/09-design-direction.md)。

### 第 9 步：做三处动效（规则 25）

完全不动的界面像一张截图。**新界面和改动了操作流程的界面**，先把这三处做出来：**① 主操作的反馈**（按下立即生效，完成时交出结果）｜**② 一处状态切换的来路**（东西从哪来、到哪去）｜**③ 首次进入时的一次出场**。

手感用「**动作 + 实物**」定参数：`咔嗒`=磁铁吸合（刚度 350–400 / 阻尼 10–15）、`滑入`=抽屉阻尼（250–300 / 20–25）、`流淌`=倒蜂蜜（150–200 / 30–40）。过冲幅度跟面积走：大面积 ≤1–2%，小物件 10–20%。

**静态截图证明不了动效** —— 要留 3–5 秒录屏或开始 / 中间 / 结束三帧。

详见 [references/10-icons-motion-review.md](references/10-icons-motion-review.md)。

### 第 10 步：自检 + 独立评审（**不许跳过**）

1. 打开 [templates/UI-自检清单.md](templates/UI-自检清单.md)，逐条核对。**不合格的项当场改掉再交付**，并在回复里用一句话说明改了什么。
2. **有隔离的、能看图的执行者时，派一个独立评审**（规则 26）：新上下文、只看画面不看代码、10 分制且**必须附带具体差距**。**没有就自检，并明确标注「未独立评审」。**

需要具体数值（间距刻度、字号行高配对表、色阶生成法、对比度校验）时，读 [references/08-engineering-parameters.md](references/08-engineering-parameters.md)。

## AI 塑料风的 11 个典型症状（先自我诊断）

写出界面后，出现下列任何一条，说明骨架没搭对：

| 症状 | 违反 | 怎么修 |
|---|---|---|
| 满屏紫蓝渐变 + 玻璃拟态 + 到处发光阴影 | 规则 02 | 退回灰度骨架，颜色只留一处主色 |
| 层级全靠字号，辅助文字小到 12px 还发灰 | 规则 03 | 改字重 + 颜色做层级，字号收敛 |
| 所有间距都是 16px，卡片里外一样 | 规则 09 | 组间距 = 组内距的 2–3 倍 |
| 每个区块都套 1px 灰边框 | 规则 19 | 删线，改背景色差 + 留白 |
| 三个按钮全是高饱和实心 | 规则 06 | 按金字塔分级：实心 / 线框 / 文本 |
| 段落横跨 1400px 全宽，行长 200+ 字符 | 规则 08 / 11 | 约束 max-width，行长收到 45–75 字符 |
| 图标被拉大、截图被缩小，比例失调 | 规则 18 | 保持原尺寸，用容器填充空间 |
| **首屏左边大标题 + 按钮，右边一张装在圆角卡片里的产品界面** | 规则 22 | 换骨架表里的其他骨架，或让产品界面占满首屏 |
| **假数据是整数 + 张三李四 + "2 小时前"** | 规则 23 | 换成不整齐的真实数据 |
| **图标还是 Lucide 默认的 24px / 2px 圆头描边** | 规则 24 | 按气质换一套，描边跟字重走 |
| **按下按钮、切换标签、增删列表毫无反应** | 规则 25 | 补三处基本动效 |

## 26 条军规速查表

### 基础 20 条

| # | 规则 | 一句话判据 |
|---|---|---|
| 01 | 为你的设计选择一种个性 | 字体 / 色彩 / 圆角 / 措辞四项，全站一致 |
| 02 | 别着急上色 | 灰度下能读懂层级，才算骨架成立 |
| 03 | 字号并非万能 | 层级 = 字重 + 颜色，不只靠字号 |
| 04 | 通过弱化来凸显重点 | 突出不了主角，就去弱化配角 |
| 05 | 不到万不得已别用标签 | 格式或上下文能自明，就删标签 |
| 06 | 别让"语义"决定按钮样式 | 主要实心 / 次要线框 / 辅助文本 |
| 07 | 从"过度留白"开始 | 先给多，再收紧 |
| 08 | 不必非得填满整个屏幕 | 内容宽度按需约束，不撑满 |
| 09 | 间距的"亲疏"之别 | 组间距 > 组内间距 |
| 10 | 等比缩放并非总是有效 | 大元素在小屏要收得更狠 |
| 11 | 控制文本行长，动态适配行高 | 行长 45–75 字符，行高随行长与字号变 |
| 12 | 以基线对齐，而非居中 | 混排用 `align-items: baseline` |
| 13 | 你需要的颜色远比想象中更多 | 中性 8–10 档 + 主色 5–10 档 + 语义色 |
| 14 | 巧用"浅底深字" | 浅底深字（反转对比），不用深底白字 |
| 15 | 不要只靠颜色传递信息 | 颜色 + 图标双通道 |
| 16 | 用强调色边框为设计添彩 | 一道彩条，最小代价换焦点 |
| 17 | 图片上的文字需要稳定的对比度 | 治背景：蒙版 / 降对比 / 单色叠底 |
| 18 | 万物皆有其适用尺寸 | 图标不放大，截图不缩小 |
| 19 | 慎用边框 | 先试背景色差、留白、阴影 |
| 20 | 别忽视"空状态"的设计 | 空状态优先设计，给 CTA 并隐藏空壳控件 |

### 进阶 6 条

| # | 规则 | 一句话判据 |
|---|---|---|
| 21 | 模糊词必须翻译成决定 | 「高级 / 克制」→ 色相上限、网格公差、占比预算 |
| 22 | 先定首屏骨架，再写文案 | 内容页首屏就是第一排内容；左右分栏一轮最多一次 |
| 23 | 示例数据要像真的 | 不整齐的指标、有层次的时间、说具体动作的按钮 |
| 24 | 图标是一套语言，不是默认值 | 按气质选库，描边跟字重走，能不用就不用 |
| 25 | 每个界面先做三处动效 | 主操作反馈 / 状态切换来路 / 首次出场 |
| 26 | 交付前派一次独立评审 | 隔离上下文、只看画面、10 分制且必须说清差距 |

## 输出规范

- **要代码就给能跑的代码**：直接产出 HTML / CSS / Tailwind / WXSS，把设计令牌以 CSS 变量或 Tailwind `@theme` 的形式写进去，不要只给一段描述
- **要评审就给可执行的结论**：按「问题 → 违反哪条规则 → 具体怎么改（给出改后的值 / 类名 / 代码片段）」三段式输出，**不要只说"这里不太好看"**
- **独立评审单独输出**：评审意见按「位置 / 观察与证据 / 影响 / 建议 / 验证」五项写，**分数必须附带具体差距**；没有独立评审条件时明确标注
- **产物落盘**：设计令牌默认写到 `styles/design-tokens.css`（或项目既有的主题文件）；基调卡、自检报告与评审记录默认写到 `docs/ui-review/<页面名>.md`。**项目已有目录约定就跟随，不要另起一套**
- **数值给具体值**：`padding: 24px`、`line-height: 1.6`、`gap: 32px`，不要写"适当留白""稍微大一点"
- **一次只改一处主要问题**：评审时按影响面排序，先说结构性错误（骨架、层级、间距、宽度），再说细节（圆角、阴影）
- **语言跟随用户**；用户用中文就用中文
