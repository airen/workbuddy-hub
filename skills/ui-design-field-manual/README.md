# UI 设计军规（ui-design-field-manual）

用 **26 条可工程化的视觉军规**，治住 AI 生成界面的「塑料风 / 草台班子感」，让 agent 写出来的页面达到可交付的商业水准。

**核心判断**：AI 写出来的界面丑，从来不是"艺术细胞"问题，而是**视觉秩序缺失**。间距没有刻度、层级只靠字号、颜色生搬硬套、边框到处乱画、假数据一眼假、按下按钮毫无反应——这些都是可以被规则约束、被检查、被修正的工程问题。

方法底座：《Refactoring UI》（Adam Wathan / Steve Schoger）的设计工程化视角。

## 26 条军规分两部分

**基础 20 条**（整理自《Refactoring UI》与公开文章《人人都是 UI 设计师》）——覆盖基调、视觉层级、空间布局、文本排版、色彩无障碍、质感图片、细节与空状态。

**进阶 6 条**（本技能针对 agent 生成界面的高频失败补充）——这 6 条是 AI 界面最容易被一眼识破的地方：

| # | 规则 | 解决什么 |
|---|---|---|
| 21 | 模糊词必须翻译成决定 | 用户说「高级 / 克制」，到底指什么？ |
| 22 | 先定首屏骨架，再写文案 | 为什么每个 AI 页面都是"左标题右卡片"？ |
| 23 | 示例数据要像真的 | 为什么一眼就看出是假的？ |
| 24 | 图标是一套语言，不是默认值 | 为什么每个 AI 页面都是 Lucide？ |
| 25 | 每个界面先做三处动效 | 为什么界面像一张截图？ |
| 26 | 交付前派一次独立评审 | 自己判自己的卷，判得准吗？ |

## 三端安装

| 平台 | 做法 |
|---|---|
| **WorkBuddy** | 把 `ui-design-field-manual/` 整个目录拷到 `~/.workbuddy-ai/skills/`，重启后在对话里说「帮我做个好看的页面」即自动触发。或从应用市场直接安装。 |
| **Claude Code** | 把 `ui-design-field-manual/` 拷到 `~/.claude/skills/`（个人级）或项目内 `.claude/skills/`（项目级）。`SKILL.md` 的 frontmatter 是标准 Agent Skills 格式，Claude 按 `description` 自动触发。 |
| **Codex / Cursor** | 把 `AGENTS.md` 拷到项目根目录（或 `~/.codex/AGENTS.md` 作为全局），agent 写界面时即按规则约束自己。若同时保留 `references/`、`templates/`，AGENTS.md 会引用到它们。 |

> 三个平台读的是同一套规则内核，只是入口文件不同：WorkBuddy 与 Claude 读 `SKILL.md`，Codex 系读 `AGENTS.md`。

## 用法示例

- 「帮我做个 SaaS 落地页」→ 先出设计基调卡，定首屏骨架，再按 10 步搭骨架，交付前跑 61 项自检
- 「这个登录页看着好廉价」→ 按「问题 → 违反哪条规则 → 具体怎么改」输出可执行结论
- 「帮我定一套设计令牌」→ 产出 `design-tokens.css`（间距刻度 / 字号行高配对 / 色阶 / 圆角 / 阴影）
- 「这个表格怎么这么挤」→ 命中规则 09（组间距 > 组内距）与规则 08（约束最大宽度）
- 「帮我评审一下这个页面」→ 跑独立评审协议，输出「位置 / 观察 / 影响 / 建议 / 验证」五项 + 10 分制评分
- 「假数据怎么写得像真的」→ 命中规则 23

## 设计哲学

**规则不是审美偏好，是工程约束。** 26 条军规里没有一条依赖"艺术天分"：

- 先灰度后上色 = 解耦骨架排版与视觉渲染的**工程分层**
- 亲疏法则与基线对齐 = 格式塔心理学与阅读生理学的**忠实体现**
- 强调色边框 = 用最小视觉代价建立焦点的**注意力工程**
- 浅底深字与双通道传达 = 信息工程的**容错与无障碍覆盖**
- 独立评审协议 = 把"自己判卷"换成**独立复核**
