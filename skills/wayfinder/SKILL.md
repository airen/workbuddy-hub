# 寻路（wayfinder）

一个模糊的想法到来了，大到一次 agent 会话装不下，还裹在迷雾里：从这里到**目的地（destination）**的路还看不见。寻路（wayfinding）就是找到那条路，而不是朝着目的地猛冲。本技能把这条路绘制成一份挂在仓库 issue tracker 上的**共享地图（shared map）**，然后一次一个地推进它的**决策票据（decision tickets）**（这些问题是「解决它等于做一个决策」，而不是待执行的构建切片），直到路线清晰。

目的地因任务而异，给它命名是绘制地图的第一个动作：它塑造了每一张票据。它可能是一份要交接出去并迭代的规格（spec），一个在规划开始前要锁定的决策，或者一处就地进行的改动，比如数据结构迁移。地图与领域无关：工程工作、课程内容，只要形状合适都行。

## 规划，而非执行

寻路默认是**规划**：每张票据解决一个决策，当路已清晰、在有人真正动手之前再无待决之事时，地图就完成了。那种「干脆直接干活」的冲动，通常正是你已经走到地图边缘、该交接了的信号。某个任务可以在它的 **Notes** 里覆盖这一点，把执行也纳入地图本身；但除此之外，产出的是决策，不是交付物。

## 以名字称呼

每张地图和每张票据都是一个 issue，所以它有一个**名字**：它的标题。在人类读到的所有内容里（叙述、地图的 Decisions-so-far），都用那个名字来称呼它，绝不用裸的 id、编号或 slug。一堵 `#42, #43, #44` 的墙是读不下去的；名字一眼就能读懂。id 和 URL 并没有消失；名字会包住它的链接，但它们藏在名字_里面_，绝不代替名字。

## 地图（The Map）

地图是这个仓库 issue tracker 上的单个 issue，标签为 `wayfinder:map`，是权威产物（canonical artifact）。它的票据是地图的子 issue。

地图是一份**索引（index）**，不是仓库。它列出已做出的决策，并指向持有其细节的票据；一个决策只存在于一个地方，也就是它的票据里，所以地图从不复述它，只给个要点并链接过去。

**地图、它的子票据、阻塞关系、前沿查询在物理上存在哪里，是 tracker 专属的。** issue tracker 本应已经提供给你。如果没有，就提示用户运行 `setup-matt-pocock-skills` 技能。查阅 tracker 文档的「Wayfinding operations」一节，了解_这个_仓库如何表达它们。如果没有提供任何 tracker，默认使用 local-markdown tracker。

### 地图正文（The map body）

整张地图的低分辨率视图，每个会话加载一次。开放的票据**不**列在这里：它们是开放的子 issue，通过查询找到。

```markdown
## Destination

<走到这张地图终点是什么样子：这个任务正在寻路抵达的规格、决策或改动。一到两行；每个会话在选票据之前都要先对齐它。>

## Notes

<领域；每个会话都该查阅的技能；这个任务的常设偏好>

## Decisions so far

<!-- 索引：每个已关闭票据一行，足够判断相关性，再顺着链接放大到票据所持有的细节 -->

- [<已关闭票据的标题>](link): <答案的一行要点>

## Not yet specified

<!-- 见「战争迷雾（Fog of war）」：范围内、但还无法立票据的迷雾；随着前沿推进而毕业 -->

## Out of scope

<!-- 见「超出范围（Out of scope）」：被判定在目的地之外的工作；关闭，永不毕业 -->
```

### 票据（Tickets）

每张票据都是地图的一张**子 issue**；tracker 的 issue id 就是它的身份。它的正文就是那个问题，大小以一次 100K token 的 agent 会话为限：

```markdown
## Question

<这张票据要解决的决策或调查>
```

每张票据带一个 `wayfinder:<type>` 标签，取值之一是 `research`、`prototype`、`grilling`、`task`（见[票据类型](#票据类型)）。

一个会话**认领（claim）**一张票据的方式，是在任何工作之前**先**把它指派给驱动这张地图的开发者，这样并发的会话就会跳过它。那个受指派人_就是_认领：一张开放的、未指派的票据就是未被认领的。

阻塞使用 tracker 的**原生（native）**依赖关系：这一点至关重要，因为它把前沿_可视化地_渲染在 tracker 自己的 UI 里，于是人类不用打开地图就能看到哪些可以拿。只有缺少原生阻塞的 tracker 才退回到正文约定。当阻塞某张票据的每一张票据都已关闭时，这张票据就是**未阻塞的（unblocked）**；**前沿（frontier）**就是开放的、未阻塞的、未被认领的子票据，也就是已知世界的边缘。

答案不属于正文；它在解决时被记录（见[推进地图](#推进地图)）。解决一张票据期间创建的资产从 issue 链接过去，而不是粘贴进来。

## 票据类型（Ticket Types）

每张票据要么是 **HITL**（human in the loop，与一个替自己说话的人类_一起_工作），要么是 **AFK**（由 agent 独自驱动）。一张 HITL 票据只能通过那场实时交流来解决；agent 绝不代替人类那一方（一个自问自答的拷问 agent 已经破坏了这一点）。

- **Research**（AFK）：阅读文档、第三方 API，或本地资源（如知识库），以找出某个决策正在等待的事实。由一个子代理（用 Agent 工具）调用 Skill 工具加载 `research` 技能来解决。当需要当前工作目录之外的知识时使用。
- **Prototype**（HITL）：通过做一个廉价、粗糙、具体的产物来提升讨论的保真度（一份大纲、一个粗略方案、一个桩，或 UI/逻辑代码），方式是调用 Skill 工具加载 `prototype` 技能。把这个原型作为资产链接进来。当「它应该长什么样」或「它应该如何表现」是核心问题时使用。
- **Grilling**（HITL）：对话。默认情况。始终依次调用 Skill 工具加载 `grilling` 和 `domain-modeling` 两个技能。
- **Task**（HITL 或 AFK）：在一项_决策_能做出来之前必须完成的手工工作：没有什么要决策、要原型、要研究，但讨论会一直阻塞到它做完为止。比如注册一个服务以便评判它的 API、开通访问权限、搬动数据以便看清它的形状。这是唯一一种_做事_而非做决策的类型，它靠解开某个决策的阻塞来赢得位置，而不是靠交付目的地。agent 能独自驱动时就独自驱动（AFK）；否则交给人类一份精确的清单（HITL）。工作完成时即解决；答案记录做了什么，以及后续票据所依赖的任何衍生事实（凭据位置、新 URL、行数）。

## 战争迷雾（Fog of war）

地图是_刻意_不完整的：不要绘制你还看不见的东西。在活的票据之外躺着**战争迷雾（fog of war）**：那些你能看出正在到来、却还无法钉死的决策与调查的模糊轮廓，因为它们悬在仍然开放的问题上。解决一张票据会清掉它前方的迷雾，把此刻已可规格化的东西毕业成新的票据，一次一个，直到通往目的地的路清晰、不再有票据留下。

地图的 **Not yet specified** 小节就是写下那幅模糊轮廓的地方：疑似的问题、日后要重新查看的区域。它是_朝向_目的地的、尚未被发现的前沿：这里的一切都在范围内，只是还不够锐利、不足以立成票据。视图允许多松就写多松，允许多全就写多全；它同时也是一块路标，供协作者阅读这项任务正走向何方。

**是迷雾还是票据？** 判据是你_现在_能不能把这个问题精确陈述出来，而_不是_你_现在_能不能回答它。

- **能立成票据**：当这个问题已经足够锐利，即便它被阻塞、你还动不了它。
- **归入 Not yet specified**：当你还无法把问题表述得那么锐利。不要把迷雾预先切成票据大小的小块：它比一张票据更粗，一块迷雾在前沿抵达它时，可能毕业成好几张票据，也可能一张都不毕业。

**Not yet specified** 排除掉已经决定的东西（Decisions so far）、已经是活票据的东西，以及超出范围的东西（下一节）。

## 超出范围（Out of scope）

迷雾只会_朝向_目的地聚集。目的地确定了范围，所以超出它的工作就是**超出范围（out of scope）**：它不是迷雾，也不属于 **Not yet specified**。它在地图上拥有自己的 **Out of scope** 小节：你已经有意识地判定_这_项任务不做的工作。把它放在这里靠的是范围，不是锐利度。

超出范围的工作永不毕业（前沿止于目的地），所以只有当目的地被重新划定它才会回来，而且那时是作为一项全新任务，而不是续接。

把某样东西判定为超出范围是一个划定范围的动作，不是路线上的一个步骤。当一张已经存在的票据原来坐落在目的地之外时（绘制地图时划错了进来，或被某次解决暴露出来），**关闭它**（一张已关闭的票据明确地不在前沿上），并在 **Out of scope** 小节留一行：要点加上为什么它超出范围，链接到那张已关闭的票据。它不进入 **Decisions so far**，那里记录的是实际走过的路线；一条范围边界不是路线上的一个步骤。

## 调用方式（Invocation）

两种模式。无论哪种，**每个会话绝不解决超过一张票据**，研究票据除外。

### 绘制地图

用户带着一个模糊的想法来调用。

1. **给目的地命名。** 依次调用 Skill 工具加载 `grilling` 和 `domain-modeling` 两个技能，钉死这张地图正在寻路抵达的是什么：规格、决策还是改动。目的地确定了范围，所以它最先敲定。
2. **测绘前沿。** 再拷问一次，这次是**广度优先（breadth-first）**：在整个空间里铺开，而不是在任一条线索上深挖，把开放的决定和当下可走的第一步翻出来。**如果这一步没翻出任何迷雾**（通往目的地的路已经清晰，整段旅程小到一次会话装得下），你就不需要地图。停下来，问用户想怎么进行。
3. **创建地图**（标签 `wayfinder:map`）：填好 Destination 和 Notes，Decisions-so-far 留空，把迷雾草草写进 **Not yet specified**。
4. **创建你现在能规格化的票据**，作为地图的子 issue，然后在**第二遍**里连上阻塞边（issue 需要先有 id 才能互相引用）。连边把它们分拣进前沿和被阻塞两堆；一切你还无法规格化的都留在迷雾里：**Not yet specified** 小节。
5. **发射研究子代理。** 对你刚创建的每一张 `research` 票据，起一个子代理（用 Agent 工具）调用 Skill 工具加载 `research` 技能来并行解决它，把发现捕获在一条一次性的 `research/<name>` 分支上，并从票据给出一个上下文指针。
6. 停：绘制地图是一次会话的工作；它本身不解决任何东西。

### 推进地图

用户带着一张地图（URL 或编号）来调用。票据是**可选的**：不指定票据时，由你来挑下一个决策，而不是用户。

1. 加载**地图**：低分辨率视图，不是每张票据的正文。
2. 挑票据。如果用户点了名，就用它。否则按顺序取第一张前沿票据。**认领它**：在任何工作之前把它指派给你自己。
3. 解决它。**按需放大**：按需拉取任何相关或已关闭票据的完整正文；`## Notes` 块点名了哪些技能，就调用 Skill 工具加载哪些技能。如果拿不准，依次调用 Skill 工具加载 `grilling` 和 `domain-modeling` 两个技能。
4. 记录解决结果：把答案作为一条**解决评论（resolution comment）**发出来，**关闭**这个 issue，并向地图的 Decisions-so-far **追加一个上下文指针**。
5. 添加新浮现的票据（先创建、后连边）；把答案已使其可规格化的任何迷雾毕业，从 **Not yet specified** 里清掉每一块已毕业的迷雾，让它只作为新票据存在。如果答案揭示出某张票据（这张或另一张）坐落在目的地之外，**把它判定为超出范围**，而不是在路线上解决它。如果这个决策使地图的其他部分失效，更新或删除那些票据。

用户可能会并行地跑未阻塞的票据，所以要预计其他会话正在并发地编辑 tracker。
