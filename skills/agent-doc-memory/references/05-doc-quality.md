# 05 · 好文档的标准

> 写文档时对照。**一份没人愿意读的文档，和没有文档一样糟。**

## 四条硬判据

### 1. 为什么 > 是什么

代码已经记录了"是什么"：有哪些函数、什么签名、什么数据结构。**你抄一遍，等于写了一本第二天就过期的说明书。**

文档的价值在代码里读不出来的部分：

| 代码里有 | 文档该有 |
|---|---|
| `function refresh(token)` | 为什么要在过期前 5 分钟刷新（而不是 1 分钟） |
| `CREATE INDEX ON orders(user_id)` | 为什么按 user_id 建索引（查询模式是什么） |
| `if (retries > 3) throw` | 为什么是 3（下游的幂等窗口是多久） |
| 用了 Redux | 为什么不用 Context（当时遇到的具体问题是什么） |

**一句话判据**：**这句话，读代码能读出来吗？能 → 删掉。**

### 2. 一份文档一个主题，标题即结论

- 决策记录：**一页一个决策**（不是"2026 年 9 月的技术选型汇总"）
- 调研笔记：**一个库 / 一个 API 一篇**（不是"第三方服务调研大全"）
- 规格：**一个功能一份**

**为什么**：只有当文档能被**一句话引用**时，它才有用。

- ✅「这个按 `decisions/0003-分库方案.md` 来」
- ❌「这个按 `2026-Q3-技术选型汇总.md` 的第 4 节第 2 段来」

标题要**像结论**，不像分类：「订单表按 user_id 分片」好过「分片方案」。

### 3. 开头写清状态

每份文档（除 INDEX）开头三行：

```markdown
> 状态: 现行 ｜ 最后更新: 2026-10-06 ｜ 适用范围: 后端订单服务
```

三个状态词，只用这三个：

| 状态 | 含义 | 处理 |
|---|---|---|
| **现行** | 当前有效，按它做 | 正常引用 |
| **过期** | 曾经有效，现在不一定 | 尽快改对；改之前不引用 |
| **已废弃** | 明确不再有效 | 保留文件（历史价值），**写明被谁取代** |

**留着错的文档比没有文档更糟**——因为它会被当成真相。这是本技能最想强调的一条。

### 4. 不抄代码，只指位置

- ✅「token 刷新逻辑在 `src/auth/session.ts` 的 `refresh()`」
- ❌ 把 `refresh()` 的实现贴进文档

**为什么**：抄来的代码第二天就过期，而且**它开始说谎**——文档说"A 逻辑"，代码里已经是"B 逻辑"，读者不知道信谁。

指位置的方式：

- 路径 + 符号名：`src/auth/session.ts:refresh()`
- 表名 / 接口路径：`POST /api/v1/orders`
- 配置键：`config.retry.maxAttempts`

## 格式约定（保持轻）

- **纯 Markdown**，不用私有格式（否则不可 diff、不可分享）
- **表格用于并列对比**，不要用来塞长段落
- **代码块只用于**：命令、配置片段、最小可用示例、目录树
- **链接用相对路径**：`[决策 0003](../decisions/0003-*.md)`，这样在 git 平台和本地都能点
- **长度**：决策 / 调研 100–300 行；约定按主题分节；规格 50–200 行。**超过 400 行的文档，考虑拆**

---

## 写作语气

**写给同事看，不是写给机器看。** Agent 只是读者之一。

- 说人话，不堆术语（术语要用就进 `glossary.md` 定义）
- 结论先行：第一段就给答案，细节放后面
- 用具体数字：`P99 1.8s`，不是"比较快"
- 承认不确定：「这块我们还没验证」，比编一个确定答案好
- 保留争议：如果当时有分歧，写清"另一派认为……"，未来的你可能需要这个信息

---

## 自检清单

写完一份文档，过一遍：

- [ ] 第一段能让读者知道**结论**吗？
- [ ] 我说清了**为什么**（动机 / 代价 / 边界）吗？
- [ ] 有没有**抄代码**？（有 → 改成指路径）
- [ ] 有 `状态` + `最后更新` + `适用范围` 吗？
- [ ] 标题是**结论**还是**分类**？
- [ ] 这份文档能被**一句话引用**吗？
- [ ] 三个月后我自己还愿意读它吗？

## 反面样本对照

| 差 | 好 |
|---|---|
| 「关于认证的一些说明」（标题是分类，内容杂） | 「移动端改用 JWT 而非 Cookie Session」（标题是结论） |
| 「我们使用了 PostgreSQL」（只写是什么） | 「选 PostgreSQL：需要事务与 JSONB；放弃了 Mongo 的水平扩展便利，代价是分片要自己做」（含代价） |
| 「性能优化记录：改了缓存、加了索引、调了参数」（一锅炖） | 三份独立文档：`research/redis-cache-ttl.md`、`decisions/0005-order-index.md`、`research/pg-conn-pool.md` |
| 贴了一段 80 行的 `refresh()` 实现 | 「`refresh()` 在 `src/auth/session.ts`，提前 5 分钟刷新，因为……」 |
| 「参见 2026-Q3 技术选型汇总第 4 节」（不可引用） | 「参见 `decisions/0003`」（可一句话引用） |
