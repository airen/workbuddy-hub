# ④ 验收与上线：让成果持续产生价值

> 目标：不只是「上线了」，而是「上线之后还能持续产生价值」。验收、发布、交接、复盘，四件事一件都不能省。

**本阶段交付**：验收记录 · 运营交接包 · 复盘报告
**最终目标**：可用、可控、可持续产生价值

四个模块：按标准验收 → 分阶段发布 → 交接与运营 → 收尾与复盘。

---

## 模块 1：按标准验收

要点：

- **用约定场景、评测集与门槛验证**——就是立项时定下的那一套，不是临时新编的
- **联合评估三个维度**：

  | 维度 | 看什么 |
  |---|---|
  | **业务价值** | 业务目标达成了吗 |
  | **模型效果** | 任务成功率、事实准确性达标吗 |
  | **工程质量** | 响应时间、稳定性、单次成本达标吗 |

- **记录遗留问题**，由**授权验收人**确认签字

> 按标准看效果，才算数。

要点补充：验收不通过要写清「差在哪、怎么补、什么时候再验」，而不是含糊过关。

---

## 模块 2：分阶段发布

发布路径：

```text
内部验证 → 小范围试点 → 逐步放量
```

要点：

- **发布前确认**：监控、告警、应急、回滚，四样都要就绪
- **高风险输出保留人工复核与兜底**——AI 会错，关键场景必须有人接住
- **逐步放量**：每放一档都观察指标，出问题能及时收

> 稳步上线，控制风险，创造更大价值。

要点补充：回滚方案必须在发布**前**演练过，不是写在文档里就算有。

---

## 模块 3：交接与运营

要移交的东西：

| 类别 | 具体内容 |
|---|---|
| **技术资产** | 代码、模型配置、提示词及数据说明 |
| **操作资产** | 操作手册、权限、告警配置与责任人 |
| **持续运营** | 跟踪质量退化、成本和用户反馈 |
| **再评测** | 数据或模型变化后重新评测 |

要点：

- 交接**不是发个文档**，要有明确的责任人接收
- **质量退化**是 AI 系统的常态（数据漂移、模型升级），要有人持续盯
- **数据或模型变化后必须重新评测**，不能沿用旧结论

> 持续运营，让价值不断延续。

---

## 模块 4：收尾与复盘

要点：

- **核对**交付、验收记录与合同事项
- **归档**决策、实验、变更和经验教训
- **总结**哪些方法可复用，哪些假设被推翻
- **约定**收益复查时间与业务负责人

复盘要诚实：

- 写「哪些假设被推翻了」比写「我们做得很好」有价值得多
- 结论要落到**可复用的方法**，否则下次还会踩同一个坑
- 收益复查要**定时间、定人**，否则没人回头验证真实价值

> 复盘沉淀，让下一次做得更好。

---

## 阶段收尾：过推进关口

- [ ] 验收用约定场景/评测集/门槛，三维度（业务/模型/工程）都评估过
- [ ] 验收记录有授权验收人确认，遗留问题有处置方案
- [ ] 发布走了「内部验证 → 小范围试点 → 逐步放量」，回滚方案已演练
- [ ] 高风险输出有人工复核与兜底
- [ ] 技术资产与操作资产都完成交接，有明确接收责任人
- [ ] 有质量退化与成本跟踪机制
- [ ] 复盘报告完成，含「被推翻的假设」与「可复用方法」
- [ ] 收益复查已约定时间与业务负责人

**最终目标：可用、可控、可持续产生价值。** 到这一步，项目才算真的落地。
