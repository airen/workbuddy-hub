# ① 立项：先定义价值，再启动开发

> 目标：在写第一行代码之前，把「为谁、解决什么问题、带来什么价值」说清楚，并且把责任落到人、把授权拿到手。

**本阶段交付**：项目章程 · 相关方登记册 · 初步风险清单
**推进关口**：价值明确、责任到人、授权启动

四个模块：业务目标 → 范围边界 → 相关方与责任 → 成功标准。顺序不能反：**先有价值，才有范围；先有范围，才有责任；三者齐了才谈成功标准。**

---

## 模块 1：业务目标

**要回答的问题**：谁在什么场景遇到什么问题？

要点：

- **谁**：具体到角色（一线客服、审核员、运营、家长…），不是「用户」这种空词
- **什么场景**：在哪个流程、哪一步、多频繁
- **什么问题**：现在的痛是什么、代价是什么（时间、成本、错误率、体验）
- **带来什么价值**：把「做一个 AI 助手」改写成**可验证的业务结果**

反例 → 正例：

| 反例（不可验证） | 正例（可验证） |
|---|---|
| 做一个客服 AI 助手 | 把客服平均处理时间缩短 30%，且满意度不低于现状 |
| 用大模型做知识问答 | 让 80% 的常见问题由 AI 一次答对，人工只处理剩下的 20% |
| 做一个 AI 出题工具 | 出题效率提升 5 倍，题目结构校验通过率 ≥ 99% |

**产出**：一段「为谁 / 什么场景 / 什么问题 / 什么价值」的四句陈述，写进项目章程。

---

## 模块 2：范围边界

**要回答的问题**：做什么、不做什么、交付什么、受什么约束？

要点：

- **明确要做**：本期的功能范围，越具体越好
- **明确不做**：本期**明确排除**的东西（这一条最能防止范围蔓延，必须写）
- **交付物**：本期要交出哪些东西（模型、接口、文档、评测集…）
- **约束**：时间、预算、合规、技术栈、数据权限
- **先选一个高价值、可验证的场景**：不要一次铺开，聚焦一个点
- **确认数据来源、使用权限与技术可行性**：数据从哪来、能不能用、技术上跑不跑得通

> 聚焦高价值场景，从小处着手，快速验证。

**产出**：范围边界表（要做 / 不做 / 交付物 / 约束）写进项目章程。

---

## 模块 3：相关方与责任

**要回答的问题**：谁出资源、谁认价值、谁统筹、谁实现？

| 角色 | 职责 |
|---|---|
| **发起人** | 授权与资源 |
| **业务负责人** | 价值与验收 |
| **项目经理** | 统筹、协调与升级 |
| **技术 / 数据 / 测试** | 实现与质量 |

要点：

- 每个角色**落到具体的人**，不是部门名
- **授权边界**要写清：项目经理能决定什么、什么必须上报发起人
- **升级路径**要写清：出问题时找谁、多久必须响应

> 各司其职，协同推进，让 AI 项目真正落地。

**产出**：相关方登记册（见模板）。

---

## 模块 4：成功标准

**要回答的问题**：怎么算成功？谁来判？

四个维度，**每个都要给目标值与评测方法**：

| 维度 | 指标举例 |
|---|---|
| **业务** | 效率、满意度、实际使用率 |
| **模型** | 任务成功率、事实准确性 |
| **工程** | 响应时间、稳定性、单次成本 |
| **管理** | 目标值、评测方法、验收人提前约定 |

要点：

- **提前约定**：目标值、评测方法、验收人，三样必须在立项时就定下来，不能等做完再补
- 评测方法要具体到「用哪个评测集、怎么算分」
- 业务指标要写清**基线值**（现在是多少），否则没法判断「改善了」

> 用可衡量的结果，定义 AI 项目的成功。

**产出**：成功标准表（维度 / 指标 / 目标值 / 评测方法 / 验收人）写进项目章程。

---

## 阶段收尾：过推进关口

在进入「② 计划」之前，逐条确认：

- [ ] 业务目标能用一句话说清「为谁解决什么问题、带来什么价值」
- [ ] 范围边界里**「不做」**一栏非空
- [ ] 四个角色都落到了具体的人
- [ ] 成功标准的四个维度都有目标值 + 评测方法 + 验收人
- [ ] 数据来源与使用权限已确认
- [ ] 发起人已明确授权

**交付物齐了、关口过了，才进入计划阶段。** 没过的项列成缺口清单，不要跳过。
