# MISSION.md 格式

`MISSION.md` 位于工作区根目录。它记录用户学习这个主题的**原因**。每一个教学决策（接下来教什么、呈现哪些资源、设计哪些练习）都应当能追溯到这份文档。

## 模板

```md
# 任务书：{主题}

## 为什么（Why）
{1–3 句话。用户所追逐的具体真实世界目标。当他拥有这项技能后，他的生活或工作会发生什么变化？避免「为了理解 X」这类抽象表述；逼出底层的成果。}

## 成功的样子（Success looks like）
- {用户将能够做到的一件具体、可观察的事}
- {另一件具体的事}
- {…}

## 约束（Constraints）
- {时间、预算、既有承诺、学习偏好，任何会限制做法的东西}

## 超出范围（Out of scope）
- {用户明确表示现在不想去追的相邻主题，用来保护最近发展区}
```

## 规则

- **每个工作区只有一个任务书。** 如果用户想学两件不相关的事，那就是两个工作区。
- **具体优于抽象。**「十月前跑完半马」胜过「变得更健康」。「把一个 Rust CLI 交付给我的团队」胜过「学 Rust」。
- **对含糊要顶回去。** 如果用户说不出为什么，先访谈他，再动笔。糟糕的任务书比没有任务书更糟。
- **现实变了就修订。** 任务书会变。当用户的目标移动时，更新这份文件：不要留下一份过时的任务书继续指引未来的会话。
- **保持简短。** 如果 `MISSION.md` 超过一屏，它就不再是罗盘，而变成一份计划了。
