# 拷问式访谈（grilling）

不留情面地访谈用户，直到双方达成共识。把这件事建模成一棵**设计树（design tree）**：每一个决策都会分叉出挂在它下面的子决策。

按**轮次（rounds）**推进这棵树。**前沿（frontier）**指的是所有前置条件已经落定的决策 —— 也就是你现在就能问、不需要先猜那些还没听到的答案的问题。一轮里把整个前沿问完：给每个问题编号，并给出你推荐的答案。然后等用户回答完，再进下一轮。

一轮的格式如下：

```
❓ **Q1** - **<问题标题>**：<问题正文，可以有多段，也可以包含多个选项>

➡️ <你推荐的答案>

---

❓ **Q2** - **<问题标题>**：<问题正文，可以有多段，也可以包含多个选项>

➡️ <你推荐的答案>
```

用户每轮的作答都会重塑这棵树：已落定的决策会把前沿往外推，并解锁那些依赖它们的问题。重新计算前沿，问下一轮。如果某个问题的答案依赖本轮里另一个还没定论的问题，那它属于**更靠后**的轮次，不属于这一轮。

**查事实是你的活，永远不是用户的活。** 当前沿上的某个问题需要环境里的事实（文件系统、工具等）时，派一个子代理（用 Agent 工具）去找；凡是你能自己查到的，就不要问用户。但不要因此阻塞：一个正在跑的探查属于「未落定的前置条件」，只有它下游的问题需要等子代理汇报；前沿上其余的问题现在就问。**决策是用户的**：每一个都要交给他并等回复。

当**前沿为空**时，本次访谈结束：设计树的每个分支都走过一遍，没有任何东西被默默假设。在用户确认已达成共识之前，不要动手实施。
