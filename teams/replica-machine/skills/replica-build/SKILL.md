# 复刻实现

按蓝图把参考站"长"出来。一次一个切片：搭结构 → 接数据 → 自测 → 留证 → 提交。

> 复刻的是**行为**，不是源码。请求照发、状态照变、界面照动——实现是自己的。

## 适用场景

- 蓝图已就绪，开始写代码
- 复刻中途按差异报告修复
- 给已有复刻品补一个页面/交互

## 输入

- **实现蓝图**（`replica-blueprint` 的产出）
- **参考站的运行入口**（用于对照行为）
- 现有代码库（若为增量复刻）

## 执行步骤

### 步骤 1 — 选一个切片

从蓝图的切片清单里取**下一个未完成**的切片，读它的"做完后能验证什么"。不并行铺开多个未完成切片。

### 步骤 2 — 搭最小结构

只搭这个切片需要的结构：路由、布局容器、组件骨架、数据层接口。不提前实现后续切片的功能。

### 步骤 3 — 接数据与交互

按蓝图第 4 节的**数据契约**接数据：请求方法、路径、载荷、响应字段、错误分支。按第 5 节的**交互规格**接交互：触发条件、预期结果、边界情况。

对齐原则：

- **请求对齐**：路径、方法、载荷形状与证据包一致。
- **状态对齐**：加载态 / 空态 / 错误态都要有，且表现与参考站一致。
- **不照抄源码**：参考站源码只用于理解行为，不复制。

### 步骤 4 — 自测

本地跑起来，走一遍该切片的交互：

- [ ] 正常路径：操作 → 请求 → 界面变化，与证据包记录一致
- [ ] 空态：数据为空时的表现
- [ ] 错误态：请求失败时的表现
- [ ] 边界输入：空值 / 超长 / 特殊字符

### 步骤 5 — 留证

为这个切片留可展示的运行证据：

- 截图（关键状态）
- 控制台 / 网络输出
- 测试结果（若有测试）

### 步骤 6 — 提交

一个切片一个原子提交。提交说明写清"这个切片做了什么、怎么验证的"。

### 步骤 7 — 下一个

上一个切片有运行证据后，回到步骤 1。

## 修复模式

拿到差异报告后：

1. 按 **阻断 → 重要 → 次要** 排序。
2. 逐条复现差异点的场景，确认参考站的真实行为。
3. 只改该差异相关的代码，不顺手扩大改动面。
4. 留修复前后的对比证据。
5. 回给**提出该差异的验证员**复验，不自己宣布解决。

## 工作原则

- **行为对齐优先于代码对齐**：不照抄参考站源码与构建产物。
- **素材要干净**：不用参考站受版权保护的图片、字体、图标、文案。
- **最小实现**：不做蓝图外的功能；额外想法单独提给主理人。
- **不猜 API**：框架/库行为以官方文档为准，不确定标"未验证"并给出验证方法。
- **每步可回退**：一次一个可提交的小步，diff 能独立读懂。

## 输出

- 可运行、已自测、已提交的增量
- 每个切片的运行证据
- 切片完成清单（对照蓝图的切片清单）

## 质量自检

- [ ] 每个切片有可展示的运行证据
- [ ] 请求路径/方法/载荷与数据契约一致
- [ ] 加载态 / 空态 / 错误态都实现且表现一致
- [ ] 未使用参考站受版权保护的素材
- [ ] 每个提交能独立解释、可独立回退
- [ ] 未验证的框架行为已标注
