# 网站目标侦察清单

一次完整的网站侦察，按下面的清单逐项过。每一项产出都要能落进证据包。

## 1. 目标与范围

- [ ] 目标 URL（含要研究的页面路径）
- [ ] 授权依据（自有 / 已获授权 / 开源许可）
- [ ] 本次要研究的页面与交互清单
- [ ] 明确不研究的部分

## 2. 页面结构

- [ ] 关键页面的 DOM 层次（顶层容器、主要区块）
- [ ] 路由结构（路径 → 页面）
- [ ] 可访问性文本（`--include-accessibility-text`）用于理解语义结构
- [ ] 关键组件的边界（哪些 DOM 属于同一个组件）

## 3. 前端脚本

- [ ] 加载的脚本清单（bundle、chunk、第三方库）
- [ ] 是否有 source map（有则读原始源码，可读性更高）
- [ ] 每个关键请求的**发起脚本**（请求记录里的"发起者"）
- [ ] 数据组装逻辑：响应怎么被解析、转换、渲染

## 4. 网络请求

对每个要研究的交互，单独开一个观察窗口：

- [ ] 请求 URL 与路径
- [ ] 方法（GET / POST / …）
- [ ] 状态码
- [ ] 响应结构（`--include-json-body-shapes` 得到字段形状）
- [ ] 触发时机（哪个操作触发的）
- [ ] 请求载荷（若有）

## 5. 交互

- [ ] 每个关键交互的完整链路：**操作 → 请求 → DOM 变化**
- [ ] 交互的边界：空输入、超长输入、特殊字符、错误响应下的表现
- [ ] 加载态 / 空态 / 错误态各自长什么样

## 6. 素材与资产

- [ ] 图片 / 图标 / 字体清单及来源
- [ ] 哪些是通用素材、哪些是目标方独有的受版权保护资产（后者需替换）

## 7. 截图

- [ ] 每个关键页面 / 状态一张截图
- [ ] 记录视口尺寸与设备像素比（供后续视觉比对复现）

## 8. 收尾

- [ ] 未知项清单（没看清的 + 影响面 + 建议下一步）
- [ ] 采集通道（REA / 降级通道）与限制说明
- [ ] 观察窗口之外的请求如实标注

## 常见坑

- **只开一个窗口采集多个交互**：窗口之外的请求会丢。一个交互一个窗口。
- **忽略 source map**：有 source map 时不读原始源码，等于放弃可读性。
- **把"没观察到"写成"不存在"**：观察窗口有时限，没抓到 ≠ 没有。
- **忽略登录态**：需要登录的页面，先在浏览器里登录好再采集。
