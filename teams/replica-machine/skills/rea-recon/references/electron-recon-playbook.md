# Electron / 打包应用侦察清单

目标是 Electron 或打包应用时，用静态 JavaScript 分析读文件（不运行应用），沿"渲染进程 → preload → IPC → 主进程"追踪功能链路。

## 0. 前置

- [ ] 确认可分析的目标路径（解包后的应用目录，或 ASAR 文件）
- [ ] 确认授权依据
- [ ] 静态分析不需要 Hopper / Ghidra / IDA

## 1. 基础分析

```bash
npx -y rea-agents@latest analyze-javascript-application /absolute/path/to/app --json
```

- [ ] 模块清单
- [ ] 导入关系（谁依赖谁）
- [ ] Electron 边界（渲染进程 / preload / 主进程各有哪些模块）
- [ ] 相关证据（REA 会一并返回）

## 2. 功能链路追踪

对每个要复刻的功能，沿下面这条链走一遍，把每一跳都记进证据包：

```
界面元素（按钮/输入）
  → 渲染进程调用的 API
  → preload 暴露的接口
  → IPC 通道名
  → 主进程处理函数
  → 副作用（文件、网络、系统调用）
```

- [ ] 渲染进程侧：事件处理函数在哪、调了什么
- [ ] preload 侧：`contextBridge` 暴露了哪些 API
- [ ] IPC 侧：通道名与消息形状（参数、返回）
- [ ] 主进程侧：处理逻辑与副作用

## 3. 路由与状态

- [ ] 页面/窗口路由结构
- [ ] 全局状态管理方式（若有）
- [ ] 持久化位置（配置、缓存、本地数据库）

## 4. 原生扩展

- [ ] 是否依赖原生扩展（`.node` 文件）
- [ ] 原生扩展承担了什么职责（这决定了复刻时能否用纯 JS 替代）

## 5. 收尾

- [ ] 未知项清单（如：被混淆的模块、原生扩展内部逻辑、服务端私有协议）
- [ ] 采集通道与限制
- [ ] 说明哪些部分**只能行为对齐、无法逐行复刻**（如原生扩展）

## 常见坑

- **只看渲染进程**：Electron 功能往往跨进程，漏掉 preload / IPC 就会复刻不出效果。
- **忽略原生扩展**：`.node` 原生模块无法直接复刻，需要在蓝图里标为"用等价实现替代"。
- **把 ASAR 当成明文**：ASAR 是打包格式，需先解包再分析；REA 可处理 ASAR 输入。
