# 交付物标准

交付前逐条核对。未达标项必须写明原因。

## 一、定界与授权

- [ ] 目标明确（参考站 + 页面/功能范围）
- [ ] 授权依据明确
- [ ] 验收标准可执行（写得出"怎么验"）
- [ ] 明确列出了"不做什么"

## 二、侦察

- [ ] 证据包七节齐全
- [ ] 每条结论可指回证据（请求 / 脚本 / 截图）
- [ ] 事实与"推测（待验证）"分开
- [ ] 未知项单列，含影响面与下一步
- [ ] 采集通道与限制写明（降级通道须显式标注）

## 三、蓝图

- [ ] 技术栈选型有理由，未验证项已标注
- [ ] 组件映射覆盖证据包全部页面/模块
- [ ] 每个请求有数据契约（含错误分支）
- [ ] 每个交互有规格（含边界情况）
- [ ] 素材逐项有处置方案
- [ ] 未知项已转成假设，无阻塞性假设
- [ ] 切片清单可按依赖顺序独立验证

## 四、实现

- [ ] 每个切片有可展示的运行证据
- [ ] 请求路径/方法/载荷与数据契约一致
- [ ] 加载态 / 空态 / 错误态都实现
- [ ] 每个提交能独立解释、可独立回退
- [ ] 未使用参考站受版权保护的素材

## 五、验证

- [ ] 差异报告四轴覆盖（IPC 仅 Electron）
- [ ] 每条差异有级别、复现步骤、证据、期望 vs 实际
- [ ] 正常路径、空态、错误态、边界输入都覆盖
- [ ] "不可比"项单列并说明原因
- [ ] 修复复验有明确结论

## 六、交付报告

必须包含：

1. **这次复刻了什么** — 页面/功能清单 + 关键实现说明
2. **门禁结论** — G0–G5 各自过了没有
3. **差异报告最终状态** — 阻断/重要/次要各自处理情况
4. **遗留项** — 以及为什么没解决
5. **合规声明** — 授权依据 + 被替换的素材清单

## 七、交付判断

- [ ] 全部门禁通过且无未解决阻断级差异 → 给出"可交付"判断
- [ ] 存在未解决阻断级差异 → 明确报告"因 X 未解决，不给出可交付判断"
- [ ] 判断明确，不回避
