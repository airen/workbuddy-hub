# 复刻交付

主理人的收尾技能：开工前把范围与授权定死，收尾时把交付说清。

> 没有授权依据，不启动；没有验证结论，不交付。

## 适用场景

- 接到一个复刻请求，要先定界
- 复刻完成，要出交付报告
- 复刻中途范围变更，要重定验收标准
- 授权存疑，需要判断能否继续

## 执行步骤

### 步骤 1 — 定界四问

对每个复刻请求，问清四件事：

1. **目标**：参考站 URL / 具体页面 / 具体功能；Electron 目标给可分析路径。
2. **授权依据**：自有项目、已获书面授权，或目标本身是开源/公开许可。
3. **复刻范围**：这次复刻哪些页面与交互；明确**不做什么**。
4. **验收标准**：以什么判定"复刻成功"。

含糊时**一次问一个问题**，问到四件事都有明确答案。

### 步骤 2 — 授权把关（硬门禁）

按 `references/legal-boundary.md` 判断：

- 授权依据明确 → 继续。
- 授权依据缺失或存疑 → **停下，先问用户**，不"先做了再说"。
- 目标明确越界（如要求复刻他人付费产品用于商业分发）→ 说明风险，不启动。

### 步骤 3 — 写验收标准

把"复刻成功"写成可核验的条目：

```
- 页面 A 的布局、间距、字体与参考站一致（视觉比对通过）
- 交互 X 的请求序列与参考站一致（网络比对通过）
- 空态/错误态表现一致
```

验收标准是后续一致性比对的依据，必须可执行。

### 步骤 4 — 编排与把关

按团队 SOP 调度成员，守住五道门禁：

| 门禁 | 位置 | 规则 |
|---|---|---|
| G0 | 定界 → 侦察 | 没有授权依据或范围无法界定，不启动 |
| G1 | 侦察 → 蓝图 | 证据包缺关键证据或以推测为主，回炉补侦察 |
| G2 | 蓝图 → 实现 | 存在无法绕开的阻塞性未知项，回炉补侦察 |
| G3 | 每个切片 | 没有运行证据，不进下一个切片 |
| G4 | 验证 → 交付 | 存在未解决的阻断级差异，不放行 |

### 步骤 5 — 出交付报告

对照 `references/delivery-standard.md` 逐条核对，产出交付报告：

1. **这次复刻了什么**（页面/功能清单 + 关键实现说明）
2. **门禁结论**（G0–G5 各自过了没有）
3. **差异报告最终状态**（阻断/重要/次要各自处理情况）
4. **遗留项**及**为什么没解决**
5. **合规声明**：授权依据 + 被替换的素材清单

### 步骤 6 — 给交付判断

裁决型结论必须明确：

- 全部门禁通过、无未解决阻断级差异 → 给出"可交付"判断。
- 存在未解决阻断级差异 → 明确报告"因 X 未解决，不给出可交付判断"，不回避。

## 工作原则

- **授权是硬门禁**：存疑即停，先问不猜。
- **验收标准可执行**：写不出"怎么验"的标准，等于没写。
- **不代写成员产出**：编排与汇编是我的事，专业产出归成员。
- **裁决不回避**：能不能交付必须给明确判断。
- **遗留项要写原因**：没解决的要说明为什么没解决，不藏。

## 输出

- 任务定界 + 授权依据 + 验收标准
- 交付报告（含合规声明）
- 明确的交付判断
