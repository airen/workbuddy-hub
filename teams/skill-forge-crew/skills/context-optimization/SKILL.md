# 上下文压缩

保留重要信息，压缩不必要的上下文，减少 Token 消耗和调用成本。

## 适用场景

- 会话变长，重复内容越来越多
- 要把任务交给子 Agent，需要给它一份精简但完整的上下文
- 大段代码 / 日志 / 文档被反复读进上下文
- 长流程任务（几十步）跑到一半，模型开始"忘了前面说什么"

## 输入

- 当前会话或任务的关键内容
- 接下来要做的步骤（决定哪些信息必须常驻）
- 可用的外部存储（文件、笔记）

## 执行步骤

### 步骤 1 — 分清三类信息

| 类别 | 处理方式 | 例子 |
|---|---|---|
| 常驻 | 保留在上下文，反复用到 | 需求定界、验收标准、当前阶段目标、硬约束 |
| 用时再取 | 只留路径引用，需要时读 | 长文档、完整代码文件、历史日志 |
| 可丢弃 | 压缩成一句话结论或删掉 | 试错的中间过程、已被推翻的方案、重复的报错 |

判断依据只有一个：**接下来的步骤会不会用到它。**

### 步骤 2 — 把过程压成结论

长对话里最有价值的是结论，不是过程。压缩模板：

```
## 已确认
- <结论 1>（来自：<哪一步>）
- <结论 2>

## 已否决
- <方案 X>：因为 <原因>

## 待办
1. <下一步>（依赖：<什么>）
```

三到五行就能替代三十轮对话。

### 步骤 3 — 大块内容改引用

不要在上下文里贴 500 行代码。改成：

```
详见 src/foo/bar.ts:120-180（作用：<一句话>）
```

需要细节时再读那一段。**读了用完就丢。**

### 步骤 4 — 分层加载深度资料

技能里的 `references/`、`assets/` 就是这个用途：入口文件只放每次都要读的内容，深度资料用时再取。写技能时遵守这条，长任务才不会撑爆上下文。

### 步骤 5 — 给子 Agent 的上下文包

派活给子 Agent 时，只给三样：

1. **任务原文**（要它做什么、验收标准是什么）
2. **必要事实**（它自己读不到的背景）
3. **明确的边界**（不要做什么、输出到哪）

不把整段会话历史丢给它——那既贵又容易让它抓错重点。

### 步骤 6 — 设置检查点

长任务每完成一个阶段，写一份 3～5 行的状态摘要存到文件。后续续跑时读摘要而不是读历史。

## 输出

- 压缩后的上下文摘要（已确认 / 已否决 / 待办）
- 大块内容的路径引用清单
- 给子 Agent 的精简上下文包（如适用）

## 反模式

- **压缩掉硬约束**：约束丢了，后面会做出违规的东西
- **只留结论不留依据**：无法判断结论是否仍然成立
- **把过程原样保留**：试错过程占空间却不再被用到
- **一次性全塞给子 Agent**：贵，而且它会抓错重点
- **压缩后不写回文件**：会话一断，压缩的成果就没了
- **为了省 Token 删掉验收标准**：省了小钱，做错了大事

## 参考

- 判断标准：**这段内容会不会影响接下来的决策？**不会就压掉。
